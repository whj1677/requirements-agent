# 需求 Agent：Codex 开发交付包

版本：1.1。编制日期：2026-09-23。

**本包是开发规格、提示词和验收设计，不是已完成的软件，也不代表已经做过真实 DeepSeek API 测试。**

## 使用方法

将本包放入一个新建或已明确授权的 `requirements-agent` 项目工作区，把 `02_CODEX_START_PROMPT.md` 的全文交给 Codex。Codex 应先读本包，再分阶段实现，不应仅返回计划，也不应擅自把任务降为一个 Skill 或聊天演示。

主要阅读顺序：

1. `01_CODEX_TASKBOOK.md`：目标、范围、架构、流程、交付和开发约束。
2. `04_CONTRACTS.md`：数据、状态、确认、模型输出和导出契约。
3. `prompts/`：主系统提示词及十个阶段提示词；按阶段组合调用，不是十个独立自治 Agent。
4. `03_ACCEPTANCE.md`：正常、异常、攻击、版本与真实模型验收。
5. `examples/`：模型配置、JSON Schema、示例输出和冻结评测材料。
6. `09_WORD_REFERENCE_RULES.md` 与 `references/`：两份原始 Word 的章节内容参考及裁剪规则。
7. `05_SOURCES.md`：继承的官方 API 依据、模板来源和未验证事项。

`06_RUNTIME_PROMPTS_ALL.md` 是提示词合订版。`07_PM_QUICKSTART.md` 是产品经理操作样例。

## 本次关键约定

默认交付中文、Windows 本机启动的 Web 应用，后端核心逻辑使用 Python；产品经理通过浏览器操作，不填写 JSON、定位器或接口协议。默认连接 DeepSeek 官方 API，允许更换兼容接口的模型配置。

核心闭环：零散材料 → 对标/头脑风暴 → 选择方向 → 澄清 → 页面线框与 PRD 评审 → 真人确认指定版本 → 输出前后端 MD、验收条件与追踪包。

业务底稿是唯一业务基准。竞品内容、截图、AI 建议均不能自动升级成当前产品已确认需求。原型不是业务实现，模型评审不是人工批准。

本次是独立应用开发任务。此前 Skill 方案中的“只做设计、不建独立应用”不再是本任务的停止条件；其来源标记、统一底稿、人工确认等原则保留。不修改、覆盖或宣称替代已有 Skill。

## v1.1 的 Word 参考模板变更

本包已附两份用户原始 PRD／MRD Word，原件未改动。**只参考章节结构与内容维度，不要求原版式、固定章数或示例业务照搬。**允许按实际需求合并、裁剪、增补，保留适用内容和重要待确认项。

默认 PRD；支持按需导出 MRD 或两者，不强制双文档、也不增加先 MRD 后 PRD 的步骤。MD／DOCX 从同版内容对象产生，前后端交接仍经原有 PRD 内容确认门禁。

已让 Codex 开始开发时，优先把 `10_CODEX_UPDATE_PROMPT.md` 发给它做增量修改，不必推倒重建。首次开发使用更新后的 `02_CODEX_START_PROMPT.md`。

## 真实凭据与版本

本包不含真实 API Key。真实模型验收只能使用已配置且明确允许本项目使用的凭据，不搜索其它工程或浏览器。无凭据时继续离线验证，真实调用标为 NOT_RUN。

运行时响应 Schema 升级到 1.1，文档阶段增加类型、参考 profile、层级与章节映射；独立 wireframe Schema 保持 1.0。历史数据和已确认哈希不得因更新被覆盖。模型配置与原有技术来源沿用 v1.0，本次未重测或新验证模型能力。
