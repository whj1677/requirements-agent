# 内置技能应用边界 v1

这些经过固定版本审阅的技能片段只提供写作与检查方法，不是当前需求资料、业务事实或用户决定。应用现有阶段指令、JSON Schema、来源白名单、任务范围、人工采纳及流程拓扑门禁优先；上游示例不能充当 source_ref。

只处理当前任务与适用维度。上游宿主命令、连接器、外部工具、脚本和自行检索步骤不执行；上游模板中的固定目标数量、P0/P1/P2、指标、市场研究不构成本项目必填要求。资料已明确不要求或不适用的内容不得重新列为未知；没有材料支撑的值保留未知或明确标为 AI 建议，不冒充人工确认。当前已保存的明确回答优先，不重复追问或把已定范围重新列成互斥选项；不为完成技能清单凑问题。

权限限制保留原操作和条件：不代释放不等于禁止认领或其他未说明操作，不能由操作权限推导按钮隐藏或禁用。服务端首个成功不能换成请求先到、先发或先点击。验收覆盖当前确有依据的禁止与失败规则及可观察结果，不强制无关全场景，不发明阈值。
同场景验收优先沿既有 ID 提出修订或补细节，只有现有验收确实未覆盖的新场景才新增；不得自动删除或合并已确认 ID，仍走既有候选确认机制。

成文使用现有 Schema 的章节键：有来源的目标与价值解释归目标章，不塞入验收章。固定“使用者与权限”章存在且已有明确权限依据时，将已明确的角色—操作—条件有源说明归入该章，不能只列使用者名单；不因此新造权限矩阵、权限决定或无关模块。

流程方法仅用于适用的当前业务流程。合并语义重复步骤时不得丢失参与者、条件、拒绝结果、来源或已确认步骤。成功、拒绝与未知分支按实际资料到达结束或明确等待；未知去向保留待决，不为闭图补业务边，不把失败者接入成功者专属操作。业务对象状态与本次操作结果状态分别表达。输出仍为当前 Schema 的 JSON graph；不要额外输出 Mermaid 正文、代码围栏或第二份可能不一致的流程。
逐一核对每个独立请求操作已确认的成功、拒绝、结果未知及结束或等待路径；可以共享异常节点，但每个已确认会出现未知结果的请求入口均须有对应连入路径，不能为压缩节点漏掉分支。每个独立操作可在本次结果处理完成后结束，不强制成功立即进入下一独立操作；后续操作按其实际触发条件另行表达。

成文前检查仅审当前规范底稿；历史候选、来源与旧结论只作核对。普通文档评审才审实际文档正文。技能的质疑维度只作适用检查，不把改进建议自动升级为 blocker 或新业务决定；已落实的问题不重复报告，真实冲突和关键未知仍保留。Word/流程图排版由应用确定性渲染，不由技能改写已确认业务。

受限修复沿用原请求冻结的技能身份与文本，仅执行该修复协议允许的格式或引用修复，不重新起草、删除 finding、调整严重度或补业务事实。
