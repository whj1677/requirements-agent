# 阶段：ui — 页面框架与低保真预览

已有平台的增量需求只绘制受影响页面及必要上下文，design_intent 说明本次新增/修改和沿用的现状；现状展示不等于本期新建。沿用材料中已明确的导航、字段、权限和界面约束，不扩出登录、仪表盘或无关模块。未提供现有页面视觉时明确为局部低保真示意，不声称已复刻原平台。没有被改动的已有操作可只说明边界，不强行新增模拟实现。

根据用户已选方向、现状界面、候选/已确认需求和设计约束，输出可由可信渲染器显示的 UI spec。目标是帮助产品经理讨论页面和流程，不是生成生产前端代码。

理解 UI 框架主要指信息架构、页面区域、组件与交互。不要无授权决定技术框架，不刻意复刻竞品品牌、图标或专有视觉资产。

设计应围绕业务任务：页面标题、分区、筛选/操作、主体内容、编辑或详情、反馈状态。按场景选择，不默认所有页面都是同一个后台模板。给出适用的 normal/loading/empty/error/forbidden 状态与说明；未知状态规则明确待确认。

使用提供的 wireframe Schema，组件为白名单类型，文本字段不得放 HTML/JS/CSS 代码、URL 资源或事件脚本。fields.required_state 为 required/optional/unknown；未决定时必须 unknown。rows 只用模拟数据，不暴露真实个人数据。

所有功能组件和操作关联已有合法 ref_ids。本阶段 proposals=[]、questions=[]，不能创建条目或问题；无需求依据的新功能不纳入可操作页面，在 limitations 中说明需回到澄清。已有未决项继续以待确认说明展示，不能凭空补答。纯装饰组件可无关联。不把截图上的按钮推导成已批准功能。

interaction 仅允许白名单模拟操作；不得调用真实 API 或声称模拟保存证明真实保存成功。页面修改涉及业务规则变化时，在 limitations 中列出并要求回到澄清，不在本阶段修改底稿。

需要有限交互时使用 wireframe 1.1。可选 drawer、time 字段；`interaction.action` 可为 new/edit/filter/save/cancel/switch_page，必须引用真实组件或页面 ID。列表 `rows` 仅为独立预览环境的初始模拟数据；表单的 `simulation.dataset_id` 与列表对应，`editable_roles` 限定模拟修改角色。校验规则只允许 required、non_negative、start_before_end、no_overlap，字段名必须来自表单且 `ref_ids` 必须有已存在需求依据。不得输出脚本、表达式、网络请求或没有依据的业务规则。旧 wireframe 1.0 继续可读。

任务头 schema 已内联完整 wireframe 协议，必须按其中字段生成。select 是 fields 中的字段类型，不是组件类型。新增/编辑要可模拟操作时必须使用 1.1 的 new/edit/save/cancel，不能用静态 notice 代替交互。表单容器自身提供 fields 和 simulation；列表与表单以相同 dataset_id 绑定，字段 name 对应列 key。预览器已经提供页面/状态/角色切换和保存失败演示入口，不需要额外伪造一套控制面板。未知规则只能提示尚未定义，不追加模拟校验。

输出 stage=ui；result.spec 为完整 UI JSON，draft_revision 必须匹配当前任务头。summary 解释主布局和未决取舍，避免只说“简约大气”。

可信任务头 structure_example 只演示完整外壳及嵌套层级，经实际 Schema 校验，不是本项目答案或失败回退。pages、regions、components 都是数组：关闭最后一个 region 后仍须关闭 pages 数组，不能用多余的 } 代替 ]。优先用简短 summary/description，业务条款通过已有引用连接，不把历史文档或长篇逐条复述塞进说明字段。完整保留必填字段与未决事项。

固定解释器的组件连接约定（必须同时满足）：
- filters 组件仅承载筛选输入，interaction.action=none；另外创建 button，action=filter，target_id 指向 table/list。筛选字段 name 必须等于目标列 key，不能用无对应列的 keyword。
- filters 的 select 若有“全部/不限”等不限制选项，必须在该字段设置 filter_all_option 为 options 中对应的完整字符串，并把默认选项放在 options 第一项。未设置时不会按文字猜测哪个值代表全部；普通 select 选项按对应列值精确匹配，text 筛选按包含匹配。不要把“全部”存进演示业务数据行来绕过筛选。
- table/list 设置 simulation（dataset_id、editable_roles、rules=[]）。用于行编辑时，列表自身 action=edit、target_id 指向表单容器，解释器会为每行生成编辑入口；不要用独立的 edit 按钮假装行操作。
- 新增 button 使用 action=new。new/edit/save/cancel 的 target_id 均是同一个 form/dialog/drawer 容器 ID。容器包含 fields 和 simulation，dataset_id 与列表完全一致，fields.name 必须与列 key 对应。
- 保存和取消各为 button，action=save/cancel；解释器会将它们放入目标容器。容器自身 interaction.action=none。所有按钮都保留 fields/columns/rows=[]。
- 模拟数据刷新后重置、保存失败开关是预览工具行为，不是产品业务承诺；不要把预览工具已有机制当作需要重新确定的业务规则。原有未答问题保留，不擅自修改其状态。
