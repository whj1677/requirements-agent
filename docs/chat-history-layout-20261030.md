# 1.2.13 聊天记录区域被挤压

用户提供客户电脑截图，并确认主要问题为聊天内容区域太小或被截断。复现采用隔离合成长聊天和实际构建后的 UI；浏览器所有 API 由隔离 ASGI 应用接管，不启动第二个工作台、不访问日常项目、不调用外部模型。

修改前 `c1aa7a98e2c671b2369dfe095ea6b6355edf3079` 已归档并推送 `codex/archive-pm-req-20261030-before-ui`。在独立开发检出中验证布局，日常入口仍为根目录 8765 工作台。

## 原因与最小修改

- “其他方式”的 details 继承了卡片通用的上下边距和顶部留白，拉高顶部模式选择行。
- 输入区、发送操作、收起的对标区、整理操作各占一行；宽屏下未套用此前只针对部分笔记本尺寸的紧凑布局，聊天记录反而只有约 150～200 像素高。
- 只调整现有 CSS：清除模式选择行多余留白，已有聊天时将发送与资料按钮排在输入框侧边，合并收起状态的辅助操作行。保留 16 像素输入字号、至少 80 像素输入高度，以及全部按钮和展开功能，不改变聊天状态、草稿、任务或数据逻辑。
