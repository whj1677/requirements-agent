# PRD 成文一致性检查与修订闭环（2026-10-14）

本次在既有需求工作台增加成文前检查，检查需求正文、字段、交互、流程、状态和验收的对应关系。模型提出检查意见，程序控制版本、确认、保存和导出；不自动代替产品经理决定业务。

## 使用路径

1. 从需求助手进入「完善需求」，切换「成文检查」。进入页面不调用模型。
2. 主动检查，或生成 PRD 时自动先检查。相同输入已有有效检查时复用，避免重复调用。
3. 发现待处理问题后，在检查卡查看冲突原文、来源、影响和建议。可以填写自己的回答、选择建议、记录暂未确定或提交异议。没有默认业务答案。
4. 「保存回答并整理修改」由 Agent 生成修订候选；也可「直接修改需求」。正文、详细字段、交互、流程和状态修改均进入前后差异预览。
5. 确认已展示的修改，再复检。保存回答、保存异议、模型请求成功本身均不等于检查通过。
6. 关键问题未处理时暂停成文。明确选择「带未决项生成 PRD 评审稿」可供讨论，具体未决检查意见随文档快照展示；检查失败、结构损坏仍不能绕过。
7. PRD 生成后改需求，旧文档仍可查看，当前检查失效。重新确认修改、复检、生成新版本；显示相对上一文档的条目变化与受影响章节，旧版本确认不会自动延续。

所有项目打开、重开和刷新恢复仍从「和助手聊需求」进入。日常入口仍为 `http://127.0.0.1:8765/`。

## 实现边界

- 复用 `Actions → Workflow → Provider` 的授权、调用预算、原始响应证据和失败处理，新增 `prewrite` 动作；不另建模型调用通道。
- 检查绑定需求、问题回答、资料、业务上下文及知识选择的输入哈希。低层 `/runs` 同样不能绕过新 PRD 的检查前置条件。
- 结构化详细定义由程序生成字段表、交互表、完整流程图、分支表和状态表。章节引用与模型解释使用不同白名单，防止模型再次改写确认值。
- 修订确认支持 `detail_contract`，同时验证引用、保存人工原文来源和答案落实证据。
- 检查意见、文档快照和历史版本分别保存。评审稿按自己的检查快照展示未决意见，不随项目后续变化漂移。
- 本次没有新增在线富文本任意改写 PRD 的功能。业务规则变化走需求修订再生成；不把修改渲染后文字当作业务底稿已同步。
