# 需求草稿填充与阶段跳转修订（2026-10-04）

## 范围与行为

本次更新既有工作台的聊天与直接填写流程。目标是让用户提供已知信息、审核 AI 草稿，再确认进入下一阶段。未新增运行入口，也未制作新版 Windows 安装包。

- 第二步新增“一键 AI 填充”：先保存人工编辑，再使用现有 `organize` 任务和模型/材料范围核对弹窗。人工填写的文字优先；空项建议标记待审核，差异化建议单独展示。未知权限、异常、保持约束与优先级不应被模型补成既定业务决定。
- 第一页发起的整理产生结果后自动进入草稿审核页；审核页发起的填充留在审核页。任务失败保留输入并显示失败状态。
- “确认并进入下一步”保存本页编辑及其他待保存草稿，读取最新项目，核对修订号和阶段内容哈希。核对接口成功后才切换阶段。失败、缺项或版本冲突留在当前页。
- 范围勾选与条目采纳保持独立。模型行为待核对的候选仍需对照来源核对保存，再决定是否采纳。

## 字段适用性

| 内容 | 全新产品 / 确认独立的新增模块 | 有关联的新增模块 / 已有功能修改 / 尚未确定 |
| --- | --- | --- |
| 目标、使用者、本次改动 | 必须核对 | 必须核对 |
| 当前现状 | 可不适用 | 必须核对 |
| 保持项 | 可不适用，也可明确没有 | 核对内容或明确确认没有 |
| 产品、模块名称 | 按需填写 | 按需填写 |
| 改动价值、优先级、暂不涉及 | 按需填写 | 按需填写 |

状态分别保存为“已填写”“待确认”“不适用”“已确认没有额外约束”。选择不适用或没有时保留已有原文记录，成文时不将其继续当作有效事实。必需字段的未知或不合法状态仍阻止核对；可选字段不会因空白而阻止继续。

已有项目只有在保存新适用性元数据后启用扩展核对契约。未触碰的旧项目保留原内容哈希与历史核对身份；实际修改字段适用性会使后续核对及旧文档提示需要更新。

## 实现与回归边界

- `scope_profile` 与 `context_field_states` 作为显式人工选择保存。后端统一验证聊天后审核和直接填写的适用规则。
- 直接填写的原始资料只包含人工输入事件产生的文字；把 AI 建议放进编辑框不会自动成为人工原始资料。
- `/stage-checks/{step}` 返回阶段状态数组。补做前序核对后重新读取项目，使用真正的最新项目修订号确认后续阶段。
- 回归覆盖新产品、独立/共享模块、字段状态、真实范围编号、旧项目兼容、文档失效、人工原文保留、接口返回形状与跳转失败阻断。
