# 1.2.13 WPS 保持打开时读取材料

用户确认 Word 已能读取，但打开 WPS 时仍被要求关闭。原因是 1.2.12 在检查独立实例之前，只要发现可见 WPS 窗口就返回 OFFICE_BUSY。这是程序的提前限制，不是本机 WPS 必然无法并行读取。

修改前 `5f82387c5635e130b0fd330de5eb1cd658db2b27` 已归档并推送 `codex/archive-pm-req-20261030-wps-open`。

## 最小修改

- 移除 WPS 可见窗口的提前拒绝及不再使用的窗口枚举代码。
- 仍通过 COM 创建实例，并核对新进程组及空文档集合；如果返回既有实例或无法确认独立空闲实例，在改变设置或打开材料前停止。
- 只打开上传字节的临时副本，保持禁用宏、关闭外链更新、只读校验、不保存原件；只退出并清理本次创建的实例。Microsoft PowerPoint 的既有实例限制保留。
- 读取的是上传时的已保存内容；用户留在 WPS 中的未保存编辑不混入上传材料。

## 验证范围

`tests/test_wps_open.py` 为显式开启的真实 WPS 测试，分别打开可见的合成 Word、Excel 文档并保留未保存编辑，再由 Agent 读取同一文件的上传快照。断言提取成功、未保存标记不进入提取结果、原文档内容和 Saved 状态不变、窗口可见性和文档数量不变、宏及链接设置不变、原文件哈希不变、原实例 PID 与创建时间仍存在。

另外保留已使用实例拒绝接管、不明新进程组拒绝接管、只读及权限拒绝、超时精确清理等回归。测试仅处理本轮自己创建的合成文档，不关闭用户原有窗口。

当前 WPS 12.1.0.29161 的演示组件仍无法确认禁用宏，PPT 本机后备读取限制未在本轮放宽。普通 PPTX 内置解析及 Word／Excel 读取属于不同结果，不能将本轮修复表述为所有 Office 功能全部通过。

最终回归、安装器身份及升级保留数据结果见下文。没有真实模型调用、客户原件语义验收、数据迁移或日常工作台重启。

## 本轮验证发现并修复

- 真实开窗提取的业务断言通过，但一次 Excel 测试在关闭自建样例后，进程恰好退出，映像查询返回 WinError 5。清理现在只在同一持有句柄已观察到退出时认可完成；仍存活且身份不可核实的进程继续拒绝结束。增加退出／仍存活两类回归，没有忽略权限拒绝。
- 首次干净 CI 的全新安装通过，跨版本升级已核对数据保留，但目标实例在 HTTP 关闭成功后超过验证器原有 20 秒退出等待。验证器将实际退出等待调整为有界 60 秒，仍要求成功退出及端口释放后才允许卸载，不以强制结束代替验收。
- 本机测试新建快捷方式偶遇 WinError 32 短暂共享占用；测试夹具仅对此错误在两秒内等待后重试重命名，保留 Unicode 快捷方式的全部真实校验，不改变生产快捷方式行为。
- 用户追加的聊天区显示问题与本轮一起处理，见 [布局复验](chat-history-layout-20261030.md)。
- 完整回归一次出现 Word 独立实例未就绪；将进程快照移至文档集合初始化查询之后，增加延迟初始化回归。受影响的真实 Word／Excel、开窗未保存编辑、只读及实例保护共 54 项复验中，53 通过，余 1 项仍为既有 WPS 演示宏禁用能力限制。

## 覆盖升级与交付目录

用户要求后续安装包默认覆盖，避免空间持续增加。保持同一 AppId、固定安装目录及 UsePreviousAppDir=yes。升级前核对该 AppId 的原安装路径、EXE 和清单，才替换程序自有 `_internal`；不清理整个安装根目录，不触及独立的用户数据目录。实际升级测试会放入旧运行资源哨兵，要求新版安装后该哨兵消失，同时原有项目／历史／附件／配置／凭据保持一致。

本机交付改用固定目录 `output/需求Agent-Windows安装版/` 和固定文件名 `RequirementsAgent-windows-x64-setup.exe`，后续交付覆盖这一份。版本和源码身份保留在 SHA256.json 及验证记录中，不再为每次交付新增版本目录。此前已存在的历史交付目录未在本轮擅自删除。

## 退出与静默卸载复验

覆盖包的旧运行文件清理及数据保留检查已通过，但静默卸载出现超时。核查发现原验证器只等待快捷方式包装进程和 HTTP 端口释放，安装器还要求后台运行互斥已释放；这两种停止条件存在时序差异。验证器现在进一步等待同一运行互斥自然消失，不强制结束服务来替代验收；持续忙碌或检查权限不足仍失败。卸载的忙碌提示改用 Inno [SuppressibleMsgBox](https://jrsoftware.org/ishelp/topic_isxfunc_suppressiblemsgbox.htm)，遵守静默参数时直接保留拒绝结果，交互卸载仍显示提示。增加互斥释放、持续存在及访问拒绝回归；超时报告记录对应可执行文件和等待秒数。

## 安装时自动关闭旧进程

用户进一步明确要求安装时结束原需求 Agent 进程。安装改用 Inno 的 [CloseApplications=force](https://jrsoftware.org/ishelp/topic_setup_closeapplications.htm)，[文件过滤](https://jrsoftware.org/is6help/topic_setup_closeapplicationsfilter.htm)仅为目标目录的 RequirementsAgent.exe，由 Windows Restart Manager 按被更新的具体文件定位进程，不按系统中同名进程批量结束；WPS、浏览器和无关 Python 不在该文件范围。移除安装前必须手工退出的阻拦；卸载仍要求正常停止，数据保留与字节校验继续执行。跨版本验证增加 --running-upgrade：在覆盖前启动并保持本轮创建的旧版运行，要求安装后其已退出，随后核对新版本与原有数据。
