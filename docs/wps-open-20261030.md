# 1.2.13 WPS 保持打开时读取材料

用户确认 Word 已能读取，但打开 WPS 时仍被要求关闭。原因是 1.2.12 在检查独立实例之前，只要发现可见 WPS 窗口就返回 OFFICE_BUSY。这是程序的提前限制，不是本机 WPS 必然无法并行读取。

修改前 `5f82387c5635e130b0fd330de5eb1cd658db2b27` 已归档并推送 `codex/archive-pm-req-20261030-wps-open`。

## 最小修改

- 移除 WPS 可见窗口的提前拒绝及不再使用的窗口枚举代码。
- 仍通过 COM 创建实例，并核对新进程组及空文档集合；如果返回既有实例或无法确认独立空闲实例，在改变设置或打开材料前停止。
- 只打开上传字节的临时副本，保持禁用宏、关闭外链更新、只读校验、不保存原件；只退出并清理本次创建的实例。Microsoft PowerPoint 的既有实例限制保留。
- 读取的是上传时的已保存内容；用户留在 WPS 中的未保存编辑不混入上传材料。

## 验证范围

`tests/test_wps_open.py` 为显式开启的真实 WPS 测试，分别打开可见的合成 Word、Excel 文档并保留未保存编辑，再由 Agent 读取同一文件的上传快照。断言提取成功、未保存标记不进入提取结果、原文档内容和 Saved 状态不变、窗口可见性和文档数量不变、宏及链接设置不变、原文件哈希不变、原实例 PID 与创建时间仍存在。

另外保留已使用实例拒绝接管、不明新进程组拒绝接管、只读及权限拒绝、超时精确清理等回归。测试仅处理本轮自己创建的合成文档，不关闭用户原有窗口。

当前 WPS 12.1.0.29161 的演示组件仍无法确认禁用宏，PPT 本机后备读取限制未在本轮放宽。普通 PPTX 内置解析及 Word／Excel 读取属于不同结果，不能将本轮修复表述为所有 Office 功能全部通过。
