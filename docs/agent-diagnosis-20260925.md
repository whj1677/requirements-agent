## 1. 总体判断

当前 Agent 已具备单机受控试用的工程基础，能够保存材料、形成候选、保留未知、审阅文档并约束模型权限；但还不能把“模型调用成功”或“工程回归通过”当作需求内容可靠、正式交接可靠的证明。

最优先的工作是修复三类确定性业务缺陷：**评审门禁接受自相矛盾的结论、澄清格式修复丢失重要问题、同主题问题合并产生悬空关联**。其次修正编辑恢复、材料读取状态和备份证据完整性。需求理解质量应在这些机制稳定后，用固定材料和人工判据评价。

不建议用主观总分表达成熟度。本次结论按证据分层：

| 维度 | 当前判断 | 主要依据与限制 |

## 3. 应保留的现有机制

1. **模型没有业务批准权。** 提案以候选保存，正式确认绑定范围、底稿与文档哈希；事务和幂等键保护重复/过期请求（`workflow.py:255-276`）。
2. **来源有确定性约束。** 引用须存在于本次实际输入片段，不能仅靠模型输出一个来源 ID 就认定有证据（`contracts.py:69-83`）。
3. **失败留痕与预算约束有效。** 修复/重试共用次数限制，输出预算不自动增加；原始调用证据与失败结果保留，重启不自动重放已可能计费的请求。
4. **本地安全边界有实际实现。** loopback、Host/Origin/CSRF、接收端绑定、公开网页地址验证和固定 IP、动态资源受控读取；本次未确认 SSRF 或凭据外泄绕过，不代表专项安全审计全部完成。
5. **Office 后备读取较克制。** 普通解析优先，后备禁宏、只读、不保存原件，核对实例与进程身份；未用普通解析失败推断文件损坏。
6. **文档与 UI 的版本边界较清楚。** MRD/PRD 分别评审，历史稿只读，过期稿禁止下载，阅读和导出使用同源内容；五步流程与取消草图的最新产品决定一致。

已排除两个初步疑点：响应在采纳前写证据不会直接导致会话 Key 明文落盘，证据层先按本次 Key 脱敏；模板 mapping 为 pending 本身也不等于阻塞缺陷，需要结合具体未决语义判断。

后续质量优化应围绕以下判据，而非无限追加提示：

- 新增、修改、保持与现状能否分开；不确定时保留待核对，不推成 new/reported。
- 每个问题是否对应一个可回答的决定；材料已有答案时引用原文，冲突时说明两处依据。
- 权限、金额/计算口径、覆盖和历史生效等重要未知是否保留；模型不能替产品决定。
- 生成 MRD/PRD 时是否保留本期边界、来源与未决身份；与阅读/Word 同源。
- 记录首次结构接受、修复次数、用户需纠正的关键错误、请求耗时和 usage；不同版本/输入/模型的记录分开，不拼接统计成功率。

输入组织有优化空间：既有电价记录的原始材料封装为 27,544 字符，Schema 6,048 字符。应先测量各部分占比，减少重复元数据与历史重复文本，保留定位和完整性清单；不能用静默截断业务原文换取 token 下降。本轮未核实价格，费用未知。

### 6.1 最小验收集合

1. `ready + 关键未决`、空覆盖、普通 warning 三类评审；分别阻塞、阻塞、按规则正常保留。
2. clarify 格式修复保持问题和 blocking；超出允许变化则失败并保留原输出。
3. 同 topic 重复、风险升级、已回答主题冲突；关联不悬空、答案不被静默改变。
4. 同页多对象保存、真实 409 冲突、切页/刷新；输入可核对恢复，不自动覆盖。
5. 含页眉页脚/内嵌对象的材料、空动态网页、超限文本、动态重读；状态与读取覆盖一致。
6. 备份→隔离恢复→按运行记录找回来源、导出、模型原始证据；校验哈希与关联。
7. 1–2 秒延迟下任务终态落屏；正常停止不打断活动任务。
8. 当前五步 UI 完整回归和一份 MRD/PRD 的实际导出检查；历史版本仍只读。

所有新增负例先在未修版得到预期失败，再修复验证；本次缺陷探针的 `defect_reproduced=true` 不可直接沿用为修复后的成功断言。

### 6.2 真实模型评价建议

先选 2 个代表场景：一个材料明确的已有平台局部改动，一个带真实冲突/重要未知的需求。固定模型、输入、输出上限和代码版本，评判预期由 PM/独立审查者保存，不发给被测模型。

建议首轮预算为每场景最多 8 次、合计最多 16 次请求，包含修复和网络重试；连接测试如需执行也计入总数。必要业务回答缺失时停在对应阶段，不由执行者代答以制造全流程成功。预算用尽就交付全部结果，不自行加轮。

首次两场景只能证明具体案例效果，不能宣称统计可靠率。记录每个阶段是否执行、首次接受/修复后接受/失败、重要错误、未读材料、人工纠正和 usage；复测保留原结果，不覆盖失败记录。

### 6.3 明确延后

- 多用户/公网部署、权限平台、全面框架迁移、通用知识库/RAG、扩大文档格式及完整 OCR：`DEFERRED`，不在本轮优化范围。
- 类型与组件可维护性：`P3/BACKLOG`，只随上述必要改动整理受影响文件；不因为 JSX 行长或文件大而重写 UI。
- 已有图片读取并行工作：合入后复核授权、位置、状态、去重和恢复，不在本计划另开同一实现。
- 依赖弃用告警：有明确升级收益及兼容回归时单独处理，不能为消除两条 warning 扩大当前改动。
