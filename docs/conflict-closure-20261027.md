## 修复内容

1. 检查失败后，已有批量核对表仍显示“重试本次检查”，不再被迫重新起草。未确认的编辑仍受离开保护。
2. 整表确认只提交真实存在的合法可编辑字段，不能将检查引用的整个流程对象当作一个字段提交。
3. 模型把验收、问题、详细定义放进 behavior 时，仅在位置唯一、无字段冲突、移动后整体符合结构时原值归位，不编造或改写业务。
4. 成文检查批量起草出现错误来源别名时，追加一次 Agent 请求，只返回错误位置的引用补丁。必须落在本轮实际发送的来源/片段对中，完整覆盖错误位置；所有业务文字及有效引用保持不变。无法修复则保留原稿，不递归重试。
5. 检查项与待决定清单不一致、固定字段引文不合法时，采用局部元数据补丁；不允许模型整段重写其他问题、建议或正确引用，也不替用户确认。
6. 已采纳内容的“建议”来源前缀、历史候选、纯排版和同义标题，不再单独造成业务阻塞。实际相反规则仍需处理。只有原回复已经判定可评审、没有待决定事项的非阻塞提醒，才允许去掉无法核实的引文并明确标为“引文未核实”，不伪造依据。
7. 验收修订目标限定为当前关联验收条款，排除需求修订候选，避免整行被拒收。
