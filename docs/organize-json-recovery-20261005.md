# 整理失败后的本地恢复（2026-10-05）

## 本轮状态卡

- 阶段：代码、专项验证、原工作台更新及本次有效草稿恢复均已执行；候选仍待人工业务核对与采纳。
- 唯一目标：处理无歧义的重复字段，并让已聊内容形成的有效草稿可在不重调模型的情况下恢复到人工核对阶段。
- 输入：当前工程、用户报告、对应的完整本机调用证据；不向外发送业务资料。
- 交付：相同重复值的确定性处理、新问题子项继承父问题门禁、本地恢复接口及页面入口、隔离回归与原工作台更新。
- 验收：只接受无歧义、完整、来源与内容检查有效的派生结果；输入已改变、内容冲突、证据不完整时拒绝恢复；恢复幂等、候选待采纳、旧失败与原始证据保留，成功后自动进入草稿页。
- 不做：不修改已确认业务规则、不自动采纳、不开新日常入口，不自动重跑真实模型，不把离线验收当作业务认可。
- 停止：实现、受影响回归、原始证据本地验证及工作台更新完成后收口。
- 分工：主窗口实现、核对证据并验收；1 个只读 Agent，请求 gpt-6-sol / medium，3 次工作派发，实际执行侧型号和费用未知。

## 已核实问题

真实响应仅一处来源引用键重复，两份数组逐项完全相同；旧解析器不区分一致重复和内容冲突，直接拒绝整份结果。另有新父问题标为阻塞，而其两个子问题标为非阻塞。已有检查要求子问题不得降低父问题的阻塞性，但程序未执行继承，而是拒绝整体结果。

只读诊断中，去除相同重复成员、沿用既有空对标栏处理，并让新子问题继承父问题门禁后，15 条候选及 5 组问题通过原结构、来源和业务内容检查。恢复前原项目没有候选。仅跳转到空草稿会迫使用户重新整理，不能视为问题已解决。

## 已实施处理

- 普通整理响应仅在完整原始证据可核对时处理完全相同的重复键值；保留类型、数值字面形式与数组顺序的比较，不接受冲突、截断或来源缺失的内容。原始响应及处理轨迹保留。
- 新问题拆分后继承父问题较严格的阻塞条件，不改写业务正文，不放宽已有问题的检查。
- 新增“恢复草稿（不调用 AI）”入口。恢复须匹配原任务、调用、原始输入、实际发送的来源片段和当前项目状态；有并发任务、版本变化或证据缺口时拒绝写入。
- 恢复在事务中复用完整内容验证，只写入待审核候选，并保留历史失败状态与调用次数。重复点击不会重复追加；未发送或未保存内容先由用户处理。
- 恢复成功后自动进入第 2 步。页面测试发现操作自身的忙碌状态曾阻止跳转，已调整为操作完成后导航并复验。返回聊天时显示“已恢复待核对草稿”和“查看恢复的草稿”，不继续以旧失败提示为主入口。
