## 3. 集中核对的产品取舍（已获得实施授权）

| 决定 | 推荐设计 | 对现状的影响 |
|---|---|---|
| D1 开始门槛与重复核对 | “本次想新增或修改什么”为核心输入，平台/页面与保持项可补充；可先只提供材料。分析后进入 P02 查看理解，缺失继续显式显示；真正的范围核对留在 P02 | 不再要求第一步先填齐独立 product/module/intent 核对表；调整第一步接收输入的检查语义，不能因此跳过 P02/后续门禁 |
| D2 局部 AI 入口 | 默认关闭的“帮我完善此项/调整此草图”抽屉，标题显示对象与版本；一处修改意图输入，结果为候选差异。完整对话保留在历史/任务记录 | 移除永久助手栏和全局发送入口；方案比较是范围页的可选展开能力，不强制每个项目探索方案 |
| D3 双文档评审 | MRD、PRD 分别点击“已核对这份文档”，绑定实际 artifact ID 和当前内容；两份均有效且已核对，才“完成文档评审并继续” | 新增最小评审记录及门禁接线；旧整体阶段核对保留原语义，不补造过去的逐文档评审事实 |
| D4 未保存内容 | 离开编辑时提供“留在当前页/保存后离开/放弃修改”；保存只保存当前输入或回答，不启动模型。无法持久化的控件明确“仅本次页面保留” | 按实际对象保存；不默认把私有正文塞入浏览器持久化缓存；刷新给离开提示，不承诺跨重启恢复 |

其余工程选择自主完成：延续灰白/绿色；一个主要滚动区；窄屏折叠步骤条；字段/来源/版本绑定及焦点管理。以上确认不等于业务条目批准、模型调用授权或部署授权。
