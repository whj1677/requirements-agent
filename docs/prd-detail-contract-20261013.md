# PRD 详细需求、流程图预览与导出

2026-10-13。本次把已讨论的“结构化详细需求 → 产品经理集中确认 → 图文表 PRD”接入现有工作台。日常地址仍为 `http://127.0.0.1:8765/`，没有新增服务或数据目录。

## 使用方式

1. 打开项目后进入“和助手聊需求”，再进入“完善需求”。打开“需求与验收”，核对本条需求的详细定义；已有普通需求可主动启用详细定义。
2. AI 整理储能云平台需求时，将同时起草字段属性、交互逻辑、业务流程和适用的状态变化。AI 结果仍是候选；已知资料、建议及未知分别显示。
3. 产品经理修改内容、查看依据、处理待决定项后，沿用底部“确认并进入交付”。不新增逐字段批准按钮。草稿可以先保存，刷新可恢复。
4. PRD 由同一份详细定义生成字段表、交互表、流程步骤与分支条件表、状态表和流程图。预览中点“放大流程图”可缩放查看；DeepSeek 只需输出文字结构。
5. Word 使用表格和内嵌 PNG，Markdown 内嵌图片。未确认内容可以下载带标识的评审稿；正式下载继续检查确认、版本、来源与完整性。

## 本次实现范围

- 字段展开业务含义、类型、来源、必填、默认、约束、可见与编辑权限；数字补单位与精度、枚举列出选项、时间补口径、计算结果补公式。可补充空值处理、唯一性及父字段。
- 交互展开角色、入口、前置条件、触发动作、输入、校验、处理中、重复操作、取消、成功、失败和数据影响。
- 流程采用带稳定编号的步骤和连线；判断与等待须有继续条件，检查缺失引用、不可达步骤和无出口路径。流程图与表格均由程序绘制和组装，不执行模型输出的 HTML/SVG。
- 属性不适用须写明原因，缺少规则不能用“默认”“资料未说明”冒充已明确内容。结构检查不证明业务语义正确。
- 来源须属于本轮真实输入；既有依赖不能在模型往返时被静默删除。模型不能提交确认标志。
- 集中确认绑定详细内容、关联规则/验收、依赖及相关来源。修改后原确认失效；并发编辑保留草稿，冲突需明确选择。
- 文档使用保存时的快照。旧图提示更新，图片缺失、结构错误及图文绑定不一致拦截下载；评审模式也不能绕过这些错误。
- 旧条目未包含新结构时保留旧确认哈希与历史文档，不自动迁移或替用户确认。

## 验证与当前限制

离线回归和隔离浏览器覆盖编辑、刷新恢复、缺项定位、并发合并、集中确认、图文表预览、缩放及评审/正式下载。浏览器使用实际应用 ASGI 和最终构建文件，无额外监听服务、无日常项目写入。记录在 `work/detail-prd-20261013/browser-final/verification.json`。

最终相关回归为 360 项通过；浏览器 7 项通过；Word 经本机只读页面渲染检查 7 页，修正了表头和分页。已更新原工作台并核对运行版本及静态文件。重启前后数据库内容哈希一致，保留 32 个项目、552 个历史版本和 1411 条记录。总记录见 `work/detail-prd-20261013/verification-summary.json`。

真实 DeepSeek 使用两种合成业务说明，各两轮，共 4 次请求；首次发现问题后修改生成契约再复验，没有把失败输出改写成成功结果，费用未知。复杂例可以保存为未确认候选，缺项可定位；简单例两轮均因额外属性未通过协议检查。复杂例还存在跨站失败范围、最终结果前提和重试分支等语义问题。因此本次不宣称模型已稳定生成可直接交给开发的 PRD，产品经理确认及独立文档审查仍是必要环节。

第二轮复杂例的 27 条属性诊断不等于 27 个业务问题，其中 22 条集中于三个未定参数。应在当前需求中集中决定这些规则，不把每个空属性都交给用户反复问答。对不属于页面数据的参数，不应机械扩成可编辑字段。

真实输出、未确认候选和独立只读复核分别保存在 `work/detail-prd-20261013/real-model-01/`、`real-model-02/`、`real-model-review-01.md`、`real-model-review-02.md`。这些本机证据不提交到版本库，不作为真实平台业务规则。
