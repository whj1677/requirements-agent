### 场景一：工单状态筛选

沿用诊断时同一固定资料与两项预写决定：包含“已取消”，重入默认“全部”且不记忆选择。通过普通 API 回答、核对范围及采纳主修订、3 规则、3 AC，未人工补写行为字段或新增 AC 来绕过缺项。

独立内容审阅后做了两处显式、可追溯的人工措辞纠正：现状条目“商品关键字”改回源文“关键字”；AC 删除源文未明确的“或清空”。两次普通编辑产生各自人工修订来源，原模型响应保留。模拟 PM 也将范围中的两处“待定”更新为预先写定的答案；不是模型自动决定业务。操作文件为 `live-test/synthetic-candidate-review-v4.json`。

采纳后原需求稳定 ID 未变，两题状态为 answered/applied；1 主需求、3 规则、3 AC 进入文档规范范围。MRD/PRD 均生成，并从正式下载处理链得到 4 个文件。独立判断见 `live-test/semantic-ingest-v3.json`、`semantic-clarify-v4.json` 和 `final-semantic-review.json`。

残余语义限制必须保留：

- 模型在讨论说明/限制中把已知“点击查询”称为触发细节待定，MRD 风险段也有相应矛盾；规范规则保留明确的查询按钮行为。生成稿须纠正这类说明后才能谈业务批准。
- MRD 还把已选主需求描述为待稳定编号的候选，并在没有接口资料时断言不涉及其它模块接口变更；这两项自由文案没有通过语义验收。原稿保留，未静默改写后声称模型直接正确。
- 个别行为/AC 的直接 source_refs 不完整，事实仍能从项目关联规则、约束和回答追溯；不能宣称字段级引用全覆盖。
- 3 条 AC 覆盖筛选、AND、第 1 页、全部、空结果、重入默认，不单独枚举全部权限、页大小/排序及范围保持项；这些在规则/约束中承载。
- 文档模板参考维度 mapping 仍为 pending；“文件可下载”不等于公司模板语义已完整覆盖。历史修订候选保留为讨论材料，不冒充已选规范。
