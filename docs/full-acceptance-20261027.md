## 已修复并复验

1. 结果校验把“查询系统记录并以返回结果更新显示”误认为业务写入。现在仅排除这一明确的响应展示表达；超时后虚构成功或写入仍会拒绝。
2. 模型在已明确的唯一性约束外，重复输出一个没有对应属性的 `evidence.uniqueness`。只有与既有约束依据完全一致时才整理重复元数据；未知、不同来源或缺少明确约束仍不自动处理。
3. 模型用真实来源 ID、片段 ID 定位引文时，程序只支持条款属性路径。现在支持精确来源/片段对，但必须属于有效材料并同时保留该检查项的来源引用；不猜测替代条款或片段。此前一份真实检查输出已通过本地重新校验，**未冒充重新跑通整条真实流程**。
4. 普通工作区缓存释放了任务面板正在指向的项目，导致跨项目查看结果失效。现在保留该项目，准确返回原任务及助手入口，不改成打开最新任务。
5. 1093×550 等短桌面仍未达到编辑空间标准。进一步压缩项目栏与阶段栏的外部空间，保持 14 px 编辑文字；完整笔记本布局脚本复验通过。

历史浏览器脚本同步改用当前阶段入口、折叠菜单和移动项目抽屉；存储断言等待真实延迟落盘，不再要求每次输入同步写存储。

## 剩余发测阻塞

- 真实检查回复的 `required_decisions` 与 `findings.decision_question` 仍可能不一致。不能靠模糊匹配或随意绑定来绕过，需要保持原问题和条款证据的受控恢复。
- 复杂冲突复检中，模型仍可能引用错误条款，或修复时改变其他引文；有时还会提出相互冲突的新确认方案。当前保护机制保留已有内容并拒收，**但尚未证明普通用户能快速完成这一真实模型闭环**。

所以，离线矩阵全绿与单次 PRD 成功不能作为“复杂真实模型使用不会再中断”的结论。
