# 需求 Agent 图文使用说明

适用于 Windows 10/11 x64。安装版本以交付包及 `release-manifest.json` 为准；运行对应的 `RequirementsAgent-<版本>-windows-x64-setup.exe`。本页配图来自 1.2.8 试用版，界面细节以当前工作台为准。无需另装 Python、Node.js 或设备许可证。程序未做商业代码签名；企业策略阻止时请联系发包人或 IT。

## 1. 配置自己的模型

左下角“模型设置”填写服务商 Base URL、模型名称和自己的 API Key。以现有默认配置为例，接收端为 `https://api.deepseek.com`，模型名为 `deepseek-flash`；请以服务商账户实际可用模型为准。保存密钥到此电脑后，再按需测试连接。测试连接与模型任务可能产生费用。

![模型设置：填写接收端、模型和自己的密钥](images/trial-1.2.8/model.png)

纯文字可先只配置主模型；要识别图片，另配置支持图片输入的视觉模型。不要把主模型连接成功当作图片已读懂。Key 不随安装包或项目导出，换电脑需要重新配置。

## 2. 新建项目，和助手聊需求

点击“新建需求项目”，先围绕一个小需求说明使用者、问题、预期、本期范围和不做什么。打开已有项目先回到需求助手，不会自动整理或调用模型；已有草稿可点“继续核对已有草稿”。

工作台按三个实际入口推进：“聊清需求想法” → “核对草稿与规则” → “评审与交付文档”。第二步在同一张确认表中核对草稿、澄清规则与验收，再进行成文检查；流程图随 PRD 一起核对。各区显示当前任务和下一步，阻塞项直接提供处理入口。

![需求助手：已有草稿可以直接继续](images/trial-1.2.8/assistant.png)

## 3. 添加资料，核对读取结果

支持 Word、Excel、PDF、PPT/PPTX、HTML/HTM、截图和文字。“已添加”不代表内容已读取；检查读取状态并查看实际内容。PDF 不自动 OCR 或解密；旧 PPT 的后备读取需要获准使用的本机 PowerPoint。HTML 只读静态正文，不运行脚本。Office 不随包提供，企业策略与权限仍须遵守。添加、读取和查看资料不会调用 AI；主动发起 AI 操作时，才将本次有效范围发送给已配置的模型。

![项目资料：核对实际读取状态与内容](images/trial-1.2.8/sources.png)

## 4. AI 起草，人工核对

在“聊清需求想法”中选择整理草稿即可开始 AI 起草，不再弹出授权窗或要求再次点击运行。系统会先核对输入、资料和模型配置；无法开始时显示具体原因并保留输入。AI 给出草稿后，人工核对或修改；查看、编辑、保存草稿和确认不调用模型。笔记本可用“专注核对”增加表格空间。

当前进度分别显示可核对需求、本期已纳入需求、待决定问题和已答待落实项；项目累计记录放在“历史与累计记录”中。已落实回答默认收起，展开后仍可查看和修改；从问题定位入口进入时会自动展开。

新问题可在“逐题回答”弹窗中选择建议并补充文字，提交后继续下一题。保存回答不等于确认需求；随后核对正文与验收中的实际落实位置。选中的建议以用户提交的回答身份带入后续核对，仍按完整原话保留明确的待定条件。

“AI 补充建议”起草当前表格及答案对应的正文、验收；只有已经启用的详细定义才随本次处理，普通文字需求不会因此自动增加字段对象或状态机。

确证相同的问题只填写一次，界面会列明对应的原记录；确认时仍逐条核对和保存。仅仅关联同一需求的问题归到一个入口，展开后分别处理，不因措辞相近就替用户作决定。已保存回答会继续带入后续整理，已解决的历史问题不作为新问题追问。

![需求表：核对需求、验收及详细定义](images/trial-1.2.8/table.png)

## 5. 有冲突时，在同一张表集中处理

“成文检查”集中列出全部待确认点和推荐草稿。缺修改时点“AI 批量起草全部修改”，一次处理全部点；已有回答和人工编辑保留。检查涉及的旧验收会直接显示，避免只新增一条正确验收而漏掉旧冲突。

![成文检查：全部确认点集中在表里](images/trial-1.2.8/conflicts.png)

人工与 AI 改到同一处时，并排比较“我的修改 / AI 新建议”，选择保留人工内容或采用 AI 建议，再统一保存；比较与选择不调用模型。

![同一区域比较两个版本](images/trial-1.2.8/compare.png)

## 6. 一次确认，整批复检

点“确认全部修改并复检”。缺项会在原表直接标红并显示输入框，不需要重新找页面；缺少真实名单等事实时不能由程序编造。补齐后仍用同一个确认按钮。确认后再运行一次整批复检，不逐条调用模型；发现新问题时在同一张表继续处理，已有回答保留。

![填写缺项后再统一确认](images/trial-1.2.8/missing.png)

## 7. 失败、部分输出或取消后继续

失败不会覆盖已有需求或 PRD。成文检查失败时，可在原页面点“重试本次检查”，不用重新起草已有修改；只有缺修改草稿时才点“AI 批量起草全部修改”。错误原因可以展开查看；手动重试仍会核对当前任务范围，可能再次计费。提交结果未知时先刷新任务状态，不要重复发起。模型格式或来源编号可恢复时，系统会在本次任务内追加一次修复，业务原文与有效引用保留；无法恢复时保留原稿。只生成部分可用修改时，核对未完成点并整批补齐。

## 8. 生成、核对与下载 PRD

复检通过后点“生成 PRD”，先预览本轮新增、逐字修改、未确认数量、排除项和 AI 建议；点“核对后生成 PRD”才发起生成，返回核对不会修改需求或调用模型。暂时不能决定业务口径时，可点“先生成待确认评审稿”，核对预览后直接在本机按已保存内容成文，不调用 AI，未决事项随文档保留。失败、过期、来源或硬性结构错误仍须先处理。

每个工作区会说明当前完成情况和下一步。成文检查通过后突出生成；交付受阻时先定位第一项实际问题；交付条件齐备后再突出正式确认。其他查看和历史入口仍可使用。

![PRD 已生成：阅读正文并下载评审稿](images/trial-1.2.8/prd.png)

“正式交付前需处理”不妨碍可用评审稿阅读与下载。评审稿有待确认标识，不能当作已完成业务批准；处理完未决事项并核对当前版本后再正式交付。旧文档和历史记录保留。

工作台与 Word 共用同一份阅读内容：短段落说明职责和规则，参数、状态和验收用表格对照，删除逐字重复的说明；业务条件、数值、单位和未决事项保留。后续 AI 起草也采用这一写法，不以删减规则换取页数。

Word 统一使用 A4 纸和微软雅黑；正文、表格均为 11 磅，标题按层级区分。普通正文首行缩进两字，标题、编号项、公式及表格不缩进；工作台正文同步采用两字缩进。表头跨页重复，表格行不拆页，标题与后文保持相邻。重新下载即可使用最新版式，无需重新调用模型。

文档按本期内容组织：单个基础需求合并概述和重复说明，多功能及已核对的详细定义保留完整章节。需求和验收使用简短编号，原编号与来源仍保留；验收用表格展示，相同标题只写一次。流程图展示动作、判断和分支，完整业务约束保留在正文，点击流程图可放大查看。

PRD 包含主要功能清单、功能流程图和风险点与待确认。风险按当前业务记录；AI 提醒的潜在遗漏明确标为“AI建议，待核对”，不自动改成业务规则或新增必答问题。

复杂流程图过小时会保留总览并附可读分图；网页可选择分图，Word 和 Markdown 同时保留完整步骤与条件。

## 9. 保存、升级与退出

先保存输入，等待任务结束，再点安装版左下角“退出工作台”确认退出。只关浏览器不会停止后台服务。固定入口为 `http://127.0.0.1:8765/`，重复启动复用同一实例。升级前正常退出并按资料权限备份 `%LOCALAPPDATA%\RequirementsAgent`；卸载保留业务数据。

## 10. 反馈问题

直接回复发包人，附软件版本、发生时间、操作步骤、预期和实际结果、完整提示、任务编号（如有）及脱敏截图。界面问题另附屏幕分辨率、Windows 显示缩放和浏览器缩放。请勿发送 API Key、完整数据目录或敏感业务材料。
