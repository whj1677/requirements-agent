# 需求 Agent 使用说明

- 适用对象：产品经理、需求整理人员及需求内容评审者。
- 源码说明基线：`v1.1.0-local.20260926`，正式源码分支为 `main`。客户安装包的版本以随包构建清单为准。
- 日常入口：<http://127.0.0.1:8765/>。本文对应当前五步工作台。

**Windows 安装包用户请先阅读 [安装与设备授权说明](windows-installation.md)。** 从“需求 Agent”快捷方式启动，在 `http://127.0.0.1:8765/activation/` 网页导入拥有者签发的本机许可证，再点击“进入工作台”；运行环境已随包提供。未授权时只开放授权网页及激活接口，不加载业务应用或初始化业务数据库。

客户版数据位于 `%LOCALAPPDATA%\RequirementsAgent\data`。退出时先保存输入，点击工作台左下角“授权与退出”，在授权网页点击“退出本机服务”并确认；只关闭浏览器标签页不会停止服务。完成激活后，可从本文第 2 节继续阅读业务操作。本文第 1、10、11 节的 `start-local.cmd`、Python 安装命令及仓库根目录 `data/` 说明适用于源码部署，不适用于客户安装包。企业加密或受保护的 Office 材料，需要客户本机已经获准使用的 Office 只读提取，具体支持情况以该企业环境的实际验证为准。

本工具帮助你将已有平台的增量诉求整理成可核对的需求底稿、MRD 和 PRD，并在人工确认后生成指定版本的研发交接包。模型可能理解错误或提出没有依据的建议，整理和审查结果都需要你核对，未知业务规则由你确认。文档生成、内容确认也不代表业务系统已开发或测试合格。

本文位于源码仓库的 `docs/`，也随 Windows 客户安装包提供。历史精简单机源码包包含 `web/dist` 和用于重建的 `web/src`，不包含 `docs/`、`tests/` 及完整工程验证脚本；它与现在包含运行环境的客户安装包不同。源码基线依据见仓库中的 [正式版本记录](version-control-20260926.md)。

## 1. 源码部署用户：开始和结束一次工作

1. 双击本工程根目录的 `start-local.cmd`。
2. 浏览器打开固定地址 `http://127.0.0.1:8765/`。重复启动会复用已有工作台。
3. 从左侧选择已有项目，或点击“＋ 新建需求项目”，填写名称后点击“创建项目”。
4. 按下文五步操作。中途离开前使用相应的保存按钮；看到“未保存”时，输入尚未成为已保存成果。
5. 结束后先等模型任务结束，保存输入，再在工程根目录的 PowerShell 中执行 `.\scripts\stop.ps1`。关闭浏览器本身不会停止后台服务。

日常入口默认是仅供本机使用的无令牌模式。若已有服务采用令牌登录，重复双击不会更改登录方式；登录页所需的是启动脚本显示的“本机访问令牌”，不是模型 API Key。

如需使用令牌登录，由维护者正常停服后执行 `.\scripts\start.ps1 -OpenBrowser`。两种方式共用相同地址与根目录 `data/`，不需要第二套工作台。

首次安装、缺少运行环境或缺少前端文件时，先看第 10 节。

## 2. 模型设置、材料发送与费用

进入左侧底部“模型设置”，先核对“配置用途”、接收端、模型名称和密钥状态。

修改 Base URL、模型名称等高级设置后，先点击“保存模型配置”，核对页面显示的已保存接收端，再“使用此 Key”或“测试连接（调用模型）”。输入框中的修改尚未保存时，密钥和连接测试仍使用服务端原有配置；不要将临时 Key 绑定到未核对的接收端。

| 设置或动作 | 使用说明 |
| --- | --- |
| 主分析模型 | 用于整理材料、澄清、成文和语义审查。未配置密钥时仍可录入资料、人工整理和阅读已有内容。 |
| 图片视觉模型 | 用于待分析的截图及提取出的图片。主分析可用不代表图片模型已配置或支持视觉。 |
| 保存模型配置 | 保存接收端、模型名称和预算等设置；不等于允许发送项目材料。 |
| 本机 `.env` | 默认读取 `RA_DEEPSEEK_API_KEY`。只在本机编辑器中填写，修改后正常重启应用，无须重新安装。 |
| “使用此 Key” | 在“高级模型配置、密钥与连接测试”中为当前接收端设置临时密钥，仅在当前服务进程有效，不写回 `.env`。 |
| “清除会话 Key” | 清除临时密钥；再查看界面显示的实际密钥来源，不等于删除 `.env` 中的配置。 |
| “测试连接（调用模型）” | 显式调用接收端，可能计费，不发送项目材料；成功只证明本次接口连接成功。 |
| “测试视觉能力（合成图片）” | 使用合成图片检查视觉接口，可能计费，不能代替对实际图片识别结果的核对。 |

不要把真实 Key 发到聊天、截图、文档或 Git。`.env` 是本机明文文件，不是加密保险箱；本机访问令牌与模型 Key 也不可混用。

每次发起分析、更新理解、生成文档或审查时，工作台先显示“核对本次任务”弹窗。检查以下内容后再点击“授权本次范围并运行”或“运行本次任务”：

1. 接收端地址及模型是否是你允许使用的服务。
2. 材料列表、当前底稿、问题、讨论记录和本次新增输入是否允许发送。
3. 本次执行步骤及最多请求数是否可接受；这个上限包含全部步骤、重试和修复。
4. 是否存在缺密钥、图片能力未配置、前序核对未完成等提示。

新增材料或新增回答可能使原有授权不足，需要重新核对发送范围。排除材料不会抹除它此前已经形成的底稿或讨论内容；授权前也要检查已有讨论中的敏感信息。

普通启动、保存输入、切换文档、人工核对和运行诊断不会自动调用模型。费用显示“未知”不代表免费。任务详情可查看已执行请求数与本次上限。

DeepSeek 语义审查默认启用思考模式，其开关与其它结构化阶段分开；可能更慢、消耗更多 token。达到输出或任务预算上限后，应核对原因和设置，再显式发起新任务，不把不完整输出当成审查结论。

运行中可点击“停止后续步骤”；已发出的请求仍可能计费。重启不会自动重放未完成任务，也不要通过连续重复点击来判断是否卡住。

## 3. 添加资料，先检查是否真正读到内容

任一步都可通过页头“项目资料”进入材料区；第一步也有“添加资料”。选择材料用途：现状、目标、竞品参考或模板。

| 材料入口 | 操作 |
| --- | --- |
| 粘贴文字 | 将原文放入“粘贴材料”，点击“保存文字材料”。 |
| 本机文件 | 点击“上传文档或截图”选择文件；当前不支持拖拽。支持 TXT、MD、DOCX/DOC、XLSX/XLS、PPTX/PPT、PDF、PNG、JPG/JPEG、WEBP，单个文件上限 12 MiB。 |
| 公开网页 | 输入公开 HTTP(S) 地址，必要时勾选“需要动态页面渲染”，点击“确认有权读取并添加”。只读取公开网页，不使用浏览器中的登录状态。 |

网址无法读取时，可检查地址或改用有权提供的导出文件、截图；需要登录的页面或内网地址不能靠公开 URL 入口读取。

上传成功只说明材料已添加。展开每份材料下的“来源片段”，逐项核对正文、表格位置和原文；文件名、缩略图或空片段不能证明已理解。

| 页面状态 | 如何处理 |
| --- | --- |
| 已添加 / 读取中 | 等待读取完成；本机 Office 处理可能较慢，若超时则按页面提示处理，不反复提交同一材料。 |
| 已读取 | 已取得可解析内容，仍需查看来源片段并与原件核对。 |
| 部分读取 | 查看限制说明；图片、图表或其它对象可能未取得，不要将缺失部分视为已理解。 |
| 待视觉分析 | 图片还没有形成视觉观察；需配置支持视觉的模型并授权发送，或排除图片后先处理文字。 |
| 需要本机 Office 处理 | 请维护者检查本机 Office 和读取条件，再尝试重新读取。 |
| 权限受限 | 先核实你和本机 Office 对原件的合法访问权限，不修改保护设置来绕过限制。 |
| 读取失败 | 查看具体原因；“当前读取方式无法解析”不等于文件损坏，可使用“重新读取（保留原件）”。 |

Word、Excel、PowerPoint 优先普通解析；旧格式或普通解析失败时会尝试本机 Microsoft Office 只读提取。此过程不保存或改写原件。本机 Office 能打开文件，不代表所有文字、图片和页面布局已被程序取得，也不代表获准向模型发送。

内嵌图片会显示提取、已分析和待分析数量。像素已提取不等于图片内容已分析；父材料的排除或恢复也会影响其内嵌图片。

使用“排除材料”将不适用材料移出后续使用范围；需要恢复时点击“恢复使用”。保留原件和原始读取状态，避免以重新命名、重复上传掩盖失败原因。

## 4. 第一步：提供现状与诉求

**入口：** 项目顶部“提供现状与诉求”。

1. 填写“现有平台 / 页面”，说明这次改动属于哪里。
2. 在“本次想新增或修改什么”写已知诉求、问题和目标；零散信息也可以先保存。
3. 在“保持不变 / 暂不涉及”写清保持项和本期边界，不确定的内容明确写待确认。
4. 按需添加资料，核对读取结果。单纯诉求也会在保存后形成项目来源，无须为了开始而伪造附件。
5. 只想暂存时点击“保存草稿”；准备分析时点击“分析现状与诉求”，核对任务弹窗后运行。

**预期结果：** 已保存输入留在项目中；分析成功后可查看现状摘要、改动目标、保持项及待补充信息。这些是待核对的整理结果。

**进入下一步前：** 确认分析实际产生了结果。若显示“资料已保存 · 分析未成功”，先查看失败详情；保留的输入不等于分析完成。已有结果可通过“查看已有分析结果”进入第二步。

## 5. 第二步：核对现状、价值与改动范围

**入口：** 顶部第二步。

1. 阅读现状摘要、改动目标、保持项、不在本期范围四张卡；有偏差时点击对应“编辑”，修改后“保存此卡”。
2. 使用“去补充”核对目标使用者、问题与改动价值、优先级与依据，再“保存补充信息”。未知内容不能用模型建议直接补成事实。
3. 展开“关键需求条目”，查看编号、原文、改动性质、来源及建议属性。遗漏时可“＋ 新增候选需求”；填写后“保存候选”。
4. 勾选真正属于本期的需求。范围勾选与独立采纳是两件事：核实后，还需在“独立采纳状态”中选择“采纳此条”；不接受的条目可暂缓或不采纳。
5. 有未保存修改时先“保存范围草稿”或“保存范围并重新核对”，重新查看提示；条件满足后“确认范围并进入下一步”。

**预期结果：** 本期范围有稳定需求编号，新增/修改与现状/保持项区别明确，目标用户、价值、优先级和边界均有经你核对的内容。

**进入下一步前：** 展开“继续前还需核对”处理缺失项；空需求列表、无法确定的改动性质或当前阶段的阻塞问题不能视为已完成。

“按需比较方案方向”是可选工具。“探索可选方案”会调用模型；“按此方向继续讨论”仅记录方向。只有“采纳指定条目”并核对勾选内容后才采纳对应条目，两者都不等于正式确认。

## 6. 第三步：澄清流程与规则

**入口：** 顶部第三步。问题按需求分组，建议与答案分开展示。

1. 阅读问题及提问原因，在“你的回答”中写实际业务决定，再点击“保存本次回答”。“填入建议”只是填入编辑框，仍要核对并保存。
2. 暂时不知道时点击“暂不确定，保留未知”；问题仍未解决，相关阻塞不会自动解除。
3. 展开“核对条目与业务行为，或根据回答更新理解”。需要将回答整理为修订时，点击“根据已保存回答更新理解”，核对范围后运行模型任务。
4. 在“待采纳候选”中展开详情，核对行为、关联和来源；修订候选还需对照原条款及变化，新增候选没有原条款对比。确定正确后“采纳”；不接受则暂缓。修订候选采纳后保留原需求编号。
5. 展开“核对业务行为、验收与需求关系”，逐条填写或修正“谁操作、入口及前置条件、主要流程、业务数据、权限约束、操作结果、边界和异常”，点击“保存此需求行为”。确实不适用的维度应说明业务原因。

### 保存回答与采纳的区别

| 动作 | 得到什么 | 还要做什么 |
| --- | --- | --- |
| 保存本次回答 | 留下你的回答和来源依据 | 核对关联需求是否需要修订 |
| 根据已保存回答更新理解 | 形成待审的理解或修订候选 | 查看差异，逐条决定是否采纳 |
| 采纳候选 | 将该候选纳入当前底稿，或修订对应原条目 | 检查本期范围、行为、验收及后续文档是否需重新核对 |
| 核对规则并继续 | 记录当前规则阶段的人工核对 | 继续生成和评审文档，不代表正式业务批准 |

### 人工补充验收条件

若本期需求缺少验收，不必只等待模型补齐：

1. 点击“＋ 补充关联验收条件”，选择实际关联的本期需求。
2. 填写验收名称和原文，写明可观察的操作、条件与预期结果。没有业务依据的数值、权限和异常规则继续澄清。
3. 点击“保存验收候选”。此时只形成候选，没有自动采纳。
4. 返回并展开上方“核对条目与业务行为，或根据回答更新理解”，在其中的“待采纳候选”核对内容、关联和来源后点击“采纳”。

“本期以外的未决事项及范围决定”用于记录确实移出本期的问题及理由；问题仍保持未知。本期需求仍依赖的规则不能通过填写移出理由来跳过。

**预期结果：** 本期需求均已明确采纳，行为说明可核对，并有已采纳的关联验收条件。

**进入下一步前：** 所有影响当前范围的阻塞问题、待核对修订及缺失维度已处理，再点击“核对规则并继续”。不要求把范围外未知伪装成已有答案。

## 7. 第四步：评审 MRD 与 PRD

**入口：** 顶部第四步“评审 MRD 与 PRD”。当前工作台没有独立的草图核对步骤，不需要寻找旧六步流程中的草图按钮。

1. 选择“PRD 评审稿”或“MRD 评审稿”，点击对应“生成讨论稿”；已有文档时按钮为“更新讨论稿”。两份文档分别生成，均属于模型任务。
2. 在任务弹窗核对范围与预算，运行后检查实际结果。部分完成或有限制时阅读说明，不能只凭正文出现就判定可交付。
3. 使用文档目录逐章阅读。MRD 重点看现状、价值和范围；PRD 重点看需求、流程规则、数据权限、异常和验收，两份都要与本期底稿及来源一致。
4. 发现业务含义有误，回到第二、三步修改并采纳正确内容，然后更新文档；章节中的 AI 帮助只形成待核对建议，不能代替业务决定。
5. 核对当前文档后点击“我已核对这份 PRD”或“我已核对这份 MRD”。两份必须分别核对。
6. 展开“两份文档的版本与核对状态”，确认均对应当前底稿；条件满足后点击“完成文档评审并进入交接”。

“历史版本与章节参考设置”可切换历史文档，只读查看不会调用模型，也不会将旧文档变为当前版本。章节参考默认使用已配置的用户原 Word 参考；确需回退时才明确选择“明确改用内置参考（原件不可用时）”，再生成文档。上传一份材料并选择“模板”，不等于自动替换本功能配置的章节参考。

**预期结果：** 两份当前版本的文档已保存并分别经你核对；侧栏如仍显示“未检查”，说明尚未执行模型内容审查。

**下载评审稿：** 文档可下载时显示“DOCX 下载”“MD 下载”“ZIP 下载”。所有尚未明确移出本期的未回答问题都需处理，不仅是标为阻塞的问题；过期或历史文档也不提供当前稿下载入口。按提示回到澄清并更新。下载评审稿不等于建立正式确认基线。

**进入下一步前：** 当前 MRD、PRD 均有效且人工核对完成。真实模型内容审查与人工文档核对是不同动作，仍须完成第五步中的“审查当前版本”。

## 8. 第五步：确认与交接

**入口：** 顶部第五步“确认与交接”。

1. 核对“本期范围、规则与验收”和“当前确认对象”，确认需求、MRD、PRD 都是要交接的版本。
2. 点击“审查当前版本”，核对接收端、材料范围及预算后运行真实模型审查。审查有问题时，按“重要待定与门禁问题”中的“前往核对”返回处理。
3. 若修改了需求或文档，按提示重新完成相关核对，并重新审查当前版本；历史审查不能替代本次审查。
4. 程序条件满足后，再人工核对业务意图与交付范围，点击“确认此版本的需求与文档”。
5. 在“再次核对本期范围与重要未知”弹窗中逐条复核，点击“提交服务端确认”。如版本已变化，返回核对当前内容后再确认。
6. 在“已确认基线与交接”找到该次基线，点击“生成此基线的研发交接包”，随后点击“下载交接包”。

**预期结果：** 出现不可变的确认基线和对应交接包入口。交接时同时说明基线编号，避免把历史包当成当前版本。

确认是需求内容确认，不代替技术设计评审、开发完成或测试验收。模型审查也不能替真人作最终业务批准；合成练习中的点击更不能代表真实项目批准。

后续修改会形成新草稿，原确认基线保留。页头若显示“有历史确认基线，当前草稿须重新核对”，应完成新一轮相关核对后再建立新基线。

## 9. 最小练习：仅使用合成资料

以下是虚构练习，用于认识按钮和流程；不是实际项目材料，也不是系统默认业务规则。模型可能提出不同问题，不以生成次数或条目数量作为练习完成标准。

创建项目“合成练习：工单列表状态筛选”，在第一步填写：

> 现有平台 / 页面：虚构的工单管理平台，已有工单列表。
>
> 本次诉求：让已有列表访问权限的客服按工单状态筛选当前有权查看的工单。练习设定只有“待处理”“已完成”两种状态；每次选择一个状态或“全部”，选择后更新列表；默认“全部”。价值是减少客服逐条查找，练习优先级为中，依据是每班均需分类查看。
>
> 保持不变 / 暂不涉及：沿用原有列表访问权限和数据可见范围；不修改工单状态、不新增权限、不导出。
>
> 练习补充：无匹配结果时显示空列表及“无匹配工单”；读取失败时保留筛选值并提示重试；取消筛选恢复有权查看的全部工单。性能指标未决定，保留待确认。

按以下顺序练习：

1. 先“保存草稿”，再分析。模型操作仍需真实可用的接收端、你的发送授权，且可能计费。
2. 第二步逐项核对合成设定；选中筛选需求并独立采纳。若模型增加批量操作等未提供内容，不应直接采纳。
3. 第三步逐条回答。练习原文没有提供的信息保持未知；若它影响本期交付，就先作明确的练习业务决定并保存，不能只为继续流程随便填值。
4. 人工补充并采纳一条验收：“有列表访问权限的客服选择‘已完成’后，列表仅显示其有权查看且状态为‘已完成’的工单；选择‘全部’后恢复其有权查看的全部工单。”其它真实存在的验收缺口仍按提示处理。
5. 生成并人工核对 MRD、PRD，执行当前版本审查，处理发现项后再练习确认和下载。

**观察重点：** 保存不等于采纳，建议不等于答案，下载不等于确认；最终包应绑定练习项目的指定基线。练习可在任何未知点停下，不要求强行走到最后一步。

## 10. 首次安装与维护者操作

首次使用需要本机 Python 3.11+、Node.js 22.12+（或 20.19 及以上的 20.x）及 npm；Node.js 要求来自当前锁定的前端依赖。单机包不包含这些运行时或模型密钥。安装会下载依赖和浏览器组件，需要相应网络访问条件。

在工程根目录打开 PowerShell，确认没有正在运行的工作台。已有项目先按第 11 节备份并正常停服，再安装：

```powershell
# 仅当本机策略允许时，为当前 PowerShell 窗口允许脚本执行
Set-ExecutionPolicy -Scope Process Bypass
# 保留已有配置；仅在文件不存在时创建空的密钥项
if (-not (Test-Path -LiteralPath .env)) { 'RA_DEEPSEEK_API_KEY=' | Set-Content -LiteralPath .env -Encoding utf8 }
notepad .env
# 在本机编辑器中填写密钥并保存，不要发送或提交真实 Key
.\scripts\install.ps1
```

安装成功后双击 `start-local.cmd`。脚本仅在缺少虚拟环境 Python 时自动尝试安装；已有环境但前端文件缺失时，应由维护者重新运行安装脚本，不能认为每次双击都会修复所有安装问题。

安装脚本会检查 8765 端口及活动任务，在隔离目录构建前端后才更新正式文件。提示工作台仍运行时，先正常停服；不要绕过检查或改用另一个端口。

## 11. 数据备份与安全更新

项目数据位于根目录 `data/`，包含数据库、来源原件及导出等成果。Git 受控源码不等于项目数据已备份；`.env`、数据、模型原始证据和本机备份不应提交 Git。

先保存所有输入、等待任务结束，并在备份期间停止编辑项目，再执行：

```powershell
.\.venv\Scripts\python.exe .\scripts\backup.py
```

脚本输出备份目录，默认位于 `data/backups/时间戳`。备份包含数据库、来源原件、导出包及模型调用证据，生成校验清单；存在活动任务或复制期间数据变化时会拒绝生成有效备份。备份不包含 `.env`，凭据应单独保管。

再次校验时，将下面路径替换为脚本实际输出的备份目录：

```powershell
.\.venv\Scripts\python.exe .\scripts\backup.py --verify "实际备份目录"
```

`--verify` 只校验，不恢复。备份可能包含原始业务材料和模型调用内容，应按原资料的权限要求保管。

更新顺序：保存输入和等待任务结束 → 备份并校验 → `.\scripts\stop.ps1` → 更新同一工程的正式版本 → 若涉及前端或依赖变更，运行 `.\scripts\install.ps1` → 双击原 `start-local.cmd` → 重新加载浏览器并核对项目与版本。后端没有自动热更新，仅更新磁盘文件不代表正在运行的服务已换版。纯说明文档更新无需安装或重启。

恢复由维护者处理：先停服并校验备份，在隔离目录核对数据库和文件；保留原 `data/` 供回滚，再恢复数据库、来源、导出和证据目录。代码、前端资源与数据应成套核对；不要将两个同 ID 项目的不同快照直接覆盖合并。

## 12. 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 双击后没有打开可用页面 | 在本工程根目录运行 `.\scripts\diagnose.ps1`，按提示检查环境和服务。诊断不自动调用模型；向维护者提供脱敏错误信息即可。 |
| 8765 被占用 | 让维护者核实占用者与工程路径；脚本不会自动换端口或结束未知进程，不要从历史包再开工作台。 |
| 登录页要求令牌 | 使用启动脚本显示的本机访问令牌；不是模型 Key。需要更换登录方式时先正常停服。 |
| 资料已上传却无法继续分析 | 展开来源片段和读取限制，确认可读内容、密钥、图片能力及发送范围；上传和理解是两个状态。 |
| 回答都保存了，第三步仍不能继续 | 检查关联需求的修订是否待采纳、本期需求是否独立采纳、业务行为是否缺失，以及是否有已采纳的关联验收。 |
| 文档没有下载按钮 | 先确定选中当前文档；处理未澄清事项，更新过期讨论稿。历史版本只读，不能当当前稿下载。 |
| 已核对两份文档，仍不能确认 | 查看第五步门禁：可能还缺当前版本语义审查，或审查存在阻塞项、必要决定及覆盖不足。 |
| 模型返回格式错误、空输出或请求超时 | 查看失败详情与已执行请求数。已有输入保留；核对接收端与预算后显式重试，不修改业务规则去适应错误输出。 |
| 模型任务显示预算暂停 | 阅读限制，核对每动作请求数、输出上限和时限；只有明确接受新调用后再发起，不自动追加预算。 |
| 出现“版本已变化”或编辑冲突 | 保留输入，比较旧值、最新值和自己的修改，重新核对后再保存或确认；不要直接覆盖他人的最新修改。 |
| 准备刷新或关闭页面 | 先保存草稿。未保存输入只存在当前浏览器会话；“保存后离开”失败时留在页面处理，不依赖刷新找回。 |
| 显示前后端不兼容 | 保存输入，由维护者核对更新和重启状态，再重新加载标签页；不要忽略提示后重复提交任务。 |
| 停止服务被拒绝 | 等待活动任务结束；无法确认任务状态时先诊断。强制停止只适用于明确接受中断的维护操作，已发请求仍可能计费。 |

需要排查时，记录项目名称、发生在哪一步、所按按钮、页面错误及任务编号；截图前遮挡密钥和敏感材料。更多安装和工程说明见 [README](../README.md)，Office 读取限制见 [OFFICE-READING](OFFICE-READING.md)。
