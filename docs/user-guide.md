# 需求 Agent 使用说明

- 适用对象：产品经理、需求整理人员及需求内容评审者。
- 版本说明：Windows 1.2.5，2026-10-19 试用版。在既有 1.2.4 业务基线上加入笔记本需求表格布局调整；准确源码提交与文件哈希以随包构建清单为准。
- 日常入口：<http://127.0.0.1:8765/>。本文对应当前五步工作台。

**Windows 安装包用户请先阅读 [安装与模型配置说明](windows-installation.md)。** 从“需求 Agent”快捷方式启动，直接进入 `http://127.0.0.1:8765/`；运行环境已随包提供，无需设备许可证或激活。模型 API Key 由使用者自行配置。

客户版数据位于 `%LOCALAPPDATA%\RequirementsAgent\data`。退出时先保存输入，点击工作台左下角“退出工作台”并确认；只关闭浏览器标签页不会停止服务。可从本文第 2 节继续阅读业务操作。本文第 1、10、11 节的 `start-local.cmd`、Python 安装命令及仓库根目录 `data/` 说明适用于源码部署，不适用于客户安装包。企业加密或受保护的 Office 材料，需要客户本机已经获准使用的 Office 只读提取，具体支持情况以该企业环境的实际验证为准。

本工具帮助你将全新产品、独立模块或已有平台的改动诉求整理成可核对的需求底稿、MRD 和 PRD，并在人工确认后生成指定版本的研发交接包。模型可能理解错误或提出没有依据的建议，整理和审查结果都需要你核对，未知业务规则由你确认。文档生成、内容确认也不代表业务系统已开发或测试合格。

本说明随 2026-10-19 试用版提供。需求助手入口、草稿恢复和确认流程保留，AI 输出仍须人工核对。图文指南另随试用 ZIP 提供。

本文位于源码仓库的 `docs/`，也随 Windows 客户安装包提供。历史精简单机源码包包含 `web/dist` 和用于重建的 `web/src`，不包含 `docs/`、`tests/` 及完整工程验证脚本；它与现在包含运行环境的客户安装包不同。源码基线依据见仓库中的 [正式版本记录](version-control-20260926.md)。

## 1. 源码部署用户：开始和结束一次工作

1. 双击本工程根目录的 `start-local.cmd`。
2. 浏览器打开固定地址 `http://127.0.0.1:8765/`。重复启动会复用已有工作台。
3. 从左侧选择已有项目，或点击“＋ 新建需求项目”，填写名称后点击“创建项目”。
4. 按下文五步操作。中途离开前使用相应的保存按钮；看到“未保存”时，输入尚未成为已保存成果。
5. 结束后先等模型任务结束，保存输入，再在工程根目录的 PowerShell 中执行 `.\scripts\stop.ps1`。关闭浏览器本身不会停止后台服务。

日常工作台已取消访问令牌，打开后直接进入项目列表。`start-local.cmd` 和 `.\scripts\start.ps1 -OpenBrowser` 使用同一入口与根目录 `data/`。升级前已运行的旧服务需要正常重启后才能生效；连接失败时可点击“重新连接”。

本源码工作台自 2026-10-12 起，所有项目的新建、打开、切换、重开和刷新恢复，都先显示“和助手聊需求”。已有底稿、需求、文档和任务保留，可以再主动进入直接填写、完善需求和确认交付；仅打开项目不会调用模型。从其他项目的任务进度查看结果或重试时，先进入对应项目的助手，再点击“继续查看所选任务”或“核对并重试所选任务”。安装包是否包含此入口调整，以其随包构建版本为准。

首次安装、缺少运行环境或缺少前端文件时，先看第 10 节。

## 2. 模型设置、材料发送与费用

进入左侧底部“模型设置”，先核对“配置用途”、接收端、模型名称和密钥状态。

在“基础配置”填写 Base URL 和模型名称。输入 API Key 后，点击“保存配置与密钥到此电脑”；不输入新 Key 时，按钮为“保存接收端与模型”。若只临时使用 Key，先保存接收端，再输入 Key 并选择“仅临时使用此 Key”。有未保存的接收端修改时，临时 Key 和连接测试按钮不可用，避免发往尚未核对的接收端。

| 设置或动作 | 使用说明 |
| --- | --- |
| 主分析模型 | 用于整理材料、澄清、成文和语义审查。未配置密钥时仍可录入资料、人工整理和阅读已有内容。 |
| 图片视觉模型 | 用于待分析的截图及提取出的图片。主分析可用不代表图片模型已配置或支持视觉。 |
| 保存配置与密钥到此电脑 | 保存接收端、模型和用户输入的新 Key。Windows 使用当前用户的受保护存储，重启后可继续使用；不等于允许发送项目材料。 |
| 保存接收端与模型 | 不输入新 Key 时保存基本模型配置。 |
| 保存高级参数 | 在“高级参数与密钥来源”中保存单次输出能力、超时等设置。 |
| 本机 `.env` | 默认读取 `RA_DEEPSEEK_API_KEY`。只在本机编辑器中填写，修改后正常重启应用，无须重新安装。 |
| “仅临时使用此 Key” | 为已保存的接收端设置临时密钥，仅在当前服务进程有效，不写回 `.env`。 |
| “清除临时 Key” | 清除临时密钥；受保护存储或 `.env` 中的密钥仍可能生效，以当前来源为准。 |
| “移除此电脑保存的 Key” | 删除该接收端在当前 Windows 用户下保存的密钥，不删除 `.env` 中的配置。 |
| “测试连接（调用模型）” | 显式调用接收端，可能计费，不发送项目材料；成功只证明本次接口连接成功。 |
| “测试视觉能力（合成图片）” | 使用合成图片检查视觉接口，可能计费，不能代替对实际图片识别结果的核对。 |

不要把真实 Key 发到聊天、截图、文档或 Git。`.env` 是本机明文文件，不是加密保险箱。模型 API Key 仍在模型设置中配置。

每次发起分析、更新理解、生成文档或审查时，工作台先显示“核对本次任务”弹窗。检查以下内容后再点击“授权本次范围并运行”或“运行本次任务”：

1. 接收端地址及模型是否是你允许使用的服务。
2. 材料列表、当前底稿、问题、讨论记录和本次新增输入是否允许发送。
3. 本次执行步骤是否符合你的意图；新任务不设置累计请求次数上限，模型服务可能持续产生费用。
4. 是否存在缺密钥、图片能力未配置、前序核对未完成等提示。

新增材料或新增回答可能使原有授权不足，需要重新核对发送范围。排除材料不会抹除它此前已经形成的底稿或讨论内容；授权前也要检查已有讨论中的敏感信息。

普通启动、保存输入、切换文档、人工核对和运行诊断不会自动调用模型。费用显示“未知”不代表免费。任务详情可查看已执行请求数。

DeepSeek 语义审查默认启用思考模式，其开关与其它结构化阶段分开；可能更慢、消耗更多 token。新任务不设累计请求数、费用或字符预算，旧预算设置不再生效。保留单次模型容量、单请求超时和有限错误重试。输出截断时可按已知模型能力提高单次上限重试；仍不完整则拒绝采纳。

运行中可点击“停止后续步骤”；已发出的请求仍可能计费。重启不会自动重放未完成任务，也不要通过连续重复点击来判断是否卡住。

发送助手消息或发起 AI 任务后，“AI 任务进度”面板会自动展开，显示实际步骤、当前状态和已用时间。点击“收起进度”可继续查看资料；切换项目后，已启动任务的状态仍保持可见，点击“展开”可重新查看。时间不是完成百分比，长时间停留在同一步也不代表已经失败。

“一键 AI 填充需求草稿”完成后，仍在第一步的页面会自动进入草稿核对；如果你已切换项目或步骤，可通过进度中的“查看结果并核对”返回对应结果。已有未保存输入时，先处理保存提示。其他任务按其结果入口核对，生成内容仍需人工采纳或确认。

新任务失败时，面板显示失败原因和“核对后重试”；重试先核对原任务范围，再由你运行。状态读取失败时保留上次进度，使用“刷新任务状态”核对，避免重复发起。打开旧项目不会自动弹出历史失败任务。

## 3. 添加资料，先检查是否真正读到内容

任一步都可通过页头“项目资料”进入材料区；第一步也有“添加资料”。材料按“目标与诉求”“现状资料”“设计参考”“文档模板”分别显示；材料用途由你选择，可在“分类与读取操作”中调整。修改分类不会自动修改已采纳的业务条款。

| 材料入口 | 操作 |
| --- | --- |
| 粘贴文字 | 展开“粘贴文字或添加公开网页（辅助方式）”，将原文放入“粘贴材料”，点击“保存文字材料”。 |
| 本机文件 | 点击“选择文件”；当前不支持拖拽。支持 TXT、MD、DOCX/DOC、XLSX/XLS、PPTX/PPT、PDF、PNG、JPG/JPEG、WEBP，单个文件上限 12 MiB。上传时显示进度，上传完成后单独显示服务器读取状态。 |
| 墨刀截图 | 将有权使用的墨刀页面截图保存为 PNG/JPG，点击“导入墨刀原型截图”。此入口默认归入“设计参考”；可查看截图原图，识别内容仍需视觉模型与发送授权。 |
| 公开网页 | 展开辅助方式，输入公开 HTTP(S) 地址，必要时勾选“需要动态页面渲染”，点击“确认有权读取并添加”。只读取公开网页，不使用浏览器中的登录状态。 |

网址无法读取时，可检查地址或改用有权提供的导出文件、截图；需要登录的页面或内网地址不能靠公开 URL 入口读取。

上传成功只说明材料已添加。点击材料卡片的“查看内容”或第一步中的附件卡片，预览提取文字。正文连续排版，不显示段落编号；文档图片在“文档内图片”中切换查看，来源信息在底部折叠栏。点击需求中的“查看来源”仍会定位并高亮对应原文。长材料通过“继续显示内容”分批展开，不自动省略为已读。预览不是 Office 原始排版；需要核对原件时点击“下载原始附件”，使用本机获授权的程序打开。文件名、缩略图或空片段不能证明已理解。

| 页面状态 | 如何处理 |
| --- | --- |
| 已添加 / 读取中 | 等待读取完成；本机 Office 处理可能较慢，若超时则按页面提示处理，不反复提交同一材料。 |
| 已读取 | 已取得可解析内容，仍需查看来源片段并与原件核对。 |
| 部分读取 | 查看限制说明；图片、图表或其它对象可能未取得，不要将缺失部分视为已理解。 |
| 待视觉分析 | 图片还没有形成视觉观察；需配置支持视觉的模型并授权发送，或排除图片后先处理文字。 |
| 需要本机 Office 处理 | 请维护者检查本机 Office 和读取条件，再尝试重新读取。 |
| 权限受限 | 先核实你和本机 Office 对原件的合法访问权限，不修改保护设置来绕过限制。 |
| 读取失败 | 查看具体原因；“当前读取方式无法解析”不等于文件损坏，可使用“重新读取（保留原件）”。 |

Word、Excel、PowerPoint 优先普通解析；旧格式或普通解析失败时会尝试本机 Microsoft Office 只读提取。此过程不保存或改写原件。本机 Office 能打开文件，不代表所有文字、图片和页面布局已被程序取得，也不代表获准向模型发送。

内嵌图片在所属文档的内容预览中显示，保留提取、已分析和待分析状态。像素已提取不等于图片内容已分析；父材料的分类、排除或恢复也会同步到其内嵌图片。设计参考不会自动成为本期业务规则。

使用“排除材料”将不适用材料移出后续使用范围；需要恢复时点击“恢复使用”。保留原件和原始读取状态，避免以重新命名、重复上传掩盖失败原因。

## 4. 第一步：提供现状与诉求

**入口：** 项目顶部“聊清需求想法”。

1. 在“你的想法”写已知诉求、问题和目标，点击“发送”与助手交流；不知道的内容可以保持未知。
2. 按需添加资料，核对读取结果。聊天原话会保存为来源，无须为了开始而伪造附件。
3. 已有足够信息时点击“一键 AI 填充需求草稿”，核对本次任务的材料、接收端和模型后运行。
4. 已经有明确需求、希望自己填写时，点击页首“跳过对话，直接填写需求”，立即进入第二步。新项目也可以直接点击顶部第二步。无需先聊天、上传资料或调用 AI；在第二步填写并“保存需求输入”，再核对范围和采纳条目。已有聊天草稿会带入空白需求框；本页已有内容时会并列保留，只有点击“补充到本次需求”才合入。

**预期结果：** 本页发起的 AI 整理完成且产生结果后，自动进入第二步审核。第二步发起的填充则留在第二步供人工修改和确认。

**第一步对话可选：** AI 整理路径在产生结果后进入第二步；直接填写路径可以立即进入第二步，在本页完成必要输入和核对。跳过对话不会自动完成核对、创建候选或采纳条目。失败会显示原因并保留输入，不会把失败任务当作完成。已有结果可通过“查看已有草稿”进入第二步。

从第二步进入第三步及后续步骤时，按已保存的前置核对状态解锁，锁旁标明“先完成第几步”。已保存的前置内容后来变化而失效时，不能用“跳过对话”绕过重新核对：旧标签页会显示锁定原因和返回入口，后续编辑区暂不可用，已有草稿继续保留。返回前一步不会强制丢弃被锁页的草稿；关闭或刷新整个浏览器前仍需妥善保存。

### 根据参考产品或网址对标

在第一步展开“对标参考产品”，填写对标对象及希望参考的页面、流程或问题。点击“＋ 添加参考资料”上传文件、截图或粘贴文字，核对读取状态后勾选资料。也可填写公开网址、确认有权读取并点击“读取参考网址”；聊天中的网址只提供填入按钮，不代表已经读取。

点击“对标并填充需求草稿 →”，核对任务弹窗中的参考对象、资料、其它项目上下文及接收模型，再授权运行。未输入新的聊天内容时会保存明确的对标对象和范围；已有聊天原话及人工字段继续保留。图片需配置视觉模型，观察不清的内容不能作为对标依据；旧图片缺少可核对的读取身份时，先在资料区重新读取。

整理产生结果后自动进入第二步，查看对标分析及其原文、来源和关联候选。竞品做法仅形成待审核建议，差异未知时留空；人工修改或采纳后再确认进入下一步。公开网页入口读取单页，不遍历整个站点，也不读取登录后的页面。读取失败时可改用有权提供的文件或截图，不会自动反复抓取。对标范围、网址与选择可保存在本浏览器草稿中；读取网页的确认每次恢复后需重新勾选。

网址返回 403 或没有读到正文时，失败资料不可勾选，页面提供“去粘贴网页正文或添加其他资料”：点击后直接展开并聚焦文字输入，预填原网址与待核对标题。粘贴你实际看到的内容并保存，新材料会标明人工粘贴的出处。已有未保存文字会保留，先保存后再填写新的网页正文。也可点击“使用已选资料继续（移除本次网址）”，然后发起对标；失败网址不会继续挡住已选可读资料。

模型输出格式有误时，系统在原任务内进行有限修复并保留原始回复。修复不能改变原有结论、引文或有效关联；无法证明内容完整时会保留失败记录，供核对后重新生成。新任务使用默认请求设置，单次试跑设为 1 次会阻止后续模型修复。

## 5. 第二步：核对现状、价值与改动范围

**入口：** 顶部第二步。

1. 选择“需求场景”。全新产品、确认与已有功能无关联的独立模块，不强制填写现状和保持项；有关联的新增模块、已有功能修改仍需核对这些影响。优先级、改动价值和暂不涉及的内容按需补充。
2. 填写已知信息，或点击“一键 AI 填充”。按钮先保存人工编辑，再沿用任务范围核对弹窗；实际运行可能计费。AI 只为缺项生成待审核建议，已填写的人工文字会保留，冲突建议单独展示。
3. 阅读草稿，有偏差时点“编辑”。字段可标为“待确认”，适用时可选择“不适用”或“已确认没有额外约束”；这些选择保留原文记录，未知不能冒充没有。点击缺项提示可定位待处理字段。
4. 按“保存本期范围 → 临时选择待采纳项 → 核对后采纳”处理。展开“本期范围”，用“纳入本期 / 移出本期”调整范围，再点击“保存本期范围”；范围或背景尚未保存时，下方采纳控件会说明原因，并提供返回保存的入口。范围保存后会保留，折叠区域可随时展开调整。
5. 在下方勾选本次要处理的候选，点击“批量核对并采纳”。勾选仅用于本次操作，离开页面、切换项目、取消核对或采纳成功后会清空；已保存范围和已采纳状态继续保留，已采纳条目不再用勾选表示。在弹窗中逐项核对需求、七个行为字段及来源原文，勾选确认后“一键采纳”。内容不对可“返回修改此条”；任一条受阻时整批不采纳。修订候选仍需单独对照原条款；暂缓或不采纳的条目需先改回候选才可批量选择。勾选不会自动采纳或填写空白行为字段。逐条“采纳此条”不可选时，可点“去核对此条行为”，对照来源核对并保存。
6. 本期范围内的需求均已采纳、当前阻塞问题已处理后，点击“确认并进入下一步”。未解决的待办会显示数量和定位入口；还有本次勾选未处理时，需先批量核对或清空选择。工作台会保存本页编辑、核对最新版本，并在成功后自动进入第三步。只想暂存可使用“保存范围草稿”。

影响本期范围的问题直接显示在第二步，点击阻塞清单中的“回答问题”即可就地填写并保存。未知备注不会解除阻塞；确实不在本期时可展开“本期范围决定”填写排除理由。本期仍依赖的规则不能用排除理由绕过。业务行为细节、验收条件和回答落实到条款的核对，在第三步继续处理。

若提示“AI 修复输出格式时同时改写了需求文本”，说明本次生成被保真校验拒绝，并非需要补勾某个选项。现有需求和已保存资料仍在，可以继续核对已有草稿；技术字段路径在“查看本次失败详情”中。重新生成需核对任务范围，不会自动重试。

**预期结果：** 本期范围有稳定需求编号，核心目标、使用者和本次改动明确；不适用内容有明确状态，AI 建议经过人工核对。

**进入下一步前：** 空需求列表、未选择本期范围、范围内尚未采纳、无法确定的改动性质或当前阶段阻塞问题仍需处理。保存失败、版本变化或缺项会留在当前页显示原因，并保留本次输入。

“按需比较方案方向”是可选工具，在本页范围核对完成后可用。“探索可选方案”会调用模型；“按此方向继续讨论”仅记录方向。只有“采纳指定条目”并核对勾选内容后才采纳对应条目，两者都不等于正式确认。

## 6. 第三步：澄清流程与规则

**入口：** 顶部第三步。问题按需求分组，建议与答案分开展示。

每个阶段的阻塞清单按需求或问题名称分组显示，右侧按钮直达对应位置。可点击“从第一项开始处理”，或挑选一项；处理后用“返回阻塞清单”继续。页面底部的“查看阻塞清单与处理入口”会回到同一清单，不再需要根据随机编号手工查找。

| 提示 | 操作位置 |
| --- | --- |
| 业务行为缺字段或模型行为待核对 | “补全业务行为 / 核对业务行为”自动展开该需求，并聚焦缺失字段；核对来源后保存。 |
| 缺已采纳的关联验收 | 已有本期候选时“核对关联验收候选”定位相关候选；没有候选时“补充关联验收条件”打开窗口并预选对应需求，保存为候选后仍需人工采纳。 |
| 已保存回答仍待落实 | “核对已保存回答”直接打开当前回答的人工核对弹窗。 |
| 问题待回答、范围或上下文缺项 | “回答问题 / 核对本期范围 / 核对相应字段”打开实际问题、范围设置或字段编辑器。 |
| 文档或交接受阻 | 定位实际 MRD、PRD 的生成、更新、阅读、人工核对控件，或当前审查意见；前序未核对时先显示前序步骤入口。 |

上述入口只定位或打开编辑器，不自动填写、采纳、正式确认或发起模型请求；切换位置仍会保护未保存输入。保存后程序按实际条款重新计算剩余缺项，只有原有放行条件满足才进入下一阶段。

1. 阅读问题及提问原因，在“你的回答”中写实际业务决定，再点击“保存本次回答”。“填入建议”只是填入编辑框，仍要核对并保存。
2. 暂时不知道时点击“暂不确定，保留未知”；问题仍未解决，相关阻塞不会自动解除。
3. 展开“核对条目与业务行为，或根据回答更新理解”。需要将回答整理为修订时，点击“根据已保存回答更新理解”，核对范围后运行模型任务。
4. 在“待采纳候选”中展开详情，核对行为、关联和来源；修订候选还需对照原条款及变化，新增候选没有原条款对比。确定正确后“采纳”；不接受则暂缓。修订候选采纳后保留原需求编号。
5. 展开“核对业务行为、验收与需求关系”，逐条填写或修正“谁操作、入口及前置条件、主要流程、业务数据、权限约束、操作结果、边界和异常”，点击“保存此需求行为”。确实不适用的维度应说明业务原因。

已保存的回答若仍提示“待核对关联需求”，点击其旁的“人工核对回答与当前条款”。弹窗列出原问题、回答、关联条款及来源，并逐条说明不能记录的原因：

- 内容已正确但尚未采纳的本期原条款，可点击该条旁的“采纳此条款”；程序会重新载入最新核对内容，仍需再次人工确认。
- 原条款尚未表达回答时，点击“定位并修改此条款”，保存修改后用“返回原回答核对”返回。需求的业务行为待核对时有专门定位入口。修订候选仍需单独核对采纳。
- 全部关联条款可核对后，勾选内容确认，再点击“记录回答落实”。采纳条款和记录回答落实是两个独立操作；未保存的输入继续受离开提示保护。

弹窗标题、关闭与底部操作保持可见，正文单独滚动。“重新载入核对”会清除旧确认；版本变化或重新读取失败时，须载入最新内容再确认，不能重复使用旧勾选提交。

### 保存回答与采纳的区别

| 动作 | 得到什么 | 还要做什么 |
| --- | --- | --- |
| 保存本次回答 | 留下你的回答和来源依据 | 核对关联需求是否需要修订 |
| 根据已保存回答更新理解 | 形成待审的理解或修订候选 | 查看差异，逐条决定是否采纳 |
| 采纳候选 | 将该候选纳入当前底稿，或修订对应原条目 | 检查本期范围、行为、验收及后续文档是否需重新核对 |
| 记录回答落实 | 留下人工核对当前关联条款承载回答的记录 | 继续处理其余缺项；不代表正式业务批准 |
| 核对规则并继续 | 记录当前规则阶段的人工核对 | 继续生成和评审文档，不代表正式业务批准 |

### 人工补充验收条件

若本期需求缺少验收，不必只等待模型补齐：

1. 点击“＋ 补充关联验收条件”，选择实际关联的本期需求。
2. 填写验收名称和原文，写明可观察的操作、条件与预期结果。没有业务依据的数值、权限和异常规则继续澄清。
3. 点击“保存验收候选”。此时只形成候选，没有自动采纳。
4. 返回并展开上方“核对条目与业务行为，或根据回答更新理解”，在其中的“待采纳候选”核对内容、关联和来源后点击“采纳”。

“本期以外的未决事项及范围决定”用于记录确实移出本期的问题及理由；问题仍保持未知。本期需求仍依赖的规则不能通过填写移出理由来跳过。

**预期结果：** 本期需求均已明确采纳，行为说明可核对，并有已采纳的关联验收条件。

**进入下一步前：** 所有影响当前范围的阻塞问题、待核对修订及缺失维度已处理，再点击“核对规则并继续”。不要求把范围外未知伪装成已有答案。

## 7. 第四步：评审 MRD 与 PRD

**入口：** 顶部第四步“评审 MRD 与 PRD”。当前工作台没有独立的草图核对步骤，不需要寻找旧六步流程中的草图按钮。

1. 选择“PRD 评审稿”或“MRD 评审稿”，点击对应“生成讨论稿”；已有文档时按钮为“更新讨论稿”。两份文档分别生成，均属于模型任务。
2. 在任务弹窗核对范围与接收端，运行后检查实际结果。部分完成或有限制时阅读说明，不能只凭正文出现就判定可交付。
3. 使用文档目录逐章阅读。MRD 重点看现状、价值和范围；PRD 重点看需求、流程规则、数据权限、异常和验收，两份都要与本期底稿及来源一致。
4. 发现业务含义有误，回到第二、三步修改并采纳正确内容，然后更新文档；章节中的 AI 帮助只形成待核对建议，不能代替业务决定。
5. 核对当前文档后点击“我已核对这份 PRD”或“我已核对这份 MRD”。两份必须分别核对。
6. 展开“两份文档的版本与核对状态”，确认均对应当前底稿；条件满足后点击“完成文档评审并进入交接”。

“历史版本与章节参考设置”可切换历史文档，只读查看不会调用模型，也不会将旧文档变为当前版本。章节参考默认使用已配置的用户原 Word 参考；确需回退时才明确选择“明确改用内置参考（原件不可用时）”，再生成文档。上传一份材料并选择“模板”，不等于自动替换本功能配置的章节参考。

**预期结果：** 两份当前版本的文档已保存并分别经你核对；侧栏如仍显示“未检查”，说明尚未执行模型内容审查。

正文及导出文件仅呈现产品内容：目标、使用者、范围、需求、规则、验收与尚未决定的产品事项。内部提问回答过程、模型分析提示、未采纳候选和来源审计不混入 MRD/PRD 正文；这些记录仍保存在项目中。已采纳条款保留稳定编号与版本，已知业务原文不因清理讨论信息而删除。

**下载评审稿：** 文档可下载时显示“DOCX 下载”“MD 下载”“ZIP 下载”。所有尚未明确移出本期的未回答问题都需处理，不仅是标为阻塞的问题；回答已保存但还未完整纳入关联产品条款时也需先核对采纳。过期或历史文档不提供当前稿下载入口。下载评审稿不等于建立正式确认基线。交接包中的溯源文件独立于 MRD/PRD 正文保留。

**进入下一步前：** 当前 MRD、PRD 均有效且人工核对完成。真实模型内容审查与人工文档核对是不同动作，仍须完成第五步中的“审查当前版本”。

## 8. 第五步：确认与交接

**入口：** 顶部第五步“确认与交接”。

1. 核对“本期范围、规则与验收”和“当前确认对象”，确认需求、MRD、PRD 都是要交接的版本。
2. 点击“审查当前版本”，核对接收端、材料范围后运行真实模型审查。审查有问题时，按“重要待定与门禁问题”中的“前往核对”返回处理。
3. 若修改了需求或文档，按提示重新完成相关核对，并重新审查当前版本；历史审查不能替代本次审查。
4. 程序条件满足后，再人工核对业务意图与交付范围，点击“确认此版本的需求与文档”。
5. 在“再次核对本期范围与重要未知”弹窗中逐条复核，点击“提交服务端确认”。如版本已变化，返回核对当前内容后再确认。
6. 在“已确认基线与交接”找到该次基线，点击“生成此基线的研发交接包”，随后点击“下载交接包”。

**预期结果：** 出现不可变的确认基线和对应交接包入口。交接时同时说明基线编号，避免把历史包当成当前版本。

确认是需求内容确认，不代替技术设计评审、开发完成或测试验收。模型审查也不能替真人作最终业务批准；合成练习中的点击更不能代表真实项目批准。

后续修改会形成新草稿，原确认基线保留。页头若显示“有历史确认基线，当前草稿须重新核对”，应完成新一轮相关核对后再建立新基线。

## 9. 最小练习：仅使用合成资料

以下是虚构练习，用于认识按钮和流程；不是实际项目材料，也不是系统默认业务规则。模型可能提出不同问题，不以生成次数或条目数量作为练习完成标准。

创建项目“合成练习：工单列表状态筛选”，在第一步填写：

> 现有平台 / 页面：虚构的工单管理平台，已有工单列表。
>
> 本次诉求：让已有列表访问权限的客服按工单状态筛选当前有权查看的工单。练习设定只有“待处理”“已完成”两种状态；每次选择一个状态或“全部”，选择后更新列表；默认“全部”。价值是减少客服逐条查找，练习优先级为中，依据是每班均需分类查看。
>
> 保持不变 / 暂不涉及：沿用原有列表访问权限和数据可见范围；不修改工单状态、不新增权限、不导出。
>
> 练习补充：无匹配结果时显示空列表及“无匹配工单”；读取失败时保留筛选值并提示重试；取消筛选恢复有权查看的全部工单。性能指标未决定，保留待确认。

按以下顺序练习：

1. 先“保存草稿”，再分析。模型操作仍需真实可用的接收端、你的发送授权，且可能计费。
2. 第二步逐项核对合成设定；选中筛选需求并独立采纳。若模型增加批量操作等未提供内容，不应直接采纳。
3. 第三步逐条回答。练习原文没有提供的信息保持未知；若它影响本期交付，就先作明确的练习业务决定并保存，不能只为继续流程随便填值。
4. 人工补充并采纳一条验收：“有列表访问权限的客服选择‘已完成’后，列表仅显示其有权查看且状态为‘已完成’的工单；选择‘全部’后恢复其有权查看的全部工单。”其它真实存在的验收缺口仍按提示处理。
5. 生成并人工核对 MRD、PRD，执行当前版本审查，处理发现项后再练习确认和下载。

**观察重点：** 保存不等于采纳，建议不等于答案，下载不等于确认；最终包应绑定练习项目的指定基线。练习可在任何未知点停下，不要求强行走到最后一步。

## 10. 首次安装与维护者操作

首次使用需要本机 Python 3.11+、Node.js 22.12+（或 20.19 及以上的 20.x）及 npm；Node.js 要求来自当前锁定的前端依赖。单机包不包含这些运行时或模型密钥。安装会下载依赖和浏览器组件，需要相应网络访问条件。

在工程根目录打开 PowerShell，确认没有正在运行的工作台。已有项目先按第 11 节备份并正常停服，再安装：

```powershell
# 仅当本机策略允许时，为当前 PowerShell 窗口允许脚本执行
Set-ExecutionPolicy -Scope Process Bypass
# 保留已有配置；仅在文件不存在时创建空的密钥项
if (-not (Test-Path -LiteralPath .env)) { 'RA_DEEPSEEK_API_KEY=' | Set-Content -LiteralPath .env -Encoding utf8 }
notepad .env
# 在本机编辑器中填写密钥并保存，不要发送或提交真实 Key
.\scripts\install.ps1
```

安装成功后双击 `start-local.cmd`。脚本仅在缺少虚拟环境 Python 时自动尝试安装；已有环境但前端文件缺失时，应由维护者重新运行安装脚本，不能认为每次双击都会修复所有安装问题。

安装脚本会检查 8765 端口及活动任务，在隔离目录构建前端后才更新正式文件。提示工作台仍运行时，先正常停服；不要绕过检查或改用另一个端口。

## 11. 数据备份与安全更新

项目数据位于根目录 `data/`，包含数据库、来源原件及导出等成果。Git 受控源码不等于项目数据已备份；`.env`、数据、模型原始证据和本机备份不应提交 Git。

先保存所有输入、等待任务结束，并在备份期间停止编辑项目，再执行：

```powershell
.\.venv\Scripts\python.exe .\scripts\backup.py
```

脚本输出备份目录，默认位于 `data/backups/时间戳`。备份包含数据库、来源原件、导出包及模型调用证据，生成校验清单；存在活动任务或复制期间数据变化时会拒绝生成有效备份。备份不包含 `.env`，凭据应单独保管。

再次校验时，将下面路径替换为脚本实际输出的备份目录：

```powershell
.\.venv\Scripts\python.exe .\scripts\backup.py --verify "实际备份目录"
```

`--verify` 只校验，不恢复。备份可能包含原始业务材料和模型调用内容，应按原资料的权限要求保管。

更新顺序：保存输入和等待任务结束 → 备份并校验 → `.\scripts\stop.ps1` → 更新同一工程的正式版本 → 若涉及前端或依赖变更，运行 `.\scripts\install.ps1` → 双击原 `start-local.cmd` → 重新加载浏览器并核对项目与版本。后端没有自动热更新，仅更新磁盘文件不代表正在运行的服务已换版。纯说明文档更新无需安装或重启。

恢复由维护者处理：先停服并校验备份，在隔离目录核对数据库和文件；保留原 `data/` 供回滚，再恢复数据库、来源、导出和证据目录。代码、前端资源与数据应成套核对；不要将两个同 ID 项目的不同快照直接覆盖合并。

## 12. 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 双击后没有打开可用页面 | 在本工程根目录运行 `.\scripts\diagnose.ps1`，按提示检查环境和服务。诊断不自动调用模型；向维护者提供脱敏错误信息即可。 |
| 8765 被占用 | 让维护者核实占用者与工程路径；脚本不会自动换端口或结束未知进程，不要从历史包再开工作台。 |
| 仍显示旧的令牌登录页 | 当前源码工作台已取消访问令牌；保存输入后正常重启同一服务，再刷新页面。 |
| 资料已上传却无法继续分析 | 展开来源片段和读取限制，确认可读内容、密钥、图片能力及发送范围；上传和理解是两个状态。 |
| 回答都保存了，第三步仍不能继续 | 查看页面上方“当前阶段阻塞清单”，按需求或问题点击处理按钮。按钮会定位业务行为字段、验收候选或对应回答核对窗口；处理并保存后可返回清单继续。 |
| 文档没有下载按钮 | 先确定选中当前文档；处理未澄清事项，更新过期讨论稿。历史版本只读，不能当当前稿下载。 |
| 已核对两份文档，仍不能确认 | 查看第五步门禁：可能还缺当前版本语义审查，或审查存在阻塞项、必要决定及覆盖不足。 |
| 模型返回格式错误、空输出或请求超时 | 查看失败详情与已执行请求数。已有输入保留；核对接收端与失败原因后显式重试，不修改业务规则去适应错误输出。 |
| 历史模型任务显示预算暂停 | 历史失败记录保留。更新页面后重新核对并发起新任务，新执行不再受旧人为预算限制；不会自动重放历史请求。 |
| 操作等待较长 | AI 任务查看“AI 任务进度”，可收起、展开或停止后续步骤；普通保存、上传等查看“操作反馈”。不重复点击。连接测试最多等待 60 秒；正式分析仍按模型配置及任务进度运行。 |
| 连接中断或等待响应超时 | 页面会区分失败与处理结果未知。写入请求可能已被服务器处理，应先刷新核对；未保存输入保留后再决定是否重试。 |
| 显示已保存／已确认，但页面刷新失败 | 写入已经成功，不要重复提交。按提示重试刷新，核对最新内容或基线。 |
| 出现“版本已变化”或编辑冲突 | 保留输入，比较旧值、最新值和自己的修改，重新核对后再保存或确认；不要直接覆盖他人的最新修改。 |
| 准备刷新或关闭页面 | 先保存草稿。未保存输入只存在当前浏览器会话；“保存后离开”失败时留在页面处理，不依赖刷新找回。 |
| 显示前后端不兼容 | 保存输入，由维护者核对更新和重启状态，再重新加载标签页；不要忽略提示后重复提交任务。 |
| 停止服务被拒绝 | 等待活动任务结束；无法确认任务状态时先诊断。强制停止只适用于明确接受中断的维护操作，已发请求仍可能计费。 |

需要排查时，记录项目名称、发生在哪一步、所按按钮、页面错误及任务编号；截图前遮挡密钥和敏感材料。更多安装和工程说明见 [README](../README.md)，Office 读取限制见 [OFFICE-READING](OFFICE-READING.md)。


## 1.2.5 笔记本需求表格

在较矮的笔记本窗口中，完善需求页面会压紧标题、流程导航和工具栏，将更多高度留给需求确认表；编辑字号保持不变。保存和恢复草稿的提示显示在表格底部，靠近“保存草稿”按钮。

1. 在“完善需求 → 需求列表”核对内容，用“定位需求”直接跳到目标；有待落实回答时，可用“上一项待落实”“下一项待落实”逐项检查。
2. 希望看到更多内容时，点“专注核对”；点“退出专注核对”返回，当前输入会保留。
3. 暂停前点“保存草稿”。草稿保存在当前浏览器，不等于正式确认；刷新后先回到需求助手，再主动打开完善需求以恢复草稿。请使用同一浏览器，不清理其站点数据。
4. 旧版升级前先保存、结束任务并正常退出工作台；升级后先核对项目与草稿。窗口中已加载的旧页面需保存后再刷新。
