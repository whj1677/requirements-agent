# 云平台 PRD：交互逻辑与业务流程必备内容

2026-10-13，用户明确要求：云平台项目的 PRD 必须增加交互逻辑和业务流程说明。

## 文档中怎样呈现

在“功能需求、业务规则、验收条件”之外，云平台 PRD 单独呈现两部分，并分别引用每项本期需求的已核对依据：

- **交互逻辑：** 入口及前置条件、操作者的操作步骤、输入与校验、权限、页面或操作反馈，以及资料已明确的取消和失败处理。
- **业务流程说明：** 触发条件、参与角色、业务处理顺序、对象与状态或数据变化、结束结果和异常分支。涉及储能调控时，分别说明接口接收、回执、现场执行和实际效果，不能合并为一个“成功”。

这两部分可以解释已选需求的行为字段和相关规则之间的关系。当前项目资料、已保存并采纳的需求和人工决定是依据；通用储能背景不能替代当前业务决定。后台、接口或纯数据任务按其实际触发和反馈说明交互，不因此增加页面。

## 缺少依据时怎样处理

已知部分正常写入；具体未知内容用“【资料待确认】”注明缺项和影响，交付检查保留该缺口。不得补造状态、权限、阈值或失败行为；确实不适用时须根据当前资料说明理由。章节名称、引用齐全不能证明业务内容已经完整，独立文档审查和产品经理审核继续有效。

新一轮成文的可信契约、模型响应 schema 和程序组装会共同要求两节，且每节都覆盖本期需求。正文中的已选需求、规则与验收原文保留原身份；这两节的解释单独排版，不会移到最后一条功能下面。已有文档不改写；云平台文档缺少必备内容时，交付检查会提示重新成文和核对。

明确是其它产品的项目以及 MRD 沿用原来的文档内容规则。产品上下文的产品名称优先于历史项目标题，不因旧标题含“云平台”就强制套用。
