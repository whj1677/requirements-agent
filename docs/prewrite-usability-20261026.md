# 成文确认按钮与使用体验修复（2026-10-26）

## 从当前草稿实际复现

BMS revision 50 的整批草稿有 2 个本地必填校验项：PC 端与总控屏的“当前硬件厂家”定义为枚举，却缺少可选值。原界面隐藏了字段，只在底部显示数量，并禁用确认按钮。此前从“重新 AI 起草”开始的测试覆盖不到“直接确认这份已有草稿”的卡点。

继续实际操作还发现服务端把“待核对”这一真实状态名称误当作未决定属性；客户端填好两项后仍无法保存。现在仅在状态被明确进入、明确离开、触发与条件已给出时识别该命名状态；显式 unknown 依据、未定义的状态及占位说明仍阻塞。

## 修改

- 确认按钮可点击校验，只有任务运行、正在保存或版本尚未加载等操作性原因会禁用。未通过校验不会提交，也不会触发模型。
- 缺项在同一表格区域显示自然业务名称和可直接编辑的控件；两项并排可见，保留全部已有内容，填完仍用原统一确认按钮保存。不再展示技术字段路径来让用户找位置。
- 输入多选值时保留输入过程中的逗号、换行和未完成文本；校验项在本次编辑期间保持显示，避免输入第一个字后控件消失。
- 默认用真实功能标题代替引用编号，含技术引用的长文本先展示可读版本，修改入口保留原文。显示转换不更改保存的业务内容、来源或稳定身份。默认收起未改动的验收条件。
- AI 起草协议要求枚举提供非空选项；预写草稿若缺该内容不再声明 complete=true，但保留有效候选和逐字段诊断。补齐任务带上当前表内的确切缺项。

## 验证口径

以当前 BMS revision 50 本机隔离副本、不重新起草为起点，使用真实浏览器控件点通：原表滚到底部 → 点击确认 → 两个缺项原地显示 → 逐字输入与逗号/换行分隔 → 一次统一保存成功 → 取消复检后继续 → 一次整批复检。确认之前零项目写入、零模型请求；确认后原有回答与文档保留。厂家名称使用明确的合成甲/乙/丙测试值，只存在于隔离副本，不属于正式资料、不会回写日常项目。复检回包使用离线冻结响应，未声称真实模型业务验收通过。

三个笔记本视口（1366×768、1280×720、1093×614）检查按钮可见、无遮挡且实际可点，默认可见表格没有 REQ/AC/Q/SRC/EX 等技术编号。合成整表推荐与人工修改保留流程也通过。
