# 完善需求的笔记本布局优化

优化前代码已本地归档为 `c0a9b76`。本次只调整完善需求页面的布局、定位和展开方式，保留整表保存、原文核对和显式确认的业务逻辑。

- 有效高度不超过 900px 时压缩导航与周边留白，操作按钮合并到标题区域。正文仍为原有 14px，不靠缩小输入文字增加空间。
- 待补充验收的数量保持可见，长说明按需展开。详细定义的字段、交互、流程与状态分组默认折叠，摘要显示条目数及待补充数；校验定位仍自动展开并聚焦。
- “定位需求”可以直接跳到指定需求的输入位置。
- “专注核对”临时收起项目侧栏、顶部项目栏与阶段导航；编辑表格保持挂载，退出后恢复原布局。
- 回答原文核对中的摘要随正文滚动，避免粘性摘要遮挡表头或输入。底部保存和确认按钮保留。

## 复杂需求体验后的补查

使用原真实试跑的“多站点告警批量派单”在当前工作台复核，并在隔离合成场景中验证修改与校验行为，修复三处问题：

- 定位下拉框保留上次选中值时，再次选择同一需求不会触发浏览器的 change 事件。现在定位后恢复“选择需求…”占位，可再次选择；回归使用原生键盘操作，不用会主动派发 change 的 `select_option` 冒充复现。
- 前端必填校验产生的旧错误，在填写完成后仍混入详细定义的错误列表。现在前端错误随当前草稿重新核对，红框、错误文字与分组数量同步消失；后端返回的业务问题仍保留，等待重新核对。
- 1093×614 视口下，三个标题区按钮原来纵向堆叠，实际复杂需求编辑区只有 110px。调整布局断点后，此宽度横向排列按钮。五视口隔离回归中，该尺寸普通模式为 211px、专注模式为 360px；实际页面高度还受任务提示、草稿恢复提示等内容影响。

旧构建先复现前两项失败，新构建的笔记本专项 7 项检查通过；原完善需求 14 项、详细定义 7 项浏览器检查以及导航/返回交付 9 项回归通过，TypeScript 与 Vite 构建通过。五种视口覆盖 1920×1080、1536×864、1280×720、1280×640、1093×614。0 次模型调用，隔离浏览器测试无日常数据访问、无额外监听服务。

更新现有 8765 工作台后，已用真实复杂需求和键盘复验重复定位，恢复 1280×720 专注预览。发布静态文件与验证构建字节一致，日常数据库各表内容哈希未变。补查证据为 `evidence/refinement-laptop-20261013/followup-before/`、`followup-after/`、`followup-usability/` 及 `work/refinement-laptop-20261013/followup-detail/`。
