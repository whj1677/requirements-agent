## 比较方法

同一合成告警协作场景按分轮原话执行：初始口径、已答规则、明确生效替代、保留真实冲突、明确回答冲突、正常完善和成文。前后由同一初始 seed 克隆，项目和来源身份相同。T1–T3 使用同版源码、同参数、300 秒单请求上限；之后的共同修复、额外纠错反馈及正常重试来源增量按实际阶段记录。

两个真实请求在 300 秒单请求上限超时后，两臂仅通过隔离工厂的正常模型设置 PUT，共同改为 600 秒等待；canonical 与日常工作台设置仍为原 300 秒。新阶段严格断言除 timeout 外的全部配置逐值一致，主模型、思考、输出、预算和凭据不变，派生详细审查的 timeout 同步改变；没有业务数据或 CALL 增量。v6 冻结绑定两个实际配置转换凭据及两处提示修复。不能把新配置下的结果记为原 300 秒条件通过，不能把不同历史轨迹的后续结果解释成唯一变量因果对照。

重点独立检查：已答决定是否再次被要求回答，否定和范围等子决定是否真正进入正文与验收，已生效新规则是否替代旧规则，未决冲突是否被擅自选择，各字段及最终 PRD 的自身引用是否支持其断言。

完整 PRD 必须经过真实正常业务 API 的必要详细定义、成文检查、文档生成和导出。合成测试中的核对与确认由 Agent 通过正常接口执行，不能冒称真实产品经理批准；不直接写数据库造通过状态，不使用预置通过的测试 helper，不靠评审稿选项绕过成文检查。

如果发现并修复非记忆缺陷，保留最初 baseline 失败，再在同一最终源码上比较记忆关闭和开启；不能把共同修复的改善计为 LangMem 收益。单组真实比较只支持这个场景的观察，不证明统计因果或普遍收益。所有费用未知时保持未知。
