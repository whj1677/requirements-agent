# AI 初稿与批量确认，2026-10-10

本次目标是减少产品经理重填与重复提交：AI 根据资料整理已知内容，为未明确但可提出方案的流程、前置条件和验收提供建议；人看完整内容后确认。80% 是待测的减负目标，不能用字段填充率或一次批量点击代替。

## 实现

- 合理建议允许使用原需求的真实资料作为背景，明确标记 `recommendation / context_only`。背景引用不表示资料已经规定该建议。错误引用、无依据事实、新增无来源范围仍受校验。
- 草稿按问题隔离校验，小问题不会使有效需求及验收一并丢失。完全相同的问题及同轮验收去重；同义问题尚不能保证合并。
- 中性协议外字段保留在结构诊断中。本次真实输出的顶层 `questions: []` 和行内 `statement_note: ""` 不再拒收整包。非空错位的顶层问题尚无可靠归属处理路径，仍保留原始证据并拒收，未悄悄关闭或降级。
- 表格提供临时选择、完整批量预览和一次显式确认。预览展示需求、全部业务说明、验收和关联决定；保存只作用于所选且已展示的内容。失败整批回滚、版本和内容校验、幂等提交保护继续生效。
- 手工修改会保留；预览中冻结行编辑，防止旧预览覆盖新稿。切换条目保护未保存回答；离开页面或确认后清空临时选择。已确认行修改并保存草稿后可以重新选择核对。
- “内容已确认”和“改动性质待明确”分别计数，避免已确认后仍显示零进展。
- 本行 AI 修改的任务确认弹窗用修改意见及可展开的业务文本展示附带草稿，不要求用户阅读内部 JSON；实际发送范围和输入内容不变。

## 审核 Agent 的结论

独立 Agent 对照冻结原资料发现了普通格式校验无法检查的缺口：已知权限被当成未知、入口结果和特殊时段优先级遗漏、错误引用、重复问题以及关键权限问题被标成非阻塞。

目标列表页六组预先冻结的验收点为 2 组完整、2 组部分、2 组遗漏或假未知。另十个业务事实点的有目的抽查为 9 点覆盖、1 点遗漏，不能合并成全项目准确率。用户实际耗时和无 AI 对照基线尚未测量，80% 减负未获证明。

本轮独立审查是开发验收，不是产品内已接入自动审核。建议后续接入“起草 → 独立对照原资料审核 → 一次有范围的修订 → 人工确认”：审核输出具体遗漏、原文位置和修订建议；仍有争议的内容集中交给人决定。两个 Agent 不相互批准、不无限循环、不把修订覆盖到已确认的人工内容。
