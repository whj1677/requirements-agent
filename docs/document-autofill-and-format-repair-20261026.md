# 生成文档前自动补全与一次格式修复

本次触发入口是“准备生成 / 准备更新 MRD、PRD”，不是进入项目、切换页面或确认交付按钮。

## 使用流程

1. 点击生成文档，程序按需求确认表的同一套规则检查必填内容，并合并本浏览器保留的人工草稿。
2. 有缺项时，任务改为“生成文档前，AI 自动补全必填草稿”。按原有任务弹窗核对模型和发送范围后运行，AI 起草摘要、需求、验收及未答问题，已有人工修改保留。
3. 任务结束后打开完善需求表，引导用户核对确认；重复点击生成只返回确认表，不重复调用补全模型。
4. 人工点击“确认并进入交付”并通过原有校验后，再生成文档。仍需落实的回答、版本冲突及成文检查继续显示，AI 不代替人工确认。

取消任务弹窗不调用模型。项目重新打开仍先显示需求助手，不因保留的补全意图自动跳转或发送资料。

## 格式恢复

原有本机无损恢复仍优先使用。完整回复中可验证的 JSON 标点或容器格式错误，本次新增一次模型修复：沿用原任务 Schema、来源、模型配置和请求额度，原始失败输出完整留档，修复调用关联原 CALL。

修复前后逐项比较全部 JSON 字面值及其顺序；正文、引用、编号或确认状态变化时拒绝写入。修复后仍经过全部来源、业务和结构校验。第二次仍失败不会继续循环。访谈沿用既有字面值保护的格式修复；既有引用恢复与本地唯一来源校正继续工作。

截断、缺失字符串、重复键冲突、脱敏后的不完整输出及传输拒绝无法证明保真，不靠补造业务内容强行恢复。额度不足、取消和来源版本变化同样停止后续发送。

## 验证证据

离线浏览器通过单一 8765 来源拦截进入隔离 ASGI 应用，不启动第二个工作台：覆盖取消、缺项补全、人工草稿保留、返回确认、不自动采纳、重复生成不再调用、确认后进入文档计划。

真实 DeepSeek 测试仅发送合成储能云电价模块资料，1 次请求后进入确认表，必填内容已填入，人工修改及原文档保留。真实测试未代替用户确认业务内容。故障注入另行验证格式修复与拒绝改写，不声称真实模型此次自然出现了格式故障。
