# 回答核对弹窗交互修复 · 2026-10-04

## 范围与原因

目标是修复第三步人工回答核对弹窗的操作死路、滚动布局和条款定位。截图中的关联约束尚未采纳，因此原接口正确拒绝记录；旧界面却让确认框可勾选、记录按钮禁用，且没有就地处理入口。全局输入样式使复选框拉满整行，长正文滚动还会隐藏标题和操作。

保留用户既有源码修改、已保存回答和业务采纳状态。没有扩大为全部界面重构，没有替用户核对或批准业务内容，没有执行真实付费模型、Git 提交或正式发布。

## 实现

- 核对 GET 增加只读来源与逐条处理状态，沿用既有采纳、行为核对和回答落实门槛。
- 对可单独采纳的本期原条款提供显式“采纳此条款”；成功后重新 GET，清除确认。此操作只采纳被点击条款，不自动记录回答落实。
- 原文不承载回答时提供“定位并修改此条款”；需求行为缺失时定位对应编辑器。条款编号定位覆盖需求、规则、约束和验收，自动展开并聚焦，并能返回原回答。
- 导航保护同意后才关闭核对弹窗；取消离开继续保留弹窗。修订候选的原条款核对门槛保持不变。
- 固定标题、关闭和操作区，正文独立滚动；复选框为 18 × 18 像素。约束、规则和验收仅展示已有行为字段，避免无关空字段堆积。
- 记录仍要求全部关联条款可核对、最新修订及内容哈希与明确人工确认。读取失败或版本变化需要重载，避免重复采纳或使用旧确认。
