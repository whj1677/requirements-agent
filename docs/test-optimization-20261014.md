## 修改及实际作用

| 问题 | 本轮修改 | 验证边界 |
| --- | --- | --- |
| 详细定义的来源规则发生相互覆盖 | 修复生成 Schema 的共享对象引用。字段、交互、节点、连线和状态迁移各自拥有独立的 evidence 约束，避免最后的连线规则覆盖其他对象 | 新增跨对象有效数据回归；保持存量草稿结构不变 |
| 模型修订不知道程序检查的准确位置 | 为本次输入的需求附上 `code / path / object_id / message`，可定位缺分支、错误终态、未定属性；局部完善只包含目标需求 | 验证输入不被修改、其他需求不泄漏、不把候选采纳状态当新业务问题 |
| 流程类型与字段未知范围表达不准确 | 在生成约束中展开开始、动作、判断、等待、结束的含义和连线要求；明确区分字段已知用途与未定产生方式 | 修订仍由模型提出候选；结构检查通过不代表图文业务语义通过 |
| 成文检查被完全相同的重复 JSON 键阻断 | 复用已有无损规范化：仅完整原始证据下、类型和值严格相同的重复成员可消除重复；记录位置与前后哈希，之后继续完整校验 | 不接受冲突值、截断证据或内容缺失；不采用“最后值覆盖”，不新增自动付费修复请求 |

没有修改业务确认、来源授权、交付门槛、既有数据格式或前端布局。没有替用户确定审计角色、批次标识产生方式等业务答案。
