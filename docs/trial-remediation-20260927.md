## 已实现的整改

| 问题 | 实现与保留边界 |
| --- | --- |
| 审查截断、配置联动困难 | 官方 `deepseek-flash` / `deepseek-v4-pro` 主分析新增功能优先策略。审查默认至少 65536 tokens，明确截断后最多按已批准上限（默认 131072）再尝试一次；旧结果不被截断响应替换。额度、时限随任务计划冻结，开始前可见。 |
| 输入预检 | 功能优先按已文档化的模型窗口、输出允许上限与 UTF-8 字节保守估算协调，预先为重试留空间。该估算不是实际 token 用量；实际用量以供应商响应为准。固定模式保留手动额度，未知模型及图片请求不自动加额。 |
| 长任务与记录 | 审查网络超时至少 300 秒、阶段总时限至少 900 秒；保留总请求数与取消机制。证据保留思考 token 计数，按实际输出额度调整最终内容记录容量，不记录隐藏推理。 |
| 规则问题无法闭环 | 回答绑定扩展到直接关联的原 requirement/rule/acceptance，同 kind 修订、最新回答核验、逐项人工采纳后闭环。新增 `applied_item_ids` 并兼容旧记录；本期规则仍待应用的回答会阻止成文和后续审查。 |
| 参考条款缺少入口 | 原始 reference 规则/验收可经明确理由“纳入本期并采纳”。保留原文、原来源、原身份记录和历史版本；须关联本期需求，支持双向关联。该操作会使旧文档失效，不能替代正式确认。 |
| 导出阻塞 API | 文档生成、哈希、ZIP 压缩放到受控后台任务；交接包事务外生成、短写事务复核并提交；半包不开放下载。并发容量为 2，超时未结束的任务仍占容量，防止无限积累。超时明确说明后台仍可能处理，不能冒充取消。 |
| 导出时内容变化 | 完成后在短事务内重查文档 ID、底稿和完整导出条件，过期返回 409，不记录成功导出。交接包保留原确认基线，并处理并发幂等与异常清理。 |
| 冲突与入口误解 | 冲突表单增加“放弃我的修改，使用最新值”；澄清/变更任务结果明确只生成候选，文档须另行更新。 |
| 临时编号格式修复 | 完整保留首次失败响应；仅当原错误全部是临时编号格式/长度，且只更改声明及对应临时引用、整份其它 JSON 完全相同，才允许修复。合法编号、稳定编号、来源和业务原文均不能借此变更。 |
| 旧指令干扰回答绑定 | 澄清任务明确提供当前逐题逐目标绑定任务及回答版本；旧 assistant 摘要不再重复输入，历史用户消息保留为业务参考。只有同目标、同回答版本且已追踪的待采纳候选才可复用；原规则 selected 不等于回答已应用。 |
| 运行诊断 | 移除相互覆盖的逐请求全局 faulthandler 计时器，保留进程异常记录，增加导出起止与失败、慢请求日志；不从缺少退出日志直接推断崩溃原因。 |
