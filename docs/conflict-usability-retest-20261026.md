# 冲突及异常情况的使用者复测（2026-10-26）

## 结论与验收范围

本轮专门验证“真正解决冲突，再更新 PRD”，不是仅生成一份保留问题的评审稿。以日常 BMS 修订 57 的隔离副本为主，冻结用户模拟采纳的方案和检查预期；通过真实浏览器控件提交，复检必须检查实际保存内容，不能预置为无条件通过。

在所测场景中，可不手工输入长答案，整批核对一次后复检、更新并下载 PRD。失败、部分输出及取消后均能继续处理。真实日常 BMS 的业务决定、回答与现有 PRD 不因验收被采纳或修改。

模型返回采用冻结的本地响应，模型请求函数仍经过正式工作流、Schema、引用、候选修订及确认逻辑。它验证产品流程与恢复能力，不等同于重新向真实模型发起一轮质量验收。本轮未向外部模型发送 BMS 资料，没有真实模型费用请求。

## 发现并修复的实际阻碍

1. **本机生成过 PRD 后，后续 AI 任务启动失败。** 本机任务记录缺少常规任务的幂等键，启动新任务时历史记录被直接索引而抛错。新记录补齐元数据，查询也兼容已经存在的旧记录，不需要改写用户历史。另有回归验证“旧本机记录 → 本机成文 → 普通模型文档任务”完整执行。
2. **表里有推荐答案，批量起草却拿不到。** 未改字的默认推荐不属于手工编辑增量，起草上下文又没包含该推荐字段。本次明确传入显示的推荐草稿，同时保留“尚未由人确认”的身份；要求具体方案写在正文、草稿身份放在元数据，旧验收通过目标身份修订，不能只新增正确条款。
3. **AI 失败的浮窗遮住重试按钮。** 活跃确认表中的失败起草任务改为原地显示原因与重试入口；浮窗不挡操作。真实失败状态和原稿保留，其他项目及非当前表格的失败提示仍可见，用户主动展开也不会被强行关闭。
4. **资料与编号列表把授权按钮挤到屏外。** 任务弹窗正文独立滚动、底部操作固定，资料数量先显示，明细与来源编号可展开。接收端、调用说明及资料范围仍可核对。1280×720、1093×614 下授权按钮直接可见，无需先滚过编号列表。

笔记本上的失败提示另外压缩为两行，保留表格查看空间。
