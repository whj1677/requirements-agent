## 实现

- PRD/MRD 模型现在只输出 plan_version=1、标题、有限章节、规范引用、讨论引用及短叙述。只有 PRD 专用的小 Schema 进入该阶段，不发送其它阶段定义、完整旧文档、UI spec 或带产物的历史消息。
- 输入 A/B/C/D 分别为按 kind 的规范白名单、资料陈述与回答、未采纳建议/假设/方向、未知与限制。所有条目保留采纳及真实性属性；selected 不等于业务负责人批准。资料来源与回答不静默覆盖旧条目。
- 程序生成稳定章节 ID 和层级、回填规范原文、保留条目来源和问答。候选规范引用明确报告 sections[n].normative_refs[j] 及条目，停止业务决定类错误，不自动采纳、不删除引用或改写为确定性叙述。
- 未采纳内容保持讨论身份；已有回答与关联旧条目并列，真实性和一致性待核对。没有原型时明确标注。语义覆盖无法证明的参考维度保持 pending；coverage 只由实际规范块生成。图片仅绑定实际成文功能、适用 profile 布局维度及真实页面引用。
- 单请求 max_tokens 冻结为批准配置。截断修复仅要求缩短叙述、合并章节、只列 ID，仍使用相同上限。最多两次格式修复，与网络重试共享任务额度；仍截断或上下文/请求数超限则 paused_budget。没有新增分段引擎，也没有任何自动提高输出上限的执行路径。旧纯计算函数仅为旧测试兼容保留，不由请求路径调用。
- task 保存批准配置和 plan_hash；run/call 保存实际 max_tokens、授权关联、配置/提示词/Schema/profile 哈希、输入版本、逐请求输入哈希与长度统计。脱敏后的实际输入和最终输出只在本机受控证据中保存；usage 缺失不补算，费用未知时保持 null。修复请求不覆盖前一份证据。
- 最终内容对象仍经原 Schema、引用、规范原文及版本校验，然后交给既有 Markdown/Word 导出。失败不会替换原文档。没有合成答案回退。

## 输入复杂度（重建对照，不是历史原请求或 token usage）

在同一隔离 v17 快照与相同配置上，对比基线 assembler 与新 assembler。下表为各 JSON 分区序列化字符数；空列表为两个字符。UTF-8 字节数也存入本机分析记录。

|---|---:|---:|

| 输出 Schema | 21305 | 897 |
