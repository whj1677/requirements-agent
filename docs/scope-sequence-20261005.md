# 本期范围与批量采纳顺序修复（2026-10-05）

## 任务边界与交付

- 目标：消除“已在范围内 / 本次已勾选 / 已采纳”三种状态混淆，并解释格式修复失败。
- 输入：用户截图、当前根目录实现、已保存的失败调用证据。
- 交付：现有审核页的操作顺序、临时勾选生命周期、可操作的前置提示、通俗失败说明、回归及页面证据。
- 验收：保存范围不会自动勾选或采纳；返回、取消、采纳成功后临时选择清空；持久状态保留；未保存修改和未提交勾选都有明确处理入口。
- 边界：不修改后端业务放行条件，不放宽来源或保真校验，不重跑失败的真实模型任务，不修改日常项目内容，不创建正式基线或发布标签。
- 停止条件：相关回归、隔离页面实测和唯一入口部署核对完成。

## 根因与改动

原页面把持久的 `scope_ids` 同时用于本期范围勾选与批量采纳选择，因此重新进入时“勾着”只说明在范围内，却容易被理解为已处理或即将再次采纳。

1. 本期范围改为“纳入本期 / 移出本期”，调整后明确保存；已保存范围可以折叠查看。
2. 批量采纳使用独立的临时选择。只允许选择已保存范围内的普通候选；已采纳条目显示状态，不显示勾选框。修订候选仍单独核对。
3. 未保存范围或背景时，采纳控件禁用并提供返回保存的入口。弹窗仍要求对照来源和行为后明确确认；保留原来的版本、哈希与整批校验。
4. 返回其他阶段、切换项目、打开设置、取消批量核对或采纳成功后清空临时选择；持久范围及采纳状态不变。
5. 有临时勾选未提交时，底部下一步按钮禁用，提供“去批量核对”及清空选择的说明。独立背景字段仍可按需编辑，不强制所有字段依次填写。
6. 生成失败先显示易懂的原因和后续操作，原始技术字段路径折叠到详情。任务状态读取失效时仍显示“此前记录”，并禁止直接重试。

主窗口独立对照原始调用与修复调用，并比较该项目 v37/v38 的 items、questions、messages、intake、product_context，五类业务内容均相同。本次没有为消除提示而放宽该校验，也没有自动重试真实任务。历史失败记录仍保留。

本次问题定位使用 1 个只读子 Agent、1 次工作派发，请求 `gpt-6-sol / medium`；执行侧实际型号和费用未知。主窗口负责交互设计、实现、独立核对、测试与部署。
