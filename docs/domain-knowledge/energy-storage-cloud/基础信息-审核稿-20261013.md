## 1. 基础概念与设备职责（通用参考）

以下定义是通用参考；云平台为工作定义，不证明本公司当前部署能力。

### G-001 · BMS

BMS = Battery Management System，电池管理系统。面向电池进行状态监测和管理，常见职责包括电压、电流、温度采集，SOC/SOH 估算，以及保护和均衡相关管理。云平台读取 BMS 数据，不等于云平台承担电池现场保护。[资料 1，第 2–5 页]

**本平台已确认（A-005）：BMS 不直接与云平台交互；BMS 数据先送到 EMS，再由 EMS 上传。**

### G-002 · PCS

PCS = Power Conversion System，储能变流系统，常称储能变流器。在典型交流并网电池储能中，连接电池直流侧与交流系统，完成双向电能转换并控制充放电功率。功率指令与实际反馈需要分开，PCS 也不等于整套储能系统。[资料 2，第 2–3 页；资料 1，第 6 页]

### G-003 · EMS

EMS = Energy Management System，能源管理系统。综合运行状态、目标和约束，协调设备运行及充放电安排；可在站端或集中侧部署。EMS 是能源管理功能或系统，不与云平台完全等同，不能预设所有策略都在云端计算。[资料 1，第 1–2 页]

### G-004 · SOC

SOC = State of Charge，荷电状态。表示电池在约定基准和估算口径下的荷电程度，通常用百分比显示，是状态指标而非独立设备。SOC 50% 不代表必然能对外放出额定能量的 50%；可用能量还受运行范围、退化和工况等影响。[资料 1，第 5 页；资料 3，第 3–5 页]

### G-005 · SOH

SOH = State of Health，健康状态。表示电池相对于选定基准的健康或退化程度，也是状态指标；容量、内阻等可作为不同表征。当前容量与基准容量之比是常见口径之一，不统一指定算法、报废阈值或剩余寿命。[资料 1，第 5 页]

### G-006 · 储能云平台

本知识包将储能云平台理解为：汇集站点运行数据，支撑远程监测、运维协作和业务分析的软件平台；部分产品还支持策略管理或远程调控。这是便于需求分析的工作定义，不是统一标准定义。本公司当前部署能力需结合源码观察、部署信息和当前项目资料核对，不能仅凭名称推定云平台替代站端 EMS、直接连接每个设备或具有全部控制权。

### G-007 · 彼此关系

典型关系可理解为：电池储存能量，通过充放电吸收或输出电能，BMS 监测和管理电池；PCS 承担电池与交流系统之间的电能转换；EMS 利用电池/PCS 等状态协调运行；SOC/SOH 描述电池状态，常见由 BMS 估算并被上层使用。云平台通过项目实际的采集与通信链路汇总相关数据，可支撑跨站点管理；是否参与调控以及命令如何到达 EMS/PCS，取决于产品架构。这里描述职责关系，不指定固定接线或消息必经顺序。[资料 1，第 2 页；资料 2，第 3 页；云平台关系为分析框架]

### G-008 · 功率与电量

功率表示能量变化的速率，常用 kW/MW；能量或电量表示一段时间内的数量，常用 kWh/MWh。同一计量边界上，100 kW 恒定运行 1 小时对应 100 kWh；这不自动代表电池侧、并网侧和结算侧电量相同。Ah 是电荷容量，不能直接等同 kWh。[资料 4；资料 3，第 3–5 页]

资料 1～4 的完整链接见本文第 6 节。上述定义已全文展开，使用时无需再次检索。

## 2. 我们平台的上行架构（用户已确认）

以下按你在 2026-10-13 提供的图及后续 BMS 关系补充记录，属于用户确认的架构说明。

```text
BMS
 ↓
EMS
 ↓
EMQX
 ↓
物联网 Kafka：CRRCLink-RAW-DATA
 ↓
CRRCLink
 ├→ 物联网侧 Redis
 ├→ IoTDB
 ├→ 云平台 Kafka：CRRCLink-MEASURING → 云平台侧 Redis
 └→ 云平台 Kafka：CRRCLink-SIGNALING → MySQL
```

### A-005 · BMS 经 EMS 上传

用户于 2026-10-13 补充确认：本平台 BMS 不与云平台直接交互。BMS 将数据送给 EMS，再由 EMS 将数据送往云平台（经 A-001～A-003 所述物联网链路）。云平台展示的 BMS 状态和指标来自该转送链路；平台的 BMS 查询接口不表示与现场 BMS 直接通信。此项确认的是 BMS 的交互边界与上行转送关系，BMS→EMS 的通信协议与数据格式、PCS 的接入关系仍需按项目资料核对。

### A-001 · 接入主链

用户确认上行数据由 EMS → EMQX → 物联网分区 Kafka 内的 CRRCLink-RAW-DATA → CRRCLink。节点名称沿用原图；CRRCLink 等节点在此表示图中的数据通道或处理环节，不据此认定每个名称都是独立服务或源码类。

### A-002 · 物联网存储分支

CRRCLink 分别连接物联网侧 REDIS 与 IOTDB，即图示的物联网侧 Redis、IoTDB。它们与 CRRCLink 同源分支相连，图中没有 Redis → IoTDB 的箭头；不能把历史数据说明为经 Redis 二次落库。

### A-003 · 云平台消费分支

CRRCLink 继续向云平台分区 Kafka 内的 CRRCLink-MEASURING 与 CRRCLink-SIGNALING 分流。MEASURING 连接云平台侧 REDIS，SIGNALING 连接 MYSQL。上行摘要须包含遥测与遥信两条消费分支；图并未逐项定义 SIGNALING 消息及 MySQL 表，不将其扩写为全部告警或全部业务数据。

### A-004 · 分区与证据边界

物联网、云平台是图中两个逻辑分区，各有 Kafka 区域，并各自出现 Redis。需要区分两处 Redis 的用途，不能默认相同实例；图也不证明它们物理隔离或 Kafka 属于不同集群。此前源码观察保留为局部实现证据；图中名称与 IecDTO、PointKafkaDTO、ConsumerMeasuringRunnable 等源码符号及实际 topic 的一一对应仍未核实。此次上行图不证明策略下发、回执、BMS/PCS 与 EMS 接线或现场执行结果。

## 3. 现有平台的基本业务（源码现状摘要）

以下来自你提供的归档源码，表示该快照中可见的入口和局部实现。未核实线上部署和现场运行。括号中的 C 编号用于追溯已有源码观察。

### 平台范围

给定源码含储能、光伏、充电桩等综合能源业务入口，并有资产、监测、运维、收益和策略管理入口。它帮助使用者围绕这些业务查看和管理信息；这里核实的是源码可见入口，线上是否启用未知。（C-001、C-002、C-024、C-025、C-029）

### 资产对象

前端把 Site 对应对象称为园区，Station 为电站；Station 有 siteId，LogicEqu 有 stationId、父逻辑设备 ID、设备类型及采集通道字段。可以据此理解资产、设备和采集信息的关联；不能把园区/站点/电站/主站混为一谈，或认定现场统一按“站—箱—柜—簇—电芯”组织。实际层级待确认。（C-002、C-003、C-004、C-006）

### 运行监测

本平台 BMS 查询电簇与电芯电压/温度等信息，PCS 查询功率与交直流电压电流；另有负荷、SOC、防逆流历史曲线入口。监测查询和遥控下发是不同操作。已追踪的一条曲线链路从 Kafka 点位经 Flink 统计保存到 Redis，不能据此认定所有历史数据都存 Redis。信号口径、精度、时延和缺点处理待查。（C-007、C-008、C-009、C-010、C-011、C-012）

### 异常与运维

综合列表区分故障、告警、云平台自告警，并返回列表、总数、未处理总数；心跳报文有独立处理入口。工单含报修、巡检页面及故障派发/确认/处理接口。告警恢复、处理、关闭与工单完成不能视为同一状态，完整迁移和关闭联动未核实。（C-013、C-014、C-029）

### 电价

电价模板保存主信息及时段明细，与园区/电站的实际电价配置是不同对象；模板可查询、新增、修改，删除会检查实际电价引用。明细字段记录时段类型、开始/结束时间和价格，注解描述尖峰/峰/平/谷/深谷。实际合同、特殊日期、时区及模板变更对已配置电价/历史账单的影响待核实。（C-017、C-018、C-019、C-020、C-021）

### 充放电与收益

套利页面提供日充放电清单、本期/累计收益、电量曲线；查询继续走到账单仓储。总收益服务此处用累计放电量/累计充电量显示效率百分比，充电量为零时返回零。这是局部源码口径，完整账单生成、计量边界、收益成本/税费/补算规则未知，不当作通用收益或效率标准。（C-022、C-023、C-024）

### 策略与控制

峰谷套利启动/停止先校验主站、网关在线和下发条件，组装报文后经 MessageProducer→设备服务 strategySend→外部 IoT HTTP API 发送，保存执行记录并等待回执；方法名带 MQTT 不证明业务直接发布 MQTT。回执另经 Kafka 更新记录和 Redis 验证结果，页面轮询 verify。接口接收、回执、现场执行和达到收益目标是不同状态；外部 IoT→现场段待确认。预测调度、遥控遥调安全联锁仅完成入口索引。（C-025、C-026、C-027、C-028、C-038、C-039、C-040）

### 组织与归属

资产模型和电价模板有租户归属相关字段/查询；前端有部门、成员、菜单、角色入口，部分接口标注权限。实际业主/售后/运维等角色能看哪些资产、执行哪些操作仍待确认，不能把页面存在当作人人可操作。（C-003、C-004、C-017、C-018、C-030）

### 使用边界

以上是用户提供归档源码的现状摘要，有出处的观察可用于解释该快照；不是线上版本证明，也不自动成为本期新增需求、业务规则或验收。当前项目资料、明确范围和人工决定优先。没有说明的具体规则只围绕当前需求列待确认，不猜阈值、算法、权限或闭环。运维、权限、光伏和充电桩等部分仅完成入口索引，不能据此宣称完整实现。

### 源码数据流局部

映射作业读 IecDTO 并产出 PointKafkaDTO，实时作业及监测曲线作业写 Redis；SOC 历史页经 point/queryCurve 读 IoTDB。局部类名、实际 topic 与用户图节点的对应待核实。下行仍是业务→设备服务→IoT HTTP，回执经 Kafka 更新执行记录和 Redis→页面 verify；本次上行图不证明下行现场闭环。
