## 基础概念与常用业务信息首次直接提供

按用户要求，v3 在同一 JSON 的 `overview` 先完整展开 BMS、PCS、EMS、SOC、SOH、储能云平台含义，以及设备/系统/指标之间的职责关系；另补充功率与电量区别。人工可阅读的维护稿为 [基础概念](common-concepts-v1.md)，其中注明英文全称、中文含义、常见职责、容易混淆的边界和原始公开资料。

基础概念标为通用参考，云平台为工作定义；包中的 G-001～G-008 为 `document_claim`、`dimension=domain_reference`，不冒充源码观察。CONCEPTS 是本机维护文档集合，无 Git 版本，证据用真实文档行号和 SHA-256 固定，不虚构代码仓库或部署版本。

第二层按 2026-10-13 用户附图及后续补充直接提供整体上行架构：BMS→EMS→EMQX→物联网 Kafka CRRCLink-RAW-DATA→CRRCLink，随后分别连接物联网 Redis、IoTDB，并向云平台 MEASURING→Redis、SIGNALING→MySQL 分流。A-001～A-005 是用户确认稿的文档陈述，不改标为源码观察。原图、确认内容及文件哈希见 [架构确认记录](architecture-confirmed-20261013.md)；BMS 不直接与云平台交互，先送 EMS 再上传的关系见 [BMS 补充确认](bms-ems-confirmed-20261013.md)。

第三层保留平台范围、资产对象、运行监测、异常与运维、电价、充放电与收益、策略与控制、组织归属、使用边界九组源码观察，并注明支持它们的观察 ID。修正图、页面查询和下行边界见 [数据流修正版](data-flow-20261012.md)。

对领域相关或含义模糊的输入，以上基础概念和摘要随首次背景完整提供，不按话题裁成只剩目录，也不要求 Agent 再查知识包、源码或外部资料才能理解这些信息。程序在同一次输入组装中补充命中的专题细节；没有新增模型检索步骤。详细的行业参考陈述不会被当作专题源码事实检索注入。

例如，即使当前只讨论电价，Agent 仍已经拿到“资产如何关联、监测与控制不同、告警与工单不等同、下发不证明现场成功”等基本背景。这些背景帮助理解语境，不要求本次电价需求额外实现其它模块。未涵盖的具体规则只围绕当前需求列待确认。

模型输入明确要求直接使用已展开的基础概念，不再为这些信息发起二次检索。具体 SOC/SOH 算法、控制权限、告警阈值等仍以当前项目证据为准，不能从通用定义补成业务规则。容量不足仍优先保留用户资料，不静默截断摘要或猜测缺项。

## 平台基本运作方式

给定源码中的产品是一个包含储能、光伏、充电桩入口的综合能源云平台。第一阶段围绕储能相关业务核对代表性链路，并保留其它能源业务索引。

1. **管理资产。** 前端有园区、电站、设备类型和设备建模入口；模型关联 Site、Station、LogicEqu。逻辑设备可以有父设备、设备类型、采集通道和关联通信设备，不能套用统一的“站—箱—柜—簇”层级。
2. **获取和展示运行数据。** 用户补充确认 BMS 先把数据送给 EMS，BMS 不直接与云平台交互；用户图确认 EMS 经 EMQX 进入物联网 CRRCLink 主链，再写物联网 Redis/IoTDB 并分流到云平台遥测、遥信消费者，分别连接云平台 Redis、MySQL。源码核对了点位映射、Redis 最新值/监测曲线和 IoTDB 历史查询。整体架构已说明；实际 topic、代码类映射、部署实例及具体写入/补点规则仍需核对。
3. **发现和处理异常。** 综合告警查询合并故障、告警、自告警，带分页、总数和未处理数；心跳消费者把报文委托给心跳告警服务。工单入口有派发、确认、处理，完整状态迁移与告警关闭的联动仍未知。
4. **配置电价和查看收益。** 模板主表与时段明细保存在业务服务，实际电价配置与日详情入口在系统服务。模板删除会检查电价引用。套利页面查询充放电清单、本期/累计收益与电量曲线，服务继续查询账单仓储；完整收益和账单生成口径尚未核实。
5. **配置与下发策略。** 峰谷套利实现有启动/停止校验、执行记录和回调等待。当前发送代码经 MessageProducer 调用设备服务策略接口，再经 IoT HTTP 接口发送；方法/报文中的 MQTT 名称不证明业务服务直接发布 MQTT。EMS 回执另有 Kafka 消费和执行记录更新路径。这些静态分支不能证明现场执行成功。
6. **按权限提供操作入口。** 可以看到组织、成员、菜单、角色，以及部分接口权限标注。真实用户的资产可见范围与控制权限矩阵尚未确认。

以上分别注明用户架构说明与给定源码可见实现，不把它们自动视为本次需求目标；没有运行验证生产与现场。

## 1. 通过什么方式外挂

共用知识由后端 `app/platform_knowledge.py` 读取独立 JSON，不写入任一项目资料表。聊天入口和需求整理/单行完善的模型输入组装器共用它；MRD/PRD 生成也按同一背景规则使用。视觉读取、回答覆盖判定和正式文档审查不因此增加源码知识。

所有项目使用本工作台数据目录中的同一活动包，不需要产品经理持有源码。源码仅由维护者在制作/更新知识包时读取，日常运行无需访问归档目录。

共用背景只帮助理解、解释现状和提出相关追问。当前项目材料、人工业务决定和范围优先；包内观察 ID 不作为项目 `source_refs`，不会自动新增、采纳需求或修改旧文档。若要在正式需求中把某项现状作为有项目出处的事实，可以沿已有“工程上下文”导入入口显式引用该包，或由当前项目材料/人工确认支持。

此包是用户授权的共用模型背景；已有项目接收端授权与模型任务启动流程仍保留。安装和本轮验证均未向模型接收端发送它。

活动状态可只读查询 `GET /api/platform-knowledge`，返回版本、哈希、覆盖及未知项。现有任务记录及模型调用证据会保存实际使用的版本/哈希与命中项，完整输入仍由原有调用证据机制记录。

本次没有新建页面或添加工作台按钮。浏览器日常入口仍是 `http://127.0.0.1:8765/`。

## 2. 后续通过什么方式更新

第一阶段由维护者更新知识包，产品经理核对业务含义。基础概念改 `common-concepts-v1.md` 并核对公开资料；源码现状按变更模块重查入口、实体、接口、处理与结果，无需扫描整仓。保留没有变化的观察，对失效项改写或删除，对未知项补充证据。通用参考与源码现状分别标明身份。

1. 使用 `export-business-context` 从获准源码导出同一 schema 1.0 的新 `business-context.json`，每次使用新的 `bundle_id`，更新仓库快照、证据行号/哈希和覆盖范围。
2. 对照旧包核对业务差异，同时更新基础概念和常用摘要及其观察 ID。概念维护文档有变动时更新 CONCEPTS 证据行号/文件哈希。行业参考、推断、上线情况与源码观察分开；未确认的变化继续写入未知或冲突。
3. 使用导出 Skill 的验证器，带 `--repository 仓库ID=源码目录` 核对结构、引用、真实文件哈希及行号。校验通过不代表业务评审通过。
4. 在项目根目录发布：

```powershell
.venv/Scripts/python.exe -X utf8 scripts/install_platform_knowledge.py "新包的完整路径/business-context.json"
```

发布脚本校验格式和目标产品，将新旧内容保存到 `data/knowledge/energy-storage-cloud/versions/<bundle_id>/business-context.json`，随后原子替换活动包。同一版本 ID 对应不同内容时拒绝覆盖。回退时把旧版本归档包用同一命令重新发布；各版本仍保留。

知识内容更新无需重启服务：新任务输入组装时读取新活动包。已经组装的任务输入和已有需求/文档保留原版本，不自动重算；原任务中的修复/重试继续使用已组装输入。首次增加本次后端代码需要重启工作台，后续纯知识更新不用。

该包位于被 Git 忽略的本机 `data/`，不会随源码提交或普通软件升级自动带到另一台机器。迁移时显式复制知识包并在目标数据目录安装。

## 3. 通过什么方式检索

第一阶段使用本地确定性检索，没有向量库、嵌入服务或额外分类模型调用。

- **明确无关：** 当前话题表明是教育、电商等其它产品，或明确说与储能云平台无关，不加载平台知识。当前话题优先于旧项目名称。
- **含义模糊：** 直接提供完整基础概念、业务摘要和 CORE 观察，不加载全包的专题实现细节。
- **领域相关：** 从当前用户消息、当前项目背景及本轮已选材料识别业务；单行完善只以当前行和当前消息为检索话题。
- **模块匹配：** 根据电价/分时、告警/心跳、BMS/PCS/SOC、策略/下发、园区/电站等别名排序，最多选 4 个相关模块；余量允许时扩展一层直接依赖，绝不递归装入所有模块。
- **证据筛选：** 基础概念和摘要先完整放入输入，再最多提供 12 条完整、有实现/配置证据且无已标记冲突的专题源码观察，附证据身份与相关未知。基础参考单独标明身份，推断不作为已验证事实注入。
- **容量控制：** 用户材料先取得输入空间，知识只使用剩余容量，并限制新增输入估算量；不足时减少或省略知识，保留原始资料。命中与省略的候选观察 ID 留在输入中。

例：讨论“电价模板新增地区筛选”时，重点加载电价模板和相关资产背景；不会连带加入光伏计费、工单状态和设备遥控要求。讨论“这次是教育课程管理”时，即使旧项目名称含储能，也不加载。

当前分类是初版规则，不是语义理解质量验收：复杂转折、多领域混合与未收录别名可能只拿到共用摘要。后续应根据实际使用中的错配实例小步调整，不能把命中当成事实正确或业务采纳的证明。
