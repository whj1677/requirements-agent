# 需求 Agent：Windows 安装与设备授权

本说明适用于 Windows 客户安装版。客户自行提供模型 API Key，并承担模型服务商收取的费用。设备许可证授予软件使用权，不包含模型额度。

设备授权约束本次交付的 Windows 安装包及其客户 EXE。项目源码仓库继续公开，源码开发与离线测试模式不强制客户设备授权；他人自行获取源码运行，不受客户安装包门禁约束。这一范围由软件拥有者确认，不能将安装包的授权检查理解为对所有公开源码使用的限制。

## 1. 安装前准备

- 使用 Windows 10 / 11 的 x64 电脑和日常工作的 Windows 用户账户。
- 从软件拥有者取得 `RequirementsAgent-版本-windows-x64-setup.exe`，并核对随交付提供的 SHA-256 校验值。
- 安装包包含 Python 运行环境、界面资源、材料解析依赖和网页读取用的 Chromium。客户不需要自行安装 Python、Node.js、npm 或开发工具，也不需要在安装时下载这些依赖。
- 设备授权组件使用 Windows 的 .NET Framework 4.x 和本机主板信息。若企业策略禁止读取设备身份或运行组件，请联系管理员处理，不能通过跳过授权使用软件。
- 调用远程模型、读取公开网页时仍需要相应网络连接。导出授权申请、导入许可证和授权校验本身不连接授权服务器。

安装包不包含 Microsoft Office。普通 DOCX、XLSX、PPTX 等材料先由随包解析器读取；旧版 Office 文件或普通方式无法解析的企业加密、受保护文件，需要在客户电脑使用已经安装、激活且获准自动化读取的相应 Microsoft Office，执行本机只读提取。读取时禁用宏、不更新外部链接、不保存或改写原件，也不绕过企业保护。

企业环境的支持情况取决于本机 Office、文档权限与企业策略，须用客户已授权的代表性文件实际验证。安装成功、文件上传成功或人工可以打开，都不代表程序已经读到内容；应分别核对人工打开、程序提取和页面渲染结果。未取得内容时保留“需要本机 Office 处理”或“权限受限”等真实状态，不能宣称所有企业加密文档都支持。

Office 后备读取还需要企业允许本机 PowerShell 执行随包的只读脚本。程序优先使用已安装的 PowerShell 7，否则调用 Windows 自带的 PowerShell 5.1；不会修改执行策略或添加 Bypass 参数。若脚本策略阻止运行，请由管理员按企业规范处理。普通格式的内置解析不依赖这条 Office 后备路径。

## 2. 安装与首次激活

1. 双击安装程序，按向导安装到当前用户。默认程序目录为 `%LOCALAPPDATA%\Programs\RequirementsAgent`。
2. 从桌面或开始菜单打开“需求 Agent”，浏览器进入本机网页授权页 `http://127.0.0.1:8765/activation/`。
3. 在“授权名称”填写个人或单位名称，点击“保存授权申请”，下载 JSON 文件。将该文件交给软件拥有者，并说明申请使用的软件为“需求 Agent”。
4. 软件拥有者审核后会返回许可证 JSON 文件。在授权网页选择收到的原始文件，再点击“导入并验证”。需要替换已有许可证时，先明确勾选“我确认替换本机已有的许可证”。
5. 授权有效时，页面显示“本机已授权”和授权名称，“进入工作台”按钮可用。点击后进入同一地址下的工作台 `http://127.0.0.1:8765/`。

申请只包含申请信息、用户填写的授权名称和产品绑定的设备摘要，不包含主板原始序列号或 API Key。请勿手工修改申请或许可证。生成申请不等于已获授权，复制他人的许可证也不会授权当前设备。

没有有效许可证时，同一 8765 端口仅提供授权网页及激活接口；业务工作台不可用，也不会初始化业务数据库。授权有效并点击“进入工作台”后，才加载业务应用。许可证导入、验证及工作台启动都在本机完成，不另开工作台端口。

## 3. 配置客户自己的模型

工作台首次使用时展开“高级模型配置、密钥与连接测试”。核对模型服务商、Base URL 和模型名称后，先点击“保存模型配置”；再填写自己的 API Key 并点击“使用此 Key”。随后可点击“测试连接（调用模型）”。连接测试会实际请求模型，可能产生费用。

页面输入的 Key 仅在当前工作台服务进程中有效，不会写入配置文件；完全退出并重新启动后需要重新输入。授权网页本身不收集模型 Key，软件拥有者也无需接收客户的模型 Key。

需要长期保存默认 DeepSeek 接收端的 Key 时，可由客户在 `%LOCALAPPDATA%\RequirementsAgent\.env` 中配置 `RA_DEEPSEEK_API_KEY`，然后完整退出并重新启动工作台。该文件是客户自己的明文凭据文件，应限制本机访问权限，不要发送给软件拥有者、放入共享目录或提交 Git。页面清除会话 Key 不会删除此文件中的 Key。

后续业务操作参阅随包的 [用户使用说明](user-guide.md) 中“开始一个项目”及五步业务流程。该说明中的源码安装命令、根目录 `data/` 和 `start-local.cmd` 适用于开发源码版；客户安装版的入口和目录以本文为准。

## 4. 日常使用与退出

- 始终从“需求 Agent”快捷方式进入。业务工作台固定使用 `http://127.0.0.1:8765/`，不会自动改用其他端口。
- 完成工作后，先保存输入，等待模型任务和材料读取结束；点击工作台左下角“授权与退出”返回授权网页。存在未保存修改时，先按提示保存或明确放弃；选择留在当前页会取消跳转。
- 在授权网页点击“退出本机服务”，再点击“确认退出”。页面收到服务退出确认后会显示“本机服务正在退出”；等待服务结束后再升级或卸载。如果仍有材料读取或模型任务，退出会被拒绝，请等待后重试。
- 只关闭浏览器标签页不等于停止后台工作台。
- 若出现“8765 端口已被占用”，先核对并正常退出原工作台。不要按进程名称批量结束 Python、Office 或浏览器进程。
- 软件会在运行过程中继续检查本机许可证。不要在使用时移动、删除或编辑安装后的许可证文件。

## 5. 数据、更新和卸载

| 内容 | 默认位置 |
| --- | --- |
| 程序与运行依赖 | `%LOCALAPPDATA%\Programs\RequirementsAgent` |
| 项目数据库、材料和业务成果 | `%LOCALAPPDATA%\RequirementsAgent\data` |
| 已导入许可证 | `%LOCALAPPDATA%\RequirementsAgent\license\license.json` |
| 运行日志 | `%LOCALAPPDATA%\RequirementsAgent\logs` |
| 客户自行设置的持久模型凭据 | `%LOCALAPPDATA%\RequirementsAgent\.env`，可选 |

升级前先保存输入、结束任务并正常退出。确认工作台已停止后，将 `%LOCALAPPDATA%\RequirementsAgent` 整个目录复制到受保护的备份位置。备份包含业务材料和许可证；如果配置过 `.env`，也包含客户凭据，不能作为普通附件外发。不要在运行期间直接复制 SQLite 文件作为一致性备份。

运行新版本安装程序进行更新。安装器将更新程序文件，项目数据、许可证及客户配置位于程序目录之外，不作为卸载内容删除。卸载前同样先正常退出并备份。重装到相同 Windows 用户后仍使用该用户的持久目录；换 Windows 用户不会自动转移项目和授权文件。

恢复数据前先停止程序，在单独目录核对备份内容，保留原目录用于回滚，再由维护者处理恢复。不要直接合并不同时间的同 ID 项目快照。安装包不是项目数据备份，保存安装包不能替代保存数据。

## 6. 授权问题处理

| 提示或情况 | 处理方法 |
| --- | --- |
| 尚未安装授权文件 | 导出申请，由拥有者签发，再导入许可证。 |
| 此授权不适用于需求 Agent | 联系拥有者，核对申请的产品标识为 `requirements-agent`。 |
| 签名无效、发行方不匹配或格式无效 | 使用拥有者提供的原始许可证；不要编辑 JSON，也不要使用其他软件的许可证。 |
| 授权与当前主板不匹配 | 在实际使用电脑重新导出申请，由拥有者审核并重新签发。 |
| 无法读取有效主板身份 | 联系管理员核对硬件信息和企业策略；软件不会自动改用其他设备标识。 |
| 授权组件无法运行或版本不匹配 | 先正常退出，再用同一发行方提供的安装包修复安装。 |
| 已有不同授权 | 核对新文件来源和设备后，在授权网页明确勾选替换选项，再导入。无效新文件不能代替有效授权。 |

许可证永久有效，没有时间到期机制；更换主板通常需要重新授权。重装系统可能丢失本地许可证文件，同一主板可尝试重新导入之前保存的许可证。应同时保存签发文件和项目备份。

这是离线设备授权，拥有者不能远程撤销已经签发的永久许可证。纯软件客户端也不能保证抵抗管理员修改程序、伪造硬件信息或克隆虚拟机身份。需要到期、远程撤销或联网额度控制时，应另行设计授权服务，不能把当前许可证描述为具备这些功能。

## 7. 软件拥有者：签发客户许可证

以下操作只在软件拥有者电脑执行，不发给客户运行。拥有者需要保留 `device-license` 源工程和签发环境，其中 Node.js 要求为 22 或以上。客户安装包不包含签发工具或私钥。

先核对客户申请的 `product` 为 `requirements-agent`，并核实 `subject.displayName` 和实际被授权对象。申请中的设备摘要由申请方提交，签发器不会证明申请对象的业务身份；是否授权由拥有者决定。

在 `D:\01_AI工程\01_工程项目\device-license` 的 PowerShell 中执行，替换示例输入、输出路径：

```powershell
node .\issuer\owner-cli.mjs sign --request "D:\授权申请\客户申请.json" --output "D:\授权签发\客户许可证.json"
```

输出目录需要预先存在；输出文件必须是新路径，工具不会覆盖已签发文件。成功时返回 `status: ISSUED`、`licenseId`、`requestId`、产品标识和公钥 ID。把签发的许可证 JSON 交还客户，并保留申请、签发文件、授权对象及审批记录，便于客户丢失文件后恢复。不要把拥有者私钥目录、内部验收许可证或模型凭据发送给客户。

客户程序固定产品标识及发行公钥。当前拥有者密钥使用 Windows DPAPI CurrentUser 保存于 `%LOCALAPPDATA%\ui-test-agent-issuer\keys\issuer-rsa3072-v1.dpapi`；目录名沿用授权组件的历史命名，不改变需求 Agent 的产品标识。签发必须使用与安装包内公钥配对的密钥，换一把密钥签名不能使既有安装包接受新许可证。

如需核对或重新导出当前公开信任文件，执行：

```powershell
node .\issuer\owner-cli.mjs init --product requirements-agent --trust-output .\public\requirements-agent-trust.json
```

`init` 在原有 DPAPI 密钥存在时复用它，不应删除密钥文件后重新初始化。只有公开信任文件及公钥 XML 可作为构建输入。私钥的跨电脑恢复和轮换尚无现成流程；不能把复制 DPAPI 文件当作可跨系统恢复的密钥备份。拥有者重装系统或换电脑前，需要先落实密钥保管与后续签发安排。

## 8. 验收范围

交付时应一并查看对应版本的构建清单和验收记录，核对安装包哈希及已执行项目。源码单元测试、同机隔离目录安装和全新电脑安装是不同的证据，不应相互替代。

遇到启动问题时，提供安装包版本、许可证错误码以及已脱敏的日志即可。不要发送客户 API Key、`.env`、拥有者私钥或未获准外发的业务材料。
