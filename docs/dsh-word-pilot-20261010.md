# 原始 Word 与 DeepSeek Harness 试验

结论：可以让用户直接提供 Word，由系统自动读取正文、表格和可取得的图片，再生成待确认需求。已完成一次真实 DSH 工具循环试验，但本轮结果不足以支持整套替换日常需求整理流程。

## 实际接入范围

调用链为：需求 Agent 的隔离试验脚本 → 官方 DeepSeek Harness Python SDK 0.1.5rc1 → `requirements-material-review` Skill 与只读工具 → 业务 JSON → 现有业务草稿校验器。日常工作台没有切换模型调用实现，没有增加另一个用户工作台。

DSH 自行调用 `read_document`，后者复用本项目已验证的本机 Office 只读读取路径；图片使用 `read_image`。用户不需要先手工把 Word 转成 JSON。Word 二进制并非由模型直接解释，正文、表格及图片需要实际读取成功后才作为模型输入。

本次原件是“电价管理”v13 的冻结资料，合计 15 份：1 份 Word、11 份此前从该 Word 导出的图片和 3 份用户补充文字。没有把其他项目或凭据放入模型可读工作区。所有生成结果仍为候选，没有代替用户确认。

## 验证结果

| 项目 | 实际结果 |
| --- | --- |
| 原件与数据保护 | 15 份冻结原件哈希均匹配；模型试验前后日常数据、资料工作区和项目快照未变化 |
| Word 正文和表格 | 本机只读实测取得 99 行、3193 字符，其中表格 88 行；99 个片段均按原始位置和精确文字绑定引用 |
| 图片 | 11 次图像工具调用；SDK 上传索引证明 11 个规范化图像载荷上传成功。旧事件记录不能恢复逐文件映射及每次请求携图情况，不据此宣称模型正确理解了全部图片 |
| 未读取内容 | 12 个内嵌对象中有 1 个导出失败（内嵌对象 1 / 页 4 / 字符 476）；页眉页脚、批注、修订和完整页面渲染未验证 |
| 真实运行 | 修正首次 SDK 接口配置错误后，第二次任务运行约 101 秒，11 个模型步骤、21 次工具调用。步骤数不等于含上传及重试的全部 HTTP 请求数 |
| JSON 接收 | 原回复含一句说明及唯一 JSON；原包装解析失败。保留原回复，离线提取原样 JSON 后，13 行接收 11 行、拒绝 2 行；未付费重跑来修饰结果 |
| 内容效果 | 补回业主可见范围，改善部分校验与导出说明；仍误读删除操作和特殊时段优先级，产生 2 条重复需求 |
| 性能参考 | 直接调用基线约 33 秒；DSH 约 101 秒。输入渠道也发生变化，不能将差异全归因于 Harness。费用未知 |
| 离线回归 | 45 项通过，覆盖工具边界、Word 来源绑定、资料准备和最终 JSON 包装解析 |
| 人工业务验收 | 未执行，不代表“电价管理”已经确认完毕，也不代表可以直接导出正式交付 |

本次 DSH 累计使用量为非缓存输入 106,478、缓存读取 621,696、输出 17,495，总计 745,669 token。累计使用量不是单次上下文长度，也不能按比例推算实际费用。图片上传记录的有效期为 7 天；没有证据证明会话关闭后立即删除，也未验证到期后的实际删除。

## 后续采用建议

保留“上传原件 → 自动读取和整理 → 表格展示建议及来源 → 人工修改或确认”的产品方向。DSH 保留为可选试验适配层；本轮没有证明它比现有直接调用更稳定，暂不全量替换。

要解决当前重复确认的问题，下一次改动应优先检查已有需求归并和已知事实覆盖，让模型少问资料中已经明确的问题。不能仅靠加长上下文或更换运行框架就宣称解决。

## 实现与证据入口

- `app/dsh_bridge.py`：官方 SDK 的独立运行环境、只读工具边界、执行与元数据记录。
- `app/dsh_document_reader.py`、`scripts/dsh_read_document.py`：白名单 Word 原件与已有 Office 路径；不支持未经验证的任意格式。
- `scripts/prepare_dsh_requirement_pilot.py`：冻结资料包。
- `scripts/run_dsh_requirement_pilot.py`：显式启用真实模型的隔离调用方，不由日常 UI 自动执行。
- `skills/requirements-material-review/SKILL.md`：通用资料整理 Skill，不含本次评审答案。
