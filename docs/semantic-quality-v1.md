# 语义质量契约 v1

本次复核必须分别核对输入内部一致性、系统运行角色、既有事实与本期决定、模型建议与交付义务，以及规范原文和全部文档解释的条件与量词。来源存在或人工已回答不代表内容必然一致。冲突不得由模型代替产品负责人选择。

## 流程与兼容性

不新增持久化字段。共享 `semantic-quality-1` 契约进入分析、成文和复核任务头。当前选中条目及回答的计数反例由上下文派生，`check_id` 绑定对象、具体字段和计数维度；复核必须在同一 blocker 和 required_decisions 中保留该 ID。分析阶段使用既有 related_refs/source_refs 关联问题与实际冲突，其他对象、来源或字段上的问题不能替代。

没有明确 PM 选择时，当前矛盾计数条款禁止成文。明确选择逐 Unicode 码点或扩展字素簇后可以成文；旧输入和人工决定继续保留，不删除历史以制造一致。既有人工采纳、回答应用及正式确认门禁继续生效。复核目标哈希加入契约版本，使旧复核需重新执行；不改写已确认历史文档或基线。

计数反例按实际上限派生，例如 99 个 A 加 👍🏽 是 101 个 Unicode 码点、100 个扩展字素簇。它是供业务选择的诊断反例，不是产品计数字符的实现。

## 确定性门禁的边界

当前检查覆盖可识别的中文/英文码点与 emoji 一码点冲突，及有引用解释中明确失败被泛化、全部被部分替换、建议被升级为培训义务、无既有实现证据却宣称已覆盖等有限词形。真实实现证据、明确业务义务及标为建议的文字有正例回归。它不构成任意自然语言的完整语义证明，也不能单靠关键词保证跨字段角色及事实归属一致；这些仍依赖模型复核和人工审阅。既有实现证据的同场景相关性仍需人工核对。

回归从公开 assemble/validate_response/compile_plan/reader/export 流程验证阻断与合法选择，覆盖来源及对象绑定错误、人工回答重复矛盾、旧历史保留、两个合理选择的 MRD/PRD/Markdown/DOCX 一致性。测试素材均为合成数据；不得据此宣称普遍业务质量或对外发布通过。

真实复核首次遗漏一处摘要失败条件弱化，因此复用成文解释检查生成临时 semantic_document_checks，绑定实际文档版本、章节、块和风险维度，只按该块声称的引用评价，不使用无关功能的全局规则。复核逐项在 finding 定位检查 ID；正文纠错不得自动增加 PM 决策。此机制不修改已确认文档，仅阻止遗漏风险的复核被保存。

真实调用还出现输入诊断字段被复制到响应、perspectives附加role_note，以及格式修复改写limitations。原Schema与保真门禁均拒绝，未通过删业务内容清洗接受。任务头新增response_boundary，直接从实际Schema派生各对象允许字段，并明确输入诊断不能作为响应字段；校验约束未改变。
