### 模型调用与成本

本轮实际向现有 DeepSeek 官方接收端发送 **40 次请求**：工单 18 次、内部说明 19 次、错误反例 3 次。用实际 call_id 去重，按时区解析请求开始时间，并核对 run/task/源码版本，排除了克隆数据中的历史调用。本轮累计 **817600 tokens**，其中输入 668974、输出 148626。该统计仅为应用的真实模型请求，不包含 Codex 主管和子 Agent 的用量。调用单价未配置，实际金额未知。

40 次均收到 HTTP 200，但只有 27 次输出通过本地结构/引用/语义约束；其余 13 次分别为 SCHEMA_INVALID 2、REFERENCE_INVALID 1、SEMANTIC_BLOCKED 1、OUTPUT_EMPTY 8、OUTPUT_TRUNCATED 1。被拒绝的输出没有因此得到业务批准。格式修复、失败和截断证据全部保留，不能把 HTTP 200 当作任务成功率。

同一工单文档在关闭思考时出现审查假冲突，开启后正确区分了业务冲突与非阻断建议；这是本次实际观察，未外推为所有模型/项目的普遍保证。内部说明的思考审查曾达到 16000 输出限制；负责人重新授权 24000 的隔离任务后完成。产品修复为截断暂停和清楚提示，日常预算没有自动提高。DeepSeek 模式参数依据 [官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)。

模型证据记录最终答复、参数、来源和 usage，不保存思考原文。总预算限制按本轮用户授权取消，单动作的授权、超时、取消和重试上限仍然执行。
