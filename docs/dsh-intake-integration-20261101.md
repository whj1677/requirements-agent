# 需求初稿 DSH 阶段接入与真实对照

本次只接入“读取已提取资料 → 整理待核对需求草稿”。仍使用根目录 `app/`、`web/dist/`、`data/` 和唯一入口 `http://127.0.0.1:8765/`。前端代码由本机 Kimi CLI 的 `kimi-code/k3.1-pro` 配置生成，后端由宿主指定的 GPT 6 Astra 子 Agent 实现，Codex 集成与核验。Kimi 响应未提供独立模型身份回显，配置映射与实际调用记录均保留。

模型设置的“高级参数与密钥来源”新增“资料整理方式”：现有方式、DSH 技能整理（试用）。选择须保存，不自动开始任务。正常聊天和资料上传入口保留；整理任务沿用现有项目授权和候选校验，不增加授权弹窗。打开、切换、重开项目仍先进入需求助手，不因进入页面自动调用模型。详细定义、PRD、审查和正式确认继续使用原流程。

DSH 在每个整理任务中启动隔离 SDK，加载本阶段技能，以专用只读工具读取本轮快照。来源、摘录、已答原话、未决问题和 schema 来自现有装配流程。JSON 原值不改写；任务工具只能读取精确允许的三个快照文件，按实际交付的 Unicode 字符区间核对全文，缺一个字符也不能接受候选。最终结果继续经过现有来源身份、版本、业务草稿和候选守卫，不替用户采纳需求。

运行组件固定 `deepseek-harness-sdk==0.1.5rc1` 与同版 `deepseek-harness-runtime-bin`，只安装在本工程 `.venv`。全局 DSH 未升级。官方项目仍标注开发预览，不能据此称为已完成全产品迁移或稳定性验收。依据：[官方仓库](https://github.com/deepseek-ai/deepseek-harness)、[Python SDK](https://github.com/deepseek-ai/deepseek-harness/tree/master/python)。

迁移技能时保留了仓库自有 `requirements-material-review` 的“先整理已知，再提出剩余决定”“输出”原文段，以及当前任务实际选中的上游方法。普通初稿两例选中 `anthropic-write-spec`；仍由现有阶段选择器决定是否使用其他方法，不因安装而展开全部模块。每次任务保留源文件 SHA、选段位置、上游固定提交、许可证和生成技能 SHA。原件及许可证放在技能发现目录之外，发现目录仅暴露本阶段包装技能，避免意外激活其他流程。原 Word、图片和 Office 后备提取继续由现有组件处理；本次没有新增原件重读或图像能力。

真实试用中已修复：

- 储能云平台初稿被自动提升成详细定义、跳过 DSH 的阶段判断。两路径共同修正；明确详细定义的原门槛保留。
- HTTP 200 的 gzip SSE 原始字节被当普通 SSE 转发，及运行错误被读取失败覆盖。改为解压后转发并保留编码、字节哈希、完整结束等协议证据。原首次失败未采编码，不能反推其真实编码；后续真实流已证实 gzip。
- 真实界面资料中的 4234 字符长行被标准读取工具截断，补读行号又跳过一行。改为精确字符分片工具和宿主读取计划；没有降低全文检查要求，原失败输出保留。
- 共用初稿提示增加逐字段引用自核、原始事件锚点、当前与未来状态区分，以及不把未定界面位置写成事实；没有新增模型审查链或注入测试答案。
- Kimi 修复消息已确认发送后仍显示“未发送”的旧提示，以及仅改整理方式却提示“接收端或模型已修改”的不准确文案。失败或结果未知的输入、附件及恢复信息继续保留。
- Kimi 修复需求仍为“待核对范围”时，关联问题被误标“本期以外”的显示。最终界面显示“范围待核对”，没有更改纳入、回答或确认状态。
