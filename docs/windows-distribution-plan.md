# Windows 安装与设备授权任务状态

- 当前阶段：实现与隔离验证；负责人为主管任务，打包和授权子任务按文件边界并行。
- 唯一目标：Windows x64 客户安装后无需自行安装 Python、Node 或浏览器运行依赖；经拥有者签发设备许可证后使用现有需求 Agent。
- 输入：当前 main 源码、device-license 0.2.0 / DLL 1.0.0-rsa、已有 DPAPI 签发密钥的公开部分。
- 有限交付：客户安装 EXE、校验清单、客户安装/激活说明、拥有者签发说明、源码与自动回归、实际安装授权验收记录。
- 验收：未授权只开放同端口的激活页面，不初始化业务库、不加载业务接口；合法授权可运行；错误产品/签名/设备/破损许可被拒；免令牌参数不能跳过客户版授权；依赖随包、隔离路径安装启动和文档解析可用；升级/卸载保留客户数据及许可证；包内无日常数据、API Key 或签发私钥。
- 已确认：客户自行配置模型 API Key；采用现有离线永久设备授权。首次生成授权申请、人工签发和导入属于必要的启用流程。
- 后续明确：仓库保持公开，授权只约束客户安装包；授权与启动使用网页界面。客户电脑同样有文档加密，实际安装版须在本机企业保护环境验证获准的 Office 只读后备读取，不能以开发 Python 的读取结果替代。
- 边界：不改需求业务语义、不迁移日常 data、不提供共享模型账单、不增加在线授权服务器；不打包微软 Office；不宣称可抵抗管理员修改程序或克隆硬件。
- 权限：本机实现、构建工具安装、隔离安装/卸载测试、当前设备内部验收签发。客户包和公开资料不得包含签发私钥或内部模型材料。
- 停止条件：上述实现及可执行验收完成，记录无法在当前机器证明的干净电脑/第二物理设备限制；不得用同机隔离测试冒充跨机验收。

## 部署决定

客户版固定产品标识为 `requirements-agent`，公钥固定在构建输入中。Python 通过标准输入输出调用现有 DLL 桥接 EXE，无需客户额外安装 Node。冻结的客户版在业务入口、应用创建及业务请求上校验授权；源码开发/测试工厂保留隔离回归能力，源码本身不构成防复制边界。

安装目录为 `%LOCALAPPDATA%\Programs\RequirementsAgent`；持久数据目录为 `%LOCALAPPDATA%\RequirementsAgent\data`，许可证目录为其同级 `license`。源码工作台仍保持仓库根目录 `data/` 与原入口。两种部署均使用 `127.0.0.1:8765`，端口冲突时明确拒绝启动，不自动换端口。

构建采用 PyInstaller 的目录包及 Inno Setup 安装器，Python/扩展、Playwright 的 Node 驱动及对应 Chromium 随包；运行时不下载依赖。路径及子进程适配依据 [PyInstaller 运行时说明](https://pyinstaller.org/en/stable/runtime-information.html)。

本机首轮构建暴露包内 DOCX 模板的读取者字节差异，实际客户 EXE 的解析失败，首轮不作为可交付版本。后续在干净 Windows 构建环境复建，并加入 Python/.NET 逐文件哈希一致性门。构建环境与客户企业保护环境分别验证，不更改企业策略或原始材料保护。
