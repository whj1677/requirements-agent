# 聊天摘要直接核对（2026-10-09）

此前访谈合同只保存聊天回复，不产生结构化摘要；必须另行整理才有目标、使用者、改动建议。上一轮表格测试预置了摘要与范围，未覆盖这个入口缺口。本轮修复这条链路，不更改现有人工作出的业务决定。

## 操作变化

- 同一次聊天可顺带输出有来源的 `context_draft`，转为 `product_context_proposal` 候选；不额外启动一次模型请求，不自动确认。
- 摘要先显示完整的“AI 已整理 · 待你确认”卡片及来源入口，正确时一次明确确认，需要改时才展开编辑。
- 历史聊天尚无摘要时，提供“从已有聊天和资料整理草稿”，打开现有整理任务核对；不会只因查看页面就调用模型。
- 已保存人工内容和“不适用”等判断保持。新建议单独展示，明确未知不会因保存文字而变成已明确。
- 收起摘要区域保留未保存编辑；加载迟到的底稿不会覆盖用户已选择的聊天方式或输入。待办入口定位到实际内容，确认后进入下一项。

## 来源与并发边界

摘要逐字段绑定实际输入片段。无效摘要字段单独隔离、记录限制，合法聊天回复保留；主响应、重复 JSON 键与原义修复保护不放松。候选变更提升项目版本，旧版本写入拒绝。界面确认前复查推荐和来源，已失效的推荐不能一键确认。

现有字段事实检测只是一组有限校验，不构成对模型所有语义的证明；最终仍需人工阅读。聊天摘要不等于已生成全部需求条款，也不等于本期范围或正式交付已确认。
