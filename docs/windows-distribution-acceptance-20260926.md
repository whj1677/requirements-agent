## 5. 最终源码修订与 PowerShell 兼容性

源码修订保留已安装 PowerShell 7 的优先选择；在其不可用时，将后备命令改为 Windows 系统目录下的 Windows PowerShell 5.1 **绝对路径**，解决受限 PATH 下找不到裸命令 `powershell.exe` 的问题。没有添加 `-ExecutionPolicy` 参数或修改企业策略。

`office-host-portability.json` 记录了以下不同层次的证据：

- 在隔离进程的受限 PATH 中，裸 `powershell.exe` 不能启动；系统绝对路径可启动并返回版本。
- Windows PowerShell 5.1 解析 Office worker 时未报语法错误，UTF-8 BOM 和中文字符串读取检查成功。
- 当前机器的 Windows PowerShell 5.1 执行策略为 `Restricted`。不涉及 Office COM 的探针已被策略阻断，实际 Windows PowerShell 5.1 Office 提取为 **`NOT_RUN`**。
- 当前机器另有 PowerShell 7。初包的 Office 实际提取结果属于主管执行的安装版验证，不能用 PowerShell 5.1 的语法检查代替。

最终修订同时增加 `scripts/verify_windows_install.py`：在没有已有产品注册、没有 8765 占用的环境，真实静默安装、核对安装文件、以隔离用户目录及系统 PATH 启动未授权 EXE、读取激活 HTTP 页面和接口、确认业务被拒与不建库、正常退出并真实卸载。目录中的保留哨兵不是许可证；流程不签发有效授权、不请求模型。本次云端已实际完成这些步骤，依据下载并核对的 `installation-verification.json`。这项 HTTP 验证不包含浏览器执行 JavaScript 和实际点击交互。
