# 真实需求 Agent PRD 验证与有范围的优化

日期：2026-10-13。测试对象为合成需求“多站点告警批量派单”，不是当前云平台已实施规则。用户要求实际调用已配置的需求 Agent，并交付其生成的 PRD。

## 本次已实现

- 详细定义只列实际输入、显示和结果数据；未定的上限、查询间隔及重试策略集中成问题，不生成没有配置页面的假字段。七维概述不再要求重复全部属性。
- 正文、流程、状态和验收共用生成约束；明确提醒站点失败与批次结束分开、未知先查询、重试可选以及重试仍可能失败。
- 只整理可证明重复的模型格式噪声：等于数组位置的纯数字 index，以及与连线两端节点完全相同的交互引用。原始输出、原值、位置和诊断均保留；不猜业务值，不宽松接收其他未知属性。
- 结果条件检查能区分“保存时发生超时”和保存结果断言，区分“不得当作失败”与宣称失败；后续分句、双重否定和真正结果断言继续检查。
- 修复采纳 AI 修订时未同步 detail_contract/detail_required 的接口缺口；稳定需求 ID 保留，内容版本更新，旧确认仍由原门禁控制。
- 实际 Word 检查后修复长回边撑宽和图片切断问题：边显示短编号，完整条件保留表格及 SVG 提示；回边复用通道，按完整节点层分页并标明跨页去向。业务 JSON 与文档内容哈希未改变，重排没有增加模型调用。

实现入口：`app/detail_draft.py`、`app/business_draft.py`、`app/result_conditions.py`、`app/main.py`。新增实际链路验证脚本 `scripts/run_detail_prd_agent_validation.py`。

## 尚未解决的质量限制

1. 通知节点回到逐站结果节点后，缺少足够清楚的“已通知不再次触发”条件；容易被理解为重复通知循环。须在确认通知策略时收敛分支。
2. 系统结果字段虽然只读，出现时机、空值含义和固定枚举仍未完全定义。不能把“用户无需填写”当作系统返回值可缺失。
3. 修订后的详细定义仍引用早期验收条目。为保持引用，评审稿保留相关旧验收和改进后的新验收，因此部分内容重复；不宣称已经达到精简定稿。
4. 目前 5 条问题中有两条通知策略问法重叠。最大告警数、查询间隔、通知策略、重试输入复用方式尚未决定；站点及通知状态枚举还在字段中标为未知。不能把问题数等同于所有缺口已经闭合。

下一步应先完善“修订验收复用稳定身份与引用迁移”，再把同一个决定影响的多个未知属性关联至一个可集中确认的问题。语义相近不能直接按文本相似度静默合并；需保留来源、差异及核对记录。流程语义复核继续放在成文前，以明确缺陷反馈给 Agent，而不是手写修改最终 Word。以上属于后续建议，本轮未扩大实现。
