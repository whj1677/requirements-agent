# 业务背景包使用说明

业务背景包帮助需求 Agent 理解产品现状中的业务对象、参与者、流程、规则与模块影响。技术摘要只用于解释相关系统连接，不能代替业务事实，也不能从源码推定生产环境的实际规则。

## 导出与导入

1. 在获准读取的产品源码目录，使用已安装的全局 `export-business-context` Skill，说明本次业务场景与输出位置。Skill 沿场景只读查找页面、接口、处理逻辑和业务对象，导出唯一的 `business-context.json`，并记录出处、覆盖范围、未知与冲突。不要将密钥、原始数据或无关文件放进包里。
2. 在需求 Agent 的“项目资料”中选择“导入业务背景”，上传这个 JSON。等待校验和解析完成，再在“已导入资料 → 业务背景”中查看产品概览、来源版本、覆盖限制、模块、业务陈述及出处。上传成功后仍需人工核对内容；静态源码观察不等于生产运行验证。
3. 勾选本次需求相关模块并单独保存。模块会展示声明的依赖，相关依赖可辅助分析；选择模块仅表示相关性，不表示已确认其中事实或已授权发送给模型。
4. 对确有依据、适用于本次讨论的具体陈述，逐条勾选并使用“保存已核对事实”。无需逐条确认整个包。已核对现状仍不是本期规范；本期规则须在需求流程中另行确认和采纳。缺少依据时保留未知，冲突应核对后再决定。

同一产品导入新版时，旧包保留，且新版不会自动继承旧版的模块选择或事实核对。需要切换时，明确在目标版本选择并保存模块；旧版选择与核对记录作为历史保留。资料是否发送给模型，继续遵循项目现有的接收端与材料范围授权。

业务背景用于把文档写得更具体：MRD 说明用户问题、价值依据、目标与范围；PRD 说明操作者、对象与数据、正常和异常流程、状态变化及可观察的验收。没有来源的价值、角色、权限或运行结果应写为待确认，不能由代码补造。
