# 首屏需求访谈与第二步需求草稿

## 本轮状态卡

- 阶段：实现与验证。
- 唯一目标：无需需求分析或架构知识也能从聊天开始；第二步核对整理草稿，已有明确需求可直接录入。
- 输入：用户确认的两页方案、现有资料/版本/候选/核对机制。
- 有限交付：逐轮访谈入口、用户原话与失败保存、第二步整理及明确采纳修订、直接录入入口、成对回归、真实模型与唯一工作台验证。
- 验收：聊天不代采纳业务规则；原话不因模型失败丢失；补聊不覆盖已确认范围；接收端及发送资料可核对；专业入口保留来源与核对门槛；全量、Office合成、前端构建和有限真实请求均记录实际结果。
- 明确不做：HTML/代码生成、重写历史材料或基线、修复上轮审查发现的其它独立内容风险。
- 权限：主窗口独立执行，无子Agent；沿用已授权真实模型验证，保留全部失败，不为成功重放语义失败。日常入口仍为8765，更新前核对进程、活动任务及未保存输入。
- 停止：上述实现与必要验证完成后本地提交，不推送；真实失败与缺测如实列出。

## 交互

第一屏只有轻引导、聊天、添加资料与“已有明确需求，直接整理”。每轮优先追问一个影响理解的问题，允许不知道。模型可提示形成初稿，但不决定范围、不生成HTML、不替用户确认。

“整理需求草稿”通过现有资料分析契约提取候选与范围建议；第二步展示现状、目标、本次改动、保持不变、暂不涉及和待补充信息。用户可返回补聊或直接编辑。已保存字段优先保留，新增建议须由用户明确使用后再更新。

聊天原话逐条作为项目来源和对话记录保存。模型超时、取消或输出错误不删除已提交输入。发送前呈现实际接收端与当前资料，接收端变化或资料版本变化须重新核对。
