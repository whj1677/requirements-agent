## 三、发现的问题（按严重度）

### P0-1 后端无声崩溃，无任何日志

试用中段服务进程直接消失（PID 38744），`server.stderr.log` / `server.stdout.log` 均无任何错误记录。前端表现为"无法连接服务"。崩溃前正在做第 2 步卡片保存。**建议**：增加未捕获异常/at_exit 落盘、Windows 下进程守护或至少把崩溃写入事件日志。

### P0-2 导出请求导致整个 API 死锁

基线确认后首次请求 `GET /documents/prd/zip`，随后全部 `/api/*` 无响应（静态文件正常），进程 CPU 空闲（349.3s 不再增长）——典型的锁等待/事件循环挂起，只能重启恢复。重启后同类下载毫秒级完成，说明不是导出计算本身慢，而是并发/锁路径缺陷。**建议**：导出放入线程池并审查 store 锁粒度，为 API 增加超时与请求日志。

### P1-1 输出 token 上限反复不足，且与上下文预算耦合

默认 16000 对真实审查远远不够。实际路径：16000（截断暂停）→ 24000（截断）→ 32000（截断）→ 48000 才通过（实际用了 40132 tokens；另有一次 40237 tokens 但输出非法 JSON 被判 SCHEMA_INVALID）。提高 `max_tokens` 后还会撞上下文预检公式（`输入字符 + max_tokens×4 + 4000 ≤ context_chars`），用户必须自己解这个方程去同步调 `context_chars`（180000→360000→420000→520000）。**建议**：按阶段给默认值（review 阶段默认 ≥48000）、预检失败时直接给出"建议调成 X"的提示或一键调整。

### P1-2 只关联规则的阻塞问题永远无法闭环

`accept_answer_update`（app/understanding.py:174）只接受 target 为 requirement 的修订候选；两个问题（Q-15cfdcccb0584eeb、Q-b30860dae76c48de）的 `related_refs` 只有 RULE，回答后 `understanding_status` 永远停在 `pending`。确定性门禁恰好不拦（product_flow.py:107 只查 requirement 交集），但文档生成上下文把 pending 状态喂给模型，导致"更新"类 clarify 任务的模型**拒绝改写文档**（"该回答尚未正式采纳，故本轮不擅自改写"）。**建议**：answer_refs 支持 rule 目标，或提供"该回答无需修订条目"的人工确认路径。

### P1-3 `applies_to=reference` 的条目没有 UI 转正路径

编码/命名规则被整理为 reference 后，`/items/{id}` 决策端点不改 `applies_to`，唯一路径是定向帮助任务生成 revise 候选再采纳（候选还得不带 answer_refs，否则触发 REFERENCE_INVALID）。普通用户几乎不可能自己发现这条路，本次靠读源码才走通。**建议**：条目编辑界面增加"计入本期/仅作参考"切换。

### P2-1 "更新讨论稿"存在两个行为不同的入口

文档页签的"更新讨论稿 MRD"（document 动作 → prd 阶段，真正重生成）与审查发现/局部帮助入口触发的 clarify 阶段"更新"（只产出建议，模型可能拒绝改写）同名同义，容易误用。本次先在错误入口跑了 4 次 clarify（2 次预算预检失败、1 次失败、1 次被拒）才走对。**建议**：局部入口改名（如"讨论此章节"）或在结果页明确"未改动文档"。

### P2-2 崩溃遗留表单酿成危险冲突对话框

重启后点检查点时突然弹出编辑冲突："我的修改"是崩溃前遗留的陈旧行为文本，若点"已核对，保留我的修改并重新保存"会**覆盖模型已修订的 v7 内容**；且冲突框没有"放弃我的修改"按钮，只能靠刷新页面丢弃。**建议**：冲突框增加"放弃我的修改"选项；页面重新加载后清理过期未保存表单。

### P2-3 审查-修复循环成本高

每修一处不一致 → 底稿变更 → 检查点 2/3/4 全部重走 → 两份文档全量重生成 → 重新审查 → 又发现新不一致。本次共 4 轮审查才通过，全程 38 次运行、52 次模型请求（succeeded 10 / partial 15 / failed 5 / paused_budget 8；clarify 16、prd 10、review 11、ingest 1）。**建议**：审查发现支持"按条修复不重跑全量"，或一次运行内多给几轮自查。

### P3 小项

- clarify/prd 阶段上下文含全量 documents JSON（约 20 万字符），底稿长大后预算压力主要来自这里，可考虑摘要化。
- 暂停（paused_budget）状态语义混杂：输出截断、预算预检、动作额度都归到此状态，前端文案需展开执行记录才能分辨。
- 失败运行有一次模型输出 4 万 token 但非合法 JSON（疑似推理循环），建议对 review 输出长度做软约束提示。
