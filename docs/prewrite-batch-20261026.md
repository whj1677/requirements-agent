# 成文检查整表确认（2026-10-26）

## 用户操作

进入“成文检查”默认显示一张确认表，不再逐项打开卡片或逐项调用助手。已有回答沿用；已有可用修订直接展示。缺草稿时使用“AI 批量起草全部修改”，一次任务处理全部检查点；核对后“确认全部修改并复检”，一次事务保存全部回答、正文、业务说明及验收，再准备一次整批检查任务。

查看、编辑、取消、确认保存均不请求模型。起草与复检仍分别是模型任务，使用当前配置和资料授权。取消复检后通过“继续整批复检”恢复，不重复确认。共享条款只编辑一份，人工编辑保留并显式展示合并冲突。默认展示修改或检查涉及的字段，其他字段可统一展开。逐项依据仅供只读核对。

保存通过现有 refinement-confirmation 原子接口，保留版本、来源、候选身份、范围、回答落实、幂等及成文门禁，不把已保存回答当作检查通过。正式 BMS 项目不自动采用建议。

## 实际发现与修复

真实合成模型起草曾两次只形成推荐回答、没有形成可用需求修订。第一次详细定义含未支持的结构，保持拒收；第二次将 detail_contract 文本属性误包成 text/basis/sources 对象。

对后一种精确封装，程序在本机按明确属性类型恢复：逐字保留 text，将 fact/recommendation 对应到 source/proposal，保留全部引用并重新执行来源与详细定义检查。冲突证据、伪造来源、附加字段、非字符串及关系属性不由该规则放行。原始模型输出和诊断保留。表内也能展开查看批量起草未生成可用修改的原因。
