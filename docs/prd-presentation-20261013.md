# PRD 阅读与导出格式优化 2026-10-13

用户反馈真实 Agent 产物没有此前图文表样稿清楚。本轮以同一真实 DeepSeek 文档快照重导出，优化需求 Agent 的提示规则、确定性阅读投影和 Word 排版。

## 评价与本轮改动

原稿字段、交互、流程、状态和验收覆盖较全，但首页被核对日志占据，18 条验收分别起同名标题，长 ID 打断阅读，字段五列表与交互逐属性纵表使篇幅膨胀，流程拆为四段。此前样稿的优势是清楚的章节、简短引用和紧凑表格；它属于统一假设的合成设计，不能把其数字或业务范围补入本次真实 Agent 内容。

- 结构化 PRD 使用 R01、BR01、A01 等文内编号；规范 ID、版本、来源和源位置留在原快照及导出内部引用记录，未修改业务身份。公开下载包仍沿用现有 JSON 过滤规则。
- 字段改为三列，交互按进入、输入与提交、处理中、结束结果、数据影响组织；全部业务属性、未知项和关联保留。
- 验收改为紧凑表，保留每条标题及原文，不按相似性合并不同条款。程序生成的根级验收章移到详细定义之后；自定义层级不移动。
- 未决事项汇成表；Word 首页保留评审状态，完整核对信息放在文末，已在正文显示的问题不重复列警告。正式门禁不变。
- Word 使用 A4、深蓝层级和表头、重复跨页表头、短图注；流程按完整节点层切成三段，不裁节点、不删除连线。段高包含跨段连线注释。
- 后续生成提示要求节点写具体动作、条件放相应属性，验收复用未变更的已有条款，问题避免换词重复。此提示未新增真实模型测试，不宣称模型已稳定遵循。

## 保留的限制

这是格式优化后的评审稿，未变成正式交付。通知循环的重复触发条件、结果字段何时产生/可空、旧新验收重复及通知问题重复仍需业务修订；程序没有为排版替用户决定业务。完整流程图仍分三段，尚未达到此前短主线图的一页概览效果。真实模型生成质量未重测、产品经理及研发最终验收未执行。
