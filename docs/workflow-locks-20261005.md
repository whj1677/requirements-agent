## 判断与实现

- 只约束真实的前置依赖。可选背景信息不必逐项填满，业务行为未知仍可留在第三步澄清；模型不会代替人采纳。
- 顶部原来只展示锁标记，仍可点击进入并编辑。本次依据后端 `product_flow` 的前序有效状态禁用导航；旧标签页、历史位置或其他入口落到锁页时隐藏编辑区，显示具体前置步骤和返回入口。被锁页不再标为绿色当前步骤。
- 直接填写原来跳到第二页，聊天文字却只留在浏览器。本次在第一步共用原输入框，保存实际文字及来源后自动进入第二步；无模型请求，无候选自动创建或采纳。侧栏阶段不再因未调用模型而错误留在第一步。
- 第二步现在要求本期范围内需求已明确采纳，暂不采用的需求应移出本期。第三步保留防御检查。逐条行为核对和批量采纳仍在第二步可用，缺少行为细节不会逼用户编造内容。
- 阻塞第二步的问题在第二步就地回答；未知备注仍保留阻塞，确实在范围外的问题可填写排除理由并恢复。答案落实到条款的核对继续在第三步进行，避免两页互相锁住。
- 未解决待办在继续按钮上显示数量，并提供清单定位；方案比较在本页前置核对完成后解锁。正常前进清除旧定位并回到下一页起点。
- 前置失效时编辑组件继续保留草稿；锁页返回按钮不要求先解决隐藏编辑器中的冲突。离开整个项目仍有未保存提示。草稿保护不等于关闭或刷新浏览器后自动持久化。
- 新项目第一步将旧的“产品、模块、意图、材料”四条要求合并为实际可操作的“保存本次需求”入口，避免直填路径被误认为必须重复填四项。
