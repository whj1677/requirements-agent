## 改动与正确路径

1. **CQ-01：具体计数选择一致。** 从肯定、明确的计数文案提取 Unicode 码点或扩展字素簇。人工回答、候选 statement/behavior 与当前关联条款必须选择相同单位；否定一种单位及“口径待确认”不算决定。带实际来源和回答 ID 的相反单位修订仍被拦截。成文与复核入口继续检查条款和已答计数选择的冲突；一致选择保留，程序不替 PM 选口径或采纳修订。
2. **CQ-02：局部否定与条件。** 协调词前的“不能自动重发”不否定后面的“失败场景原记录不变”；逗号不切断失败条件和原记录承诺的关系。emoji 颜色的否定也不能解除同句计数冲突。明确失败与未知结果分开的表述、真正否定原记录保证、全部成功条件和明确单码点 emoji 例外保留。
3. **CQ-03：能力、对象、场景共同支持。** “已支持备注变更审计”不能借用另一个登录告警谓词中的失败场景。只有同一实现谓词的场景或紧随其后且无另一个能力/对象的明确省略陈述才可支持；同一句有逗号或协调词均核对。覆盖成功与失败的同一备注审计、直接支持失败备注变更审计保留。缺失、否认、范围受限及带可识别不确定措辞的证据不解除风险，省略的场景也须有肯定证据。
4. **CQ-04：每一条指控有对应证据。** 额外 finding 仍需核对所指文档存在；“同样错误”不能借其它 finding 的冲突维度，或把 PRD 的错误自动归到 MRD。真实缺少 MRD 的缺口说明、两份文档各自有真实错误的报告可以保留。
5. **CQ-05：按冻结阅读正文核对位置和原句。** 审查投影的每个块附 `source_location`，使用原 artifact ID、原章节 ID、原始 block 下标，保留过滤、业务条目提升和未决问题投影后的来源位置。默认阅读/导出不显示技术位置。引文检查使用该文档冻结 item/behavior 快照展开的实际正文，不能用后来修改的当前条目替换。解释检查也只检查可见正文，并用保存的上下文、规范和已引用业务事实核对；缺失历史快照不充当实现证据。
6. **CQ-06：确认门覆盖最低规范范围。** `gate` 的 reviewed_refs 同时覆盖本期已选 requirement、rule、acceptance；只审需求不能解除确认门。`needs_changes` 可以保存不完整结果，并保留明确未覆盖 ID。审查输入说明最低覆盖集合。合成 ready 夹具显式提供其已模拟审查的全部规范 ID。旧“普通说明不阻断”正向对照也补齐其模拟已审查的规范范围；缺失覆盖的负向输入、旧断言、旧例子文件及历史产物不改。

语义版本提升为 `semantic-quality-3`，参与新的审查目标哈希，使旧结果不能自动证明新规则已经审查。程序只派生检查状态，不迁移或改写历史确认。

## 有限规则的实际限制

规则使用有限计数词形、中文能力/对象/场景词表、标点和协调词，不是通用自然语言推理。复杂嵌套否定、跨句指代、多对象省略、未识别同义词或带条件的自然语言仍需模型与人工核对。实现资料的文本匹配不证明资料真实、代码版本有效或运行行为已经验证；不确定实现证据保留风险。

定位核验针对可解析 ID/章节/原始 block 位置及显式引文，四个已定义解释风险维度有有限确定性见证，其它语义判断仍需人工审查。最低 reviewed_refs 覆盖只证明条目范围被报告审查，不能证明逐句判断正确。冻结历史缺少证据快照时不能凭后来资料证明历史实现；历史文档中既有问题保持原身份，修订必须通过新候选、采纳和确认流程。

此次内容复审提到的运行操作者与 PM 人工确认是否构成新增运行审批角色，仍是需核对的业务歧义；未自动改写条款。新增离线反例、全量和本机 Office 合成执行分别记录，不把它们当成真实模型内容验收或历史业务基线重新验收。
