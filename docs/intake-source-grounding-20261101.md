### 读完后仍空转的修复

## 关于用开源记忆框架减少 PRD 矛盾

检索能帮助记住已答信息，但 PRD 一致性还需要来源、适用范围、当前有效版本、未决冲突与章节依赖。当前代码已经具备来源失效关系、决策回答、阶段上下文等结构；本轮真实输入也证明已答信息确实被带入，仍需处理原话到草稿之间的推断错误。

- [Graphiti](https://github.com/getzep/graphiti)：时间化事实、历史关系、混合检索适合比较规则变更与追溯；需要图数据库。自动事实失效机制不能直接等价为“后上传文件优先”或替用户解决冲突。
- [LangMem](https://github.com/langchain-ai/langmem)：对话记忆提取、更新、检索，其核心能力可配合现有存储，适合评估较小范围的接入。
- [Mem0](https://github.com/mem0ai/mem0)：可比较多层记忆与召回能力；公司需求仍须保留独立的事实与确认状态，不能直接把 Agent 自述当产品决定。
- [LangGraph 记忆文档](https://docs.langchain.com/oss/python/langgraph/add-memory)区分会话内持久状态与跨会话长期记忆。两者与需求约束的真实性不是同一件事。
- [Ragas Faithfulness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/)与 [DeepEval Faithfulness](https://deepeval.com/docs/metrics-faithfulness)可借鉴“断言是否得到检索上下文支持”的语义评估；仍需另测已答决定遗漏和旧规则误用，不能只测检索命中。

建议用同一批失败案例比较“当前实现”和记忆层候选：重复追问、已答子决定覆盖、旧规则误用、冲突保留、各字段来源准确性，以及实际延迟和调用量。本轮仅完成资料查证与方案判断，尚未安装、接入新记忆框架，也未迁移日常数据。
